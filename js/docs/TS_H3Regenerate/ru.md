# TS H3 Regenerate

Увеличивает готовый латент H3 и уточняет детали через Open-H3-Regenerate-2K.
Подключите чистую модель H3 через [TS H3 Regenerate Model](https://github.com/AlexYez/comfyui-timesaver/blob/master/js/docs/TS_H3RegenerateModel/ru.md).
LoRA первичной генерации остаются на отдельной ветке.

Подключите выход `NOISE` ноды **Random Noise** ко входу `noise`. Seed задаётся в Random Noise.
Один выход можно подать и в сэмплер черновика, и в Regenerate. Шум генерируется на итоговой
сетке, а кадры в перекрытии получают одинаковые значения шума.

`denoise`: **1** — опубликованное расписание NVIDIA; **0** — только увеличение,
без диффузионного пересчёта; промежуточные значения уменьшают стартовый шум и степень
перерисовки. При значении ниже 1 строится расписание shift-6 от пониженной сигмы.
Число шагов остаётся 2 или 3. Результат при меньшем denoise требует проверки на вашем видео.

`width` / `height` — итоговый размер, кратный 32. Для 1080p считайте 1920×1088,
после декодирования обрежьте 4 строки сверху и снизу. Для 4K — 3840×2176 с обрезкой до 2160.
Если исходник ниже площади 2K, а целевой размер выше, нода сначала увеличивает латент
до промежуточного размера около 2K с учётом пропорций. Для цели 3840×2176
промежуточный размер — 2560×1440, для портрета — 1440×2560.

## Опорные кадры и Full Reference

Подайте исходный positive в `conditioning`. Режим `off` используется по умолчанию
и оставляет текст с тегами. Ключевые кадры и медиареференсы черновика подключаются
к уточнению через один из режимов ниже.

`first frame (preserve character)` добавляет отдельно закодированный стартовый кадр.
Подключите `first_frame` и **обычный H3 video VAE** к `video_vae`; совместимый INT8 video VAE тоже подходит.
Для двухкратного апскейла подайте в `first_frame` исходник, подготовленный отдельной
веткой **ImageScale** прямо в итоговый размер. Такая ветка сохраняет детали, потерянные
при уменьшении картинки для черновика. Если размеры отличаются, нода подгоняет первую
картинку батча к холсту через Lanczos без обрезки и кодирует её один раз. Fast VAE
служит только для декодирования. Опорное изображение влияет на генерацию как условие модели.
В [опубликованном опыте с первым кадром](https://ai-muninn.com/en/blog/open-h3-regenerate-2k-rtx5090)
проверяли мелкие надписи. Сохранение лица оценивайте на своём видео.

`first and last frames` добавляет `last_frame` с тем же обычным `video_vae`.
Конечная картинка при необходимости подгоняется через Lanczos с центральной обрезкой.
Начальная опора привязана к нулевому кадру всего ролика, конечная — к последнему кадру
и используется только при уточнении последнего фрагмента.

`connected frames (auto)` берёт доступные изображения из `first_frame` и `last_frame`
независимо. Подключайте первый кадр, последний или оба. Если оба входа пусты,
уточнение идёт по тексту и черновому латенту. При наличии хотя бы одного кадра
подключите обычный H3 video VAE. Последний кадр участвует только в финальном фрагменте.

`full reference (Ref2VA)` берёт из positive ноды **MiniMax H3 Reference to Video** уже
закодированные картинки, видео, видео со звуком и отдельное аудио. Порядок блоков и
теги текста сохраняются. Для Regenerate подайте чистую pruned **Ref2VA** через
**TS H3 Regenerate Model**. Входы `first_frame`, `last_frame` и `video_vae` в этом
режиме можно оставить пустыми. Размер и длина референсов влияют на расход VRAM.
Full Reference экспериментален. При `denoise=0` все режимы референсов отключены.

## Звук и фрагменты

Звук: `keep source audio (lipsync)` держит звуковой латент неизменным во время уточнения;
`silence (reference)` кодирует тишину через подключённый H3 audio VAE, как в исходном
подходе NVIDIA. На выход всё равно передаётся исходный звуковой латент, если он был на входе.
Частота — 24 fps; нода сохраняет длину латента, не растягивает звук и не создаёт кадров.
Сохранение исходного звука само по себе не гарантирует сохранения движения губ — проверяйте результат.

`chunk_length=0` обрабатывает целый клип. На 16 ГБ VRAM 2K может не поместиться.
При ненулевой длине нода обрабатывает ролик фрагментами. Задавайте `chunk_length` и
`temporal_overlap` кратными 17 кадрам, с перекрытием меньше длины фрагмента.
Шум общий для всего клипа. Для продолжения с несколькими фрагментами нужен
`temporal_overlap` от 17 кадров.
`chunk_mode=independent (crossfade)` сохраняет прежнюю независимую перерисовку кусков.
Детали в перекрытии могут различаться, поэтому смешивание иногда выглядит как «перетекание».
`continue (lock overlap)` подаёт готовое перекрытие следующему куску как чистый видеоконтекст
с нулевой маской перерисовки. Уже готовая часть сохраняется точно, уточняется новая часть.
`continue (blend overlap)` фиксирует первую половину латентных позиций перекрытия
(минимум одну), а оставшуюся часть пересчитывает и плавно смешивает с предыдущим фрагментом.
Продолжение может переносить изменения вдоль длинного ролика — проверяйте и швы, и накопление искажений.
Если последнему куску остаётся добавить меньше 17 новых кадров, нода пытается равномерно
распределить существующие куски по родной временной сетке. Для 226 кадров при настройках 85/17
длины станут 68,68,68,73 вместо 85,85,85,22: после 221-го кадра не остаётся отдельной
пятикадровой дорисовки. Число кусков, перекрытие, длительность и выбранный предел длины сохраняются.
Для очень коротких роликов сетка может не допускать более удачного разбиения. Это устраняет
данный случай короткого хвоста, но не гарантирует сохранение движения и положения камеры.
При опоре на стартовый кадр его локальная позиция в последующих фрагментах отрицательна.
Так сохраняется привязка к началу всего ролика. Обработка фрагментами экспериментальна.
При `chunk_length=0` весь ролик обрабатывается за один проход.

Декодирование: обычный H3 Video VAE либо **TS H3 Fast VAE Decode**.
Fast VAE поддерживает FP32 и INT8 convrot. Он требует отдельного файла и может потреблять больше памяти, чем обычный
декодер с тайлами; подключите обычный video VAE к `fallback_vae` для автоматического отката.
Используется PyTorch SDPA; ускорения SoL-Engine / MXFP8 / CUDA Graphs не включены.

Исходный подход: [NVIDIA](https://github.com/NVlabs/Sana/tree/sol-engine/models/Open-H3-Regenerate-2K).
Декодер и его экономный forward: NVIDIA / [rdh9616](https://github.com/rdh9616/ComfyUI-Open-H3-Regenerate), Apache-2.0.
