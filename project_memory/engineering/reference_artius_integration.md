История двух интеграций Artius со снятой TS Image Studio; старые маршруты не являются текущим API.

**Текущая опора (2026-11-02):** Студийная интеграция относится к снятой TS Image Studio. Не считать старые studio-маршруты текущим API; при возврате использовать git history и текущие интерфейсы внешнего Artius.

**Граница записи:** ниже сохранены исходные наблюдения и причины решений. Замеры, версии окружения и слова «сейчас» относятся к дате соответствующего наблюдения; это не повторная проверка на новом окружении. Порядок чтения и ограничения: [инженерная память](README.md#как-читать-записи).

TS Image Studio и Artius Browser связаны так, что обе стороны обновляются
независимо: **ни один модуль одного пака не импортируется другим**, и каждый
полностью работоспособен в одиночку.

**1. Действия над ассетом.** Студия публикует запись в `window.tsAssetActions`
(реестр в `js/_studio/_asset_actions.js` — исторический файл `js/_studio/_asset_actions.js`; см. [снятая студия](../history/project_image_studio.md)):

```js
{ id, label: {en, ru}, order, supports(asset) -> bool, run(asset) -> {ok, message} }
```

`asset` = `{id, filename, url, type, extension}`; `url` готов к `fetch`.
`supports` синхронный — меню строится сразу, поэтому чтение файла только в
`run`. Artius показывает применимые записи в контекстном меню карточки
(`tsBuildContextMenuItems` → `ext:<id>`) и поднимает тост из `message`.
Первая запись — `ts-image-studio.recreate`.

Массив на `window` выбран сознательно: публикатор и потребитель — разные
ComfyUI-расширения без общего графа модулей, порядок загрузки не гарантирован.

**2. Студийный тег.** Artius при скане читает чанк `ts_studio`
(`tsab/media/image.py: TSExtractStudioSession`), кладёт компактный тег в свой
блоб метаданных и отдаёт полем `studio` в списке ассетов
(`ts_asset_payload.py: TSResolveStudioTag`). Карточка получает акцентный бейдж
«режим · модель» с настройками в тултипе. Не-студийные ассеты отдают `{}`.

Грабли: старые изображения тег не получают до `Rebuild Cache` — обычный скан
переиндексирует только новые/изменённые файлы. `TS_PROMPT_PARTS_VERSION`
поднят до 7, поэтому on-demand detail-просмотр тоже переизвлекает блоб.

Открытие студии снаружи: `openStudio(node, persist)` не использует `node`, а
`openStudioInstance()` возвращает уже открытую. Ноды `TS_ImageStudio` может не
быть на графе — тогда сессия detached (в памяти страницы), граф пользователя
не трогаем.

Правки в репозитории Artius помечаются `[AI agent]` в коде и описываются в его
`CHANGELOG.md` — требование владельца.

Связано: [project_image_studio](../history/project_image_studio.md), [reference_live_copy_sync](reference_live_copy_sync.md).

## Кнопка «S» на карточках снята (2026-08-05)

Артиус рисует на карточке кнопку `use-in-studio` («S») только когда студия
опубликовала действие `ts-image-studio.use-source` — гейт на стороне браузера
(`tsExternalIds.has(...)`). Владелец: кнопка путает (кажется, что грузит в
любой режим, а по факту попадала в инпэйнт), перетаскивания достаточно.

Поэтому убрано **со стороны студии** — снята публикация действия и функция
`useAssetAsSource`. Артиус трогать не пришлось: нет действия — нет кнопки.
Действие `ts-image-studio.recreate` («R») осталось: оно делает другое —
восстанавливает сессию, в которой картинка сделана.

Проверка после правки — по реестру, а не по DOM: в консоли страницы
`window.tsAssetActions.map(a => a.id)` должен вернуть только `recreate`.
