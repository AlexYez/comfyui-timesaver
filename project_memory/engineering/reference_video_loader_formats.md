# TS Video Loader: форматы и чёрный прямоугольник вместо картинки

Жалоба владельца 17.09.2026: «загрузил ProRes — звук есть, а картинки не видно».

## Диагноз (замерено)

**Декодер ни при чём.** Прогон образцов через код самой ноды:

```text
prores_422hq.mov (yuv422p10le)  проба ок, декод (25,360,640,3) float32, лента кадров ок
prores_4444.mov  (yuv444p12le)  то же
dnxhr_hq.mov     (dnxhd)        то же
```

Чёрный прямоугольник — **плеер браузера**. Маршрут `/ts_video/view` отдаёт файл
как есть, а Chromium декодирует ровно четыре видеокодека: h264, vp8, vp9, av1.
Звук из MOV он играет, картинку — нет.

⚠️ Пак это уже знал и не пользовался: `/metadata` возвращал `browser_playable`,
фронтенд клал его в `state.playable` — и **нигде не читал**. Сообщение
показывалось только по событию `error`, то есть постфактум.

⚠️ Готовое решение лежало в соседней ноде: TS Video Saver для ProRes собирает
маленькую копию (`_encode.write_proxy`, `wants_proxy`). У загрузчика её не было.

## Расширение не решает ничего

⚠️ **ffmpeg узнаёт контейнер ПО СОДЕРЖИМОМУ.** Проверено: ProRes, переименованный
в `.zzz`, открывается как ни в чём не бывало. Поэтому белый список расширений —
это политика для HTTP-маршрутов и кнопки выбора файла, а НЕ для декодера, и
`validate_inputs` по нему больше не отказывает.

Список расширен по замеру (для каждого собирался образец и открывался тем же
PyAV): `mxf m2v vob 3gp dv asf f4v y4m mjpeg avif webp apng nut ivf rm` плюс
безопасные соседи (`qt divx m1v mpv m2p mod tod 3g2 rmvb ogm mjpg`). Самый
обидный прежний пропуск — `.mxf`: штатный контейнер ProRes и DNxHD на вещании.

⚠️ `.braw` и `.r3d` НЕ добавлять: ffmpeg их не декодирует вовсе (закрытые SDK),
запись в список лишь перенесёт отказ на шаг позже.

## Что сделано (17.09.2026)

- `nodes/video/media/_proxy.py` — маленькая копия для плеера: один вызов ffmpeg,
  H.264, длинная сторона 1280, прогресс из `-progress pipe:1`, файл в
  `.cache/ts_video` под ключом `file_identity` (перезапись исходника даёт новую
  копию). Строится **только по кнопке**; готовая подхватывается молча.
- ⚠️ Временный файл `*.proxy.mp4.<pid>.tmp` — ffmpeg по такому расширению
  мультиплексор НЕ угадывает и отвечает «Error opening output files: Invalid
  argument». Спасает явный `-f mp4`.
- ⚠️ Масштаб задан выражением `if(gte(iw,ih),min(1280,iw),-2)` — ограничивается
  длинная сторона, иначе портретный ролик не ужимается вовсе.
- Маршруты: `GET /ts_video/proxy` (состояние), **`POST`** того же адреса
  (запустить — единственный маршрут видео-нод, который что-то делает, а не
  отвечает), `GET /ts_video/proxy/view` (отдать копию; проверяется ИСХОДНИК).
- Фронтенд: кнопка `proxy` в ряду транспорта, проценты в строке состояния,
  `editor.setPlayable()` прячет сам элемент `<video>` — чтобы вместо чёрного
  прямоугольника был фон темы.
- Тесты: `tests/test_video_loader_formats.py` (34 штуки), включая сквозной
  ProRes → H.264 на настоящем ffmpeg.
