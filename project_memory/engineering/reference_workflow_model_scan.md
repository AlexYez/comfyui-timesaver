Как TS Files Downloader собирает модели из workflow — properties.models первичны, загрузчики живут в сабграфах, кнопка не сериализуется

Исходники темы: [ts-files-downloader.js](../../js/files/ts-files-downloader.js).

**Граница записи:** ниже сохранены исходные наблюдения и причины решений. Замеры, версии окружения и слова «сейчас» относятся к дате соответствующего наблюдения; это не повторная проверка на новом окружении. Порядок чтения и ограничения: [инженерная память](README.md#как-читать-записи).

# Скан моделей из workflow (TS Files Downloader)

Кнопка «Get models from workflow» в [`js/files/ts-files-downloader.js`](../../js/files/ts-files-downloader.js),
extension id `ts.filesDownloader`. Добавлена 2026-07-28. **Полностью фронтендовая** —
Python-схема ноды не менялась ни на байт.

## ⚠️ Главное: источник — не заметка, а `properties.models`

ComfyUI проставляет каждому загрузчику, пришедшему из шаблона, машинную запись:

```json
"properties": { "models": [{ "name": "...", "url": "https://...", "directory": "text_encoders" }] }
```

Это ровно та тройка, которая нужна ноде. Markdown-заметка дублирует те же факты прозой —
она **вторичный** источник (заполнить пробелы + сверка). На шаблоне Anima LLLite оба
источника дали 5 из 5 и совпали один в один.

Порядок доверия: `properties.models` → заметка → виджет загрузчика (даёт имя файла и,
через тип ноды, папку, но не ссылку). Ключ слияния везде — имя файла.

## ⚠️ Загрузчики лежат ВНУТРИ сабграфов

На шаблоне Anima LLLite все 5 моделей — в `definitions.subgraphs[0].nodes`, в корневом
`nodes` их **ноль**. Обход `app.graph._nodes` покажет пустой workflow. Скан обязан
рекурсивно спускаться в `definitions.subgraphs[].nodes` — это основной сценарий, а не
редкий край.

Берём `graph.serialize()`, а не живые объекты: сериализованный вид совпадает с форматом
файла workflow, на котором и отлаживался парсер.

## ⚠️ Кнопка не должна сериализоваться

`widgets_values` позиционный (см. [reference_widgets_values_positional](reference_widgets_values_positional.md)). У ноды 11
значений; лишний сериализуемый виджет сдвинул бы их все в каждом существующем workflow.
Поэтому кнопке ставится и `button.serialize = false`, и `button.options.serialize = false`
(правило из `_dom_widget.js::isSerializableWidget`). Проверено живьём: `widgets_values`
остаётся 11 до и после нажатия.

## Продуктовые решения пользователя

- **Дополнять** по умолчанию, «Заменить список» — отдельной кнопкой.
- **Сначала окно с разбором**, молча не писать: в `file_list` может лежать ручной список.
- **Уже скачанные модели НЕ отсеивать.** Список едет вместе с workflow, и получателю эти
  строки нужны, даже если на этой машине файл есть. Поэтому проверки наличия на диске нет
  вовсе.
- Поиск недостающих ссылок на HuggingFace — **отдельный второй заход** по группе
  «No download link», сделан. Подставлять молча нельзя: по имени файла находятся десятки
  форков, поэтому находки показываются в отчёте. Устройство и грабли —
  [reference_hf_search](reference_hf_search.md).

## Мелочи, которые всплыли

- Целевую папку пишем **коротким именем** (`text_encoders`, `loras`) — `_resolve_target_directory`
  в ноде это уже умеет. Абсолютные пути привязали бы workflow к машине.
- Диалог держим в единственном экземпляре: повторное нажатие при открытом отчёте иначе
  вешает второй оверлей поверх первого, и его кнопки пишут устаревший diff.
- Отчёт монтируется через `openFullscreenOverlay` ([reference_fullscreen_overlay](reference_fullscreen_overlay.md)) —
  он приносит keyAnchor-защиту фокуса, иначе Ctrl+Z уйдёт в граф ([reference_modal_hotkeys](reference_modal_hotkeys.md)).
