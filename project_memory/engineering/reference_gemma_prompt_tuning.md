История трёх экспериментальных Gemma-пресетов; текущий подход обновляет существующие пункты.

**Текущая опора (2026-11-02):** Три экспериментальных пресета удалены из видимого меню. Текущая настройка обновляет существующие пункты; см. [актуальную запись о пресетах](reference_llm_presets_refresh.md).

**Граница записи:** ниже сохранены исходные наблюдения и причины решений. Замеры, версии окружения и слова «сейчас» относятся к дате соответствующего наблюдения; это не повторная проверка на новом окружении. Порядок чтения и ограничения: [инженерная память](README.md#как-читать-записи).

**История, не текущее состояние.** 01.11.2026 владелец потребовал обновлять
существующие пункты без новых Gemma-пресетов. Все15 обновлены,3 временных
удалены из меню. См. reference_llm_presets_refresh.md и
feedback_update_existing_llm_presets.md. Старый HTML помечен архивным.

31.10–01.11.2026. Владелец попросил подобрать системные инструкции для Gemma:
MiniMax H3, LTX и общее улучшение с опорой на картинку. Затем указал исследования
и Skills в корне C:/Users/Sanchez/Documents/timesaver/projects/StoryMaker и
напомнил, что инструкции нужно писать под небольшие E2B/E4B.

Прочитаны три root-исследования (h3, ltx, image-generation), скиллы
neuroclip-minimax-h3-prompts, neuroclip-ltx25-i2v-prompts,
timesaver-universal-image-prompts и нужные reference-модули. Уточнения скиллов
точнее сырых исследований: роль источника важнее количества файлов; base H3
не смешивать с Full Reference; API-настройки не писать как магический синтаксис;
no music не гарантирует отсутствие музыки. Документация H3/LTX проверена онлайн.

Добавлены ОТДЕЛЬНЫЕ ключи в nodes/qwen_3_vl_presets.json, в конце списка:
- Gemma - Prompts enhance (3014 символов, потолок500 токенов).
- Gemma - Video Prompt Enhance H3 (4708, потолок700).
- Gemma - Video Prompt Enhance LTX (4219, потолок500).
Все15 прежних записей побайтно по смыслу JSON сохранены. Пользователь выбирает
новый пресет явно; defaults/сохранённые workflow не мигрировались. Общий файл
доступен также Qwen, но новые варианты подбирались именно на Gemma.
Параметры: temperature .25, top_p .8, top_k20, repetition_penalty1.05.
Это не перенос целых Skills; инструкции с явными приоритетами и короткими
примерами. Сильно сокращённая редакция (~1.7–2.5k знаков) отдельно проверена
и чаще теряла длительность, роль картинки и H3-синтаксис; краткость сама по
себе не улучшает эту модель. Один общий пресет требует различения фото/видео.

Проверки:
- Предыдущая близкая редакция:68 ответов E2B (14 сценариев, два seed).
- Сокращённая редакция:17 запрос/задача на E2B и E4B, всего34 ответа.
- Выбранная финальная: те же17 на каждой модели, seed42, всего34.
  Все буквальные строки ровно1раз:11/11 случаев на каждой модели.
  Описательная часть без лишней кириллицы17/17 на каждой.
  H3: имена трёх полей7/7 у каждой, полный проверяемый набор языка/ID лишь
  2/5 речевых случаев у E2B и3/5 у E4B. Это не гарантия смысла/привязки голоса.
-166 целевых тестов RT/preset/media compatibility +7 node/widget contracts;
  git diff --check. Полный pytest не запускался.
- JSON +4 RT help-файла установлены с резервной копией в
  tests/.cache/gemma-prompt-tuning/installed-backup-20261101-000015/.
  Существующие live-presets сохранены. API object_info обеих RT-нод видит3 ключа
  БЕЗ рестарта. V3 COMBO: options находятся в spec[1]['options'], не spec[0].
- Все3 пресета вызваны через настоящий /ts_super_prompt_rt/enhance с

Артефакт: dist/gemma-system-prompts/index.html; рядом general.txt/h3.txt/ltx.txt,
selected-results.json34, mini-results.json34, final-results.json68 (предыдущий
этап), summary.json. Скрипты/логи всех итераций — tests/.cache/gemma-prompt-tuning/.
В mini/selected исходное поле seconds удалено: оно наследовалось от старого
запроса и не было временем текущего прогона. Новых скоростных выводов не делать.

Важные наблюдения: первичная общая инструкция превращала стартовый кадр в
статичное описание и теряла реплику. Приоритет точного текста и отдельный
пример с картинкой помогли. Отрицательный словарь «шарф=scarf» усиливал
подмену шара; положительное шар=sphere/кубик=cube/стол=table помогло.
В final68 новый сложный запрос оставался по-русски; явное ENGLISH в конце
помогло в selected34. Нельзя обещать идеал: H3 по-прежнему пропускает speakerID,
иногда заголовок привязки картинки, Shot2 или правильно разведённую музыку.
Общий/LTX могут упускать детали и смешивать push/zoom. Нужна смысловая проверка;
автоматический repair/повторный LLM-pass в код НЕ добавлялся.
