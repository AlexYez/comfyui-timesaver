TS VAE Fix (бывш. рабочее имя DeGrid) — какие VAE оставляют решётку 2 px (замеры 09.10.2026 на output владельца), почему детектор ограничивает поправку и почему пакет решается одним решением

Исходники темы: [ts_vae_fix.py](../../nodes/image/ts_vae_fix.py).

**Граница записи:** ниже сохранены исходные наблюдения и причины решений. Замеры, версии окружения и слова «сейчас» относятся к дате соответствующего наблюдения; это не повторная проверка на новом окружении. Порядок чтения и ограничения: [инженерная память](README.md#как-читать-записи).

**TS VAE Fix** (`TS_VAEFix`, `nodes/image/ts_vae_fix.py`, `TS/Image/Retouch`,
с 09.10.2026, релиз 12.12.8; до выпуска называлась TS VAE DeGrid — имя выбрал
владелец, в графах старого id нет) —
аналог ComfyUI-DeGrid (lunaaispace-eng, Apache-2.0), написан заново по математике.

Замеры фазово-синхронной амплитуды решётки (/255) на настоящих PNG из
`D:\AiApps\ComfyUI\comfyui\ComfyUI\output`, VAE взят из метаданных графа:

| VAE | амплитуда |
|---|---|
| `qwen_image_vae` (обычный Qwen Image) | 1.58–1.69 → чистит |
| `qwen_image_2.1_vae_bf16` | 1.78–1.79 → чистит |
| `texture_fix_vae_for_qwen_image_2.1` | 0.09–0.43 → пропуск |
| `wan_2.1_vae` (им же у владельца декодирует **Krea 2**) | 0.12–0.24 → пропуск |
| Flux `ae`, `flux2-vae`, `flux2-vae-v2` | 0.01–0.23 → пропуск |
| HunyuanImage 3 VAE | 0.46–0.59 — ⚠️ ПОГРАНИЧНО у порога 0.5 |
| что угодно после апскейла/ресайза | ≤0.05 |

⚠️ README ComfyUI-DeGrid пишет, что Wan 2.1 VAE и Krea2 задеты. На нашей
машине это не подтвердилось: Krea 2 через `wan_2.1_vae` решётки не даёт. Не
утверждать обратного без нового замера.

⚠️ **«Соты» WAN 2.1 (жалоба 15.10.2026) — НЕ решётка, нотчем их не взять.**
Замер на Krea 2 владельца, один латент (seed 784852229756955), два декодера:
`krea2-2026-10-14_234232` (wan_2.1_vae) против `…_234349` (qwen_image_vae;
энкодер у Qwen Image тот же, что у WAN 2.1, дообучен только декодер — латент
совместим, картинка та же).
- Фазово-синхронный узор с шагом 8/16 px есть, но слабый: 0.4–0.9 и 1–1.8/255
  при шумовом полу соседних периодов 0.1–0.35; глобальный шаблон объясняет
  <0.5% энергии высоких частот, локальный гребёнчатый фильтр (p=8) на глаз
  ничего не меняет. Вычитать нечего.
- Настоящая разница — спектральная: у WAN мощность выше 0.3 цикл/px (период
  <3.3 px) в 2–4 раза больше, средние частоты равны. Это мелкая крапчатая
  зернистость декодера, сгруппированная по ячейкам латента.
- После TS DLSS Upscaler 2× эта зернистость раздувается в отчётливые круглые
  ячейки ~8–10 px — вот где «соты» видны сильнее всего. Чистить надо ДО апскейла.
- Мягкое пороговое сжатие верхней полосы (x − gauss σ0.8, порог k·MAD) убирает
  крапинку и приближает к декоду Qwen (hi-band 5.37 → 4.5–4.8/255, у Qwen 4.32),
  но автоматически отличить её от настоящей фактуры детектор не умеет — это
  был бы ручной режим. Альтернатива без кода — другой декодер того же латента
  (`qwen_image_vae`, у владельца есть ещё `krea2/krea2RealVae_v10` и
  `wan/Wan2.1_VAE_upscale2x_imageonly_real_v1`).

⚠️ **Автодетектор зерна WAN не построить — замерено.** По выходам владельца
(по 8–10 нативных декодов на VAE) ни «наклон» спектра (hi/mid), ни зерно в
ровных местах, ни диагональные «углы» спектра не разделяют wan_2.1 и
qwen_image_2.1 / flux2 / krea2RealVae — диапазоны перекрываются. Фильтр без
переключателя чистил бы и чужие картинки.

**Что есть в сети (поиск 15.10.2026):** проблема известна — «speckles, polka
dots and grain» исходного декодера WAN на СГЕНЕРИРОВАННЫХ латентах.
- spacepxl/Wan2.1-VAE-upscale2x (Apache-2.0): дообучен только декодер, энкодер
  заморожен → латент совместим с Wan 2.1 / Qwen Image / Krea 2. Учили на
  «деградированных» латентах (прокси SDEdit-деградации Wan 1.3B) именно против
  этого зерна. Голова 12 каналов + pixel shuffle = вывод 2×; штатный VAEDecode
  его не читает — нужен ComfyUI-VAE-Utils. Только картинки (видео-версии нет),
  слабее на аниме/лайнарте/тексте.
- `krea2RealVae` = тело декодера spacepxl с усреднённой 3-канальной головой,
  вшитое в обычный VAE: грузится ШТАТНЫМ VAELoader, вывод 1×. У владельца
  лежит `models/vae/krea2/krea2RealVae_v10.safetensors` — это и есть
  универсальная замена wan_2.1_vae для любых картиночных графов на латенте
  WAN 2.1. Для видео Wan — не проверено (декодер учили на картинках).
- **A/B на одном латенте 15.10.2026** (Krea 2, seed 784852229756955, файлы в
  `output/vae_ab/`): krea2RealVae заметно резче WAN (мощность выше 0.4 цикл/px
  в 3–9 раз больше) — на глаз это настоящая деталь (кожа, ветки, камни), а
  размытые «пятна-ячейки» WAN ушли; после DLSS 2× он всё ещё резче, без новых
  ячеек. qwen_image_vae — самый гладкий, но мягче и с решёткой 2 px (снимает
  TS VAE Fix). upscale2x штатный VAEDecode не читает («Cannot handle this data
  type: (1, 1, 12)») — нужен ComfyUI-VAE-Utils, у владельца не стоит.
- **Artius Wan (граф «Image Gen Artius Wan», 15.10.2026):** владелец подозревал
  int8-конверсию модели. Метрики сетки латента (скачки на линиях 8/16 px,
  фазовый шаблон 8×8) по ВСЕЙ истории output — fp16, fp8_scaled, fp8_mixed,
  int8_convrot, `.tsmodel` — одинаково на уровне шума (grid8 0.93–0.98, шаблон
  0.15–0.5/255): int8 сетки НЕ добавил. Отличия старого чистого графа от
  нынешнего: 1344×768 (1.0 МП) → 1.5 МП, shift 0.7 → 1.0, WanVideoNAG → TS_NAG,
  с 14.10 добавлен TS DLSS Upscaler. На прогонах портрет/волна (seed 424242,
  813273948338549, 1234567; `output/vae_ab_wan/`) соты глазами не нашлись —
  нужен конкретный кадр владельца.
- Источники: huggingface.co/spacepxl/Wan2.1-VAE-upscale2x,
  github.com/fblissjr/krea-explorations/blob/main/docs/krea2_vae.md.

После чистки Qwen 2.1: 1.78 → 0.28, Qwen: 1.65 → 0.11; картинка меняется в
среднем на 0.7–0.9/255, максимум ~3.6/255.

Решения, которых нет в оригинале:
- **Детектор ограничивает поправку `_DETECT_CAP = 0.02` перед усреднением.**
  Длинный прямой край тоже когерентен по фазе: вертикальный край на 128 px
  давал 0.52/255 (выше порога) — ложная «решётка». Вклад края падает как
  1/ширина, на 1024 px он 0.05.
- **Пакет = один ролик:** одно решение и медиана авто-лимитов на все кадры.
  Решение по кадрам у порога заставило бы видео мерцать.
- Покадровый расчёт (два прохода, поправка пересчитывается, а не хранится):
  память — несколько копий ОДНОГО кадра, не пакета.
- Альфа-канал не трогается; `torch.quantile` по разрежённой выборке (>2^24
  элементов он отказывается).
