Видео backend: PyAV, запись, DynamicCombo и причины выбора тракта.

**Граница записи:** ниже сохранены исходные наблюдения и причины решений. Замеры, версии окружения и слова «сейчас» относятся к дате соответствующего наблюдения; это не повторная проверка на новом окружении. Порядок чтения и ограничения: [инженерная память](README.md#как-читать-записи).

# Видео-ноды `nodes/video/media/` (v10.2+)

Три публичные ноды в одной подпапке (санкционированный split §7.1): `TS_VideoLoader`,
`TS_VideoInfo`, `TS_VideoSaver`. Приватные: `_common` (тип `TS_VIDEO_INFO`, пути),
`_probe` (метаданные, пики, спрайты), `_decode`, `_encode`, `_formats`, `_routes`.
Фронтенд: общий слой `js/_media/` + `js/video/loader/` и `js/video/saver/`.

## ⚠️ Замеры, на которых стоит вся конструкция (2026-08-11, RTX 3080 Ti)

Файл `input/6323267-uhd_4096_2160_30fps.mp4` (4096×2160, h264, 30 fps):

| Что | Результат |
|---|---|
| Декод 2 с «наивно» (полное разрешение → `torch.stack` → ресайз torch) | **5.9 с**, 6.4 ГБ |
| Тот же кусок через `av.filter.Graph` (`scale` внутри) + `thread_type="AUTO"` | **0.43 с** |
| Без многопоточного декода | 1.61 с (**×3.7** штрафа) |
| 300 кадров 4K → 1024×540, software | **0.89 с** |
| То же с `hwaccel=cuda` | **2.78 с** — ВТРОЕ МЕДЛЕННЕЕ; `d3d11va` — 4.93 с |
| Проба `av.open` | **34 мс** (против 56 мс + процесс у `ffmpeg -i` с regex по stderr) |
| `container.seek()` | садится на keyframe раньше цели на 0.77–0.9 с |

**Аппаратный ДЕКОД не использовать** — он медленнее. В коде стоит комментарий с
цифрами и датой, чтобы это не «чинили» из лучших побуждений.

## Форматы записи

`H.264 / MP4`, `H.265 (HEVC) / MP4` (с необязательными десятью битами) и
`ProRes / MOV` (шесть профилей). Добавить формат = строка в `FORMATS` плюс
`Option` в схеме сейвера.

⚠️ У HEVC обязателен `codec_tag = "hvc1"`: без него QuickTime и монтажки файл не
открывают — они узнают HEVC именно по этой метке, а не по `hev1` по умолчанию.
⚠️ `x265-params: log-level=error` не только про порядок: без него x265 вываливает
в консоль ComfyUI два десятка строк про свою сборку — в том числе при КАЖДОЙ
пробе кодировщика, поэтому проба тоже идёт с настройками первого качества.

Уровни качества проверяются измерением, а не на слово: `tests/test_video_media.py`
требует, чтобы «черновик» и «отлично» давали заметно разные файлы. Если настройки
перестанут доезжать до кодировщика, выбор качества превратится в украшение, и
заметить это иначе нельзя.

## Ключевые решения

- **Весь ресайз/поворот/формат — в графе фильтров**, не в Python. План пиксельного
  формата решается ОДИН раз по источнику: 8 бит → `rgb24`, >8 бит → `gbrpf32le`.
  VHS всегда тянет `rgba64le` (8 байт/пиксель) и делает промежуточный float64.
- **Кадры после seek, но до `start_pts`, в граф НЕ пускаются** — декодировать их
  обязательно (межкадровые зависимости), масштабировать нет.
- **Сэмплер по временным меткам**, а не фильтр `fps` (теряет кадр на границе) и не
  счётчик кадров (врёт на VFR). Окно **полуоткрытое**: 2 с при 12 fps = 24 кадра.
- **Предвыделение тензора + потолок `TS_VIDEO_MAX_BYTES`** с внятной ошибкой вместо OOM. Текущий приоритет: положительная переменная окружения → максимум запасных 8 ГиБ и 60% полной ОЗУ → запасные 8 ГиБ, если ОЗУ неизвестна (см. `_decode._max_bytes`).
- **Звук — в том же демуксе**, одним проходом. `TS_SAM_MediaLoader` для сравнения
  читает файл дважды (cv2 + отдельный ffmpeg).
- **Запись — одним проходом одним контейнером**: видео и звук чередуются по
  времени. Ни временного WAV, ни второго файла (у VHS и у `TS_Animation_Preview`
  оба этих греха есть).
- ⚠️ `movflags=+faststart` работает ТОЛЬКО при записи в файл; в `BytesIO`
  `av_write_trailer` падает. Отсюда пара `mux_options` / `file_mux_options`.
- ⚠️ Проба кодировщика обязана открывать **свой контейнер**: `prores_ks` в `mp4` не
  принимается, и проба в mp4 объявляла ProRes недоступным.
- ⚠️ Пробный кадр **не меньше 256×256**: `h264_nvenc` на 128×128 отвечает «Frame
  Dimension less than the minimum supported value».

## `DynamicCombo` — проверено живьём

Работает в ОБОИХ режимах нод. Подвиджеты именуются `<родитель>.<ребёнок>`
(у ядрового `SaveVideo` — `codec.encoding`). У `DynamicCombo.Input` **нет**
параметра `default`: умолчание задаётся порядком вариантов.

⚠️ **В промпте значение плоское, а в `execute` — словарь.** По HTTP надо слать
`"format": "ProRes / MOV"` и **отдельным ключом** `"format.profile": "422 HQ"`;
словарь `{"format": ..., "profile": ...}` сервер принимает молча и подменяет
вариантом по умолчанию — прогон завершается успехом, но пишет не тот формат.
Пропуск обязательного подключа даёт честный HTTP 400.

⚠️ **`test_all_nodes_roundtrip` даёт на такой ноде ложное падение**: он выдаёт
каждому виджету другое значение, то есть переключает и родительский `format`, —
а подвиджет выбранного варианта при этом законно исчезает. Внесено в
`BY_DESIGN_EXCEPTIONS` с объяснением; сама сохраняемость проверена отдельно и
работает так же, как у ядрового `SaveVideo`.

## ⚠️ `nodes` — имя и нашего пакета, и ядрового модуля ComfyUI

Тест, положивший корень ComfyUI в `sys.path`, оставляет в `sys.modules` ЕГО
`nodes.py`, и наши `nodes.video.media.*` перестают находиться. Ловится только в
полном прогоне или при определённом порядке файлов. В `tests/test_video_media.py`
есть `_ensure_pack_nodes()`, возвращающий имя нашему пакету; в
`tests/test_lora_loader_node.py` — обратная защита (скип, если `nodes` подменён).
При написании новых тестов, которым нужен настоящий ComfyUI, помнить об этом.
