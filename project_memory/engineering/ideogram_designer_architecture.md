Ideogram Designer: выходы, пресеты, редактор, preview и известные ограничения.

**Граница записи:** ниже сохранены исходные наблюдения и причины решений. Замеры, версии окружения и слова «сейчас» относятся к дате соответствующего наблюдения; это не повторная проверка на новом окружении. Порядок чтения и ограничения: [инженерная память](README.md#как-читать-записи).

`TS_IdeogramDesigner` (node_id `TS_IdeogramDesigner`, category `TS/Ideogram`, display "TS Ideogram Designer") is a visual designer that emits an **Ideogram 4 structured-JSON caption**. Exact caption schema + Ideogram gotchas: [ideogram4-caption-format](ideogram4-caption-format.md). Current state below is the truth as of commit `192d82d` (version 9.73); ignore older git changelog detail.

## Outputs & data flow
- **Outputs:** `json_prompt` (STRING) + `width` (INT) + `height` (INT). No aspect-ratio output. Editor has a megapixels slider (0.5–2 MP); `dims_from_aspect_mp` → `height=sqrt(MP*1e6/ratio)`, `width=height*ratio`, both rounded to a **multiple of 32** (mirrored JS `dimsFromAspectMp`; 16x9@1MP→1344×736, 1x1@2MP→1408×1408).
- **Flow:** the JS editor serializes its whole state object (`work`) — incl. `language` ru/en, `megapixels`, blocks, style — into a hidden `design_json` STRING widget. `execute` → `build_caption(design_json)` (caption) + `dims_from_design(design_json)` (W/H). The editor's live JSON panel calls `POST /ts_ideogram/preview` so the shown caption is **server-authoritative (no JS/Python drift)**. The optional `image` input is a **reference underlay only** (cached to the input dir via `unique_id`; upload via core `/upload/image` + `/view`).

## Files
- `nodes/ideogram/` — `ts_ideogram_designer.py` (V3 node, stateless); `_ideogram_helpers.py` (caption builder + `frac_to_bbox` + `clean_palette`/`norm_hex` + dims math + design-preset store + all `/ts_ideogram/*` routes; **run `python _ideogram_helpers.py` for the self-test**); data JSON: `ideogram_fonts.json` (**30** fonts), `ideogram_styles.json` (**18** styles), `ideogram_layouts.json` (**18** layouts); `user_presets/` (gitignored: `designs/<id>.json` + legacy layouts/styles).
- `js/ideogram/` — `ts-ideogram-designer.js` (entry / `registerExtension`); `_ideogram_node.js` (in-node preview, V1 LiteGraph + V2 Vue safe); `_ideogram_editor.js` (full-screen modal editor on `document.body`); `_ideogram_shared.js` (utils, i18n, preset pools, JS mirrors of `frac_to_bbox`/`compose_text_desc`/`dims_from_aspect_mp`).
- `load_fonts/styles/layouts` read their JSON **fresh per request** → editing preset DATA needs NO ComfyUI restart. The editor entry is JS → browser hard-refresh (Ctrl+Shift+R) after JS edits. Routes register at module import → **Python logic / route changes need a ComfyUI restart**.

## Preset system (the core architecture)
A design is composed top-down: **Layout → Idea → (visual style + mood + lighting + background + objects + texts)**. Surfaces:
1. **Layouts** (`ideogram_layouts.json`, 18) — composition skeletons. Each block: `type` (text|obj) + `role` + `rect` {x,y,w,h fractions} + (text) font/weight/case/color/legibility. `instantiateLayout(layout, lang)` builds the editor blocks (reads per-block `legibility {outline,solid_block}`, `outline_color`, `plate_color`, `desc_override`, obj `color_palette`). Picked via the **«Макет»** dropdown. 3 are TEXT-FREE (`art_hero`, `art_composition`, `surreal_scene` — obj-only). Renamed display names: material_typography=Материальная типографика, logo_mascot=Логотип с персонажем, art_hero=Арт персонаж, art_composition=Композиция объектов (ids unchanged).
2. **Ideas / «Главная идея»** (`LAYOUT_BRIEFS` in `_ideogram_shared.js`, **10 per layout = 180**) — a COMPLETE scene for a layout. Schema: `{ ru, en, v(=high_level_description), style_preset_id, aesthetics_id, lighting_id, background_id, objects:[{role,desc}], texts:[{role,en,ru, font_preset_id?, color?, desc_override?}] }`. The dropdown lives INSIDE the «Макет» card (right after the layout picker). Picking it (or switching layout → its `idea[0]`) runs **`applyBrief(idea)`**: sets HLD, applies the visual style, sets `work.style.aesthetics`/`lighting` + `work.background` to the **named sub-presets' exact `.v`** (so the dropdowns below show a real selection, not «Своё»), sets `work.background_palette` from the background preset's baked-in `colors`, and fills each block BY ROLE — obj.desc from `objects`, and for text blocks the literal AND **its lettering treatment** (`font_preset_id` + `color` + `desc_override`) from `texts`, so each idea's lettering reflects its preset. Skips blocks the user manually overrode (`userSetSubjects`). Then `renderBlocks`+`renderLayers`+`renderBlockPanel`+`renderInspector`. **Per-idea lettering (bug-fixed 2026-06-29):** each idea's PRIMARY text block gets a font — for `material_typography` the MATERIAL named by the idea (fur→soft_fur, gold→molten_gold…, derived by substring on the idea's clean EN label, NOT the v sentence — "ju·ice"/"frozen mid-motion" used to false-match ice) + a matching colour + `desc_override:""` to wipe the layout's hardcoded ice override; for every other text layout the font of the idea's **visual style** (`styles[style_preset_id].font_preset_id`), so a luxury idea gets didone, a tech idea mono, etc. Without this, ALL `material_typography` ideas rendered ICE (the layout default). Assembled deterministically by `scratchpad/assemble_ideas3.py` (no workflow).
3. **Visual style / «Визуальный стиль»** (`ideogram_styles.json`, 18) — a full look `{medium, aesthetics, lighting, photo|art_style, color_palette, font_preset_id}`. One dropdown (the former "Готовый стиль" + "Художественный стиль" merged). **`applyStylePresetById(id)`** sets medium/art_style/photo/color_palette/font_preset_id ONLY — it does NOT set aesthetics/lighting (those are owned by the named sub-presets).
4. **Sub-preset pools** (`_ideogram_shared.js`) — `MOOD_PRESETS` (12 → `style.aesthetics`), `LIGHTING_PRESETS` (12 → `style.lighting`), `BACKGROUND_PRESETS` (**18, each with baked-in `colors`** → `background` + `background_palette`). These are the named items ideas reference and the inspector dropdowns (`presetSelectRow`, which has an optional `onPreset(preset)` cb; background uses it to set `background_palette` from `colors`).
5. **Fonts / «Стиль текста»** (`ideogram_fonts.json`, 30) — per-text-block typographic style. 16 classic descriptors + 14 MATERIAL treatments (ice_crystal, neon_tube, fresh_fruit, soft_fur, water_splash, carved_stone, clear_glass, liquid_chrome, molten_gold, flames_fire, balloon_3d, lush_floral, carved_wood, dripping_paint). The `desc_snippet` IS the lettering descriptor (Ideogram can't name typefaces). `FONT_FAMILY` (shared) maps each id → a CSS family for the WYSIWYG preview only.
6. **Objects** (`OBJECT_PRESETS`, 30) — quick-add subjects for an obj block's `desc` (`objectPresetRow`; marks `userSetSubjects` so a later idea won't clobber it).
7. **Design presets** (`user_presets/designs/<id>.json`, gitignored) — the WHOLE editor state by name. «Пресет дизайна» card: load/save/export/import/delete. Routes `GET /ts_ideogram/design`, `POST /save_design|/import_design|/delete_design`, and `designs:[{id,name}]` in `/presets`.

Quick-pick helper pools also exist: `ARTSTYLE_PRESETS` (kept as data but the standalone art-style dropdown was removed — merged into Visual style). All preset content is served by `GET /ts_ideogram/presets`.

## Editor UI (current)
Full-screen modal, RU/EN (`I18N` + `t(key,lang)`; UI localized, **prompt-content fields stay English by design** — they ARE the model prompt). Tooltips resolve the i18n key at hover time (`.ts-ideoe-tip`).
- **LEFT — general settings inspector** (`renderInspector`): «Пресет дизайна» (designCard) → «Макет» (templateCard: layout dropdown + «Главная идея» dropdown) → «Стиль» (styleCard: Визуальный стиль → Настроение → Освещение → Фон → palettes lighting/background/image) → live **JSON-prompt panel** at the bottom (polls `/preview` every 500ms with a `lastJsonSig` guard + monotonic `jsonReqId`; pretty-printed + **syntax-highlighted** via `highlightJson`; copy button yields raw JSON).
- **RIGHT — layers + block settings**: layers panel (Photoshop-like; **z-order = `work.blocks` array order**, frontmost at top; drag-reorder; +Text/+Object/Duplicate/Delete footer; `Ctrl+]`/`[`±Shift). Below it, the selected block's settings (`renderBlockPanel`/`blockCard`): for text — «Стиль текста» (font) + literal + weight(Thin/Regular/Bold) + case + color + legibility(Обводка/Плашка, each with its own colour picker shown only when on) + visual-only + desc override + live desc preview; for obj — desc + object preset + block palette.
- **STAGE — artboard**: aspect-correct; blocks are draggable/resizable DOM divs; double-click → inline text edit; `fitText` binary-search makes canvas text WYSIWYG; artboard background is tinted by **image palette + background palette** (`applyStylePreview` → `paletteGradientCss` mesh). Selection shown by box-shadow (NOT z-index).
- **Live feedback:** `onStyleChange()` = `renderBlocks()` + `refreshJson(true)` is wired to every style/look/colour control, so any change re-tints the canvas (colour changes) and updates the live prompt immediately.

## In-node preview
`_ideogram_node.js` draws a fluid **WYSIWYG miniature of the editor** (real fonts/weights/colours/outline/plate via `drawFittedText` with word-wrap; obj blocks show their desc; mesh palette via `paintPaletteRect`). «Редактировать» button (or dbl-click) opens the editor. V1(LiteGraph)/V2(Vue)-safe DOM widget.

## Key code map
- **Python** `build_caption` → `{high_level_description?, style_description?, compositional_deconstruction}` via `_build_style_description` (photo vs non-photo key order — see caption-format memory), `_build_element` (text/obj element + per-element `color_palette` from text/outline/plate colours), `compose_text_desc` (slot 1 = per-block **`font_desc` override** else font `desc_snippet` → weight → case → **size from drawn rect** `_size_phrase_from_rect` → colour → outline/plate colours → **`desc_override` appended last**; NO hardcoded "thumbnail" tail; mirror in JS `composeTextDesc`). `frac_to_bbox` = `[y,x,y,x]` ints 0–1000 (verified JS≡Python; all 180 ideas emit valid bboxes 530/530).
- **Editor** `applyBrief` / `applyStylePresetById` (+ lookup maps `MOOD_BY_ID`/`LIGHT_BY_ID`/`BG_BY_ID`), `instantiateLayout`, `renderInspector`/`renderBlocks`/`renderLayers`/`renderBlockPanel`, `briefRow`/`templateCard`/`styleCard`/`stylePresetRow`/`presetSelectRow`/`paletteRow`/`blockCard`, `applyStylePreview`/`onStyleChange`.

## Constraints & gotchas
- **The artboard is a layout MOCKUP**: it can only render COLOURS (palettes re-tint live) + block layout. Lighting/mood/art-style are prose cues that only become a visible image in Ideogram's FINAL render — on the mockup their feedback is the live JSON prompt. (Conveyed to the user repeatedly.)
- **Ideas reference NAMED sub-presets** so dropdowns show real items; if you regenerate ideas, keep `aesthetics_id`∈MOOD, `lighting_id`∈LIGHTING, `background_id`∈BACKGROUND, `style_preset_id`∈styles, and roles ⊆ the layout's block roles; TEXT-FREE layouts have empty `texts`.
- **No z-index field in the caption** — element array order is the only stacking lever (drives editor DOM + node preview + Python). Re-confirmed vs `prompting.md`.
- **Restart matrix:** preset JSON data → no restart; JS → browser hard-refresh; Python logic/routes (build_caption, /save_design, etc.) → ComfyUI restart.
- **Editor interaction invariants (bug-fixed 2026-06-29):** (a) «Очистить всё» must reset ALL colour palettes — `work.style.color_palette` AND top-level `work.background_palette` AND `work.style.lighting_palette` — else the artboard stays tinted (applyStylePreview blends image+background palettes). (b) `startDrag` MOVE mode has a **4px activation threshold** (resize handles activate immediately) + `onUp` only re-renders if a real drag happened — so a click / double-click with a tiny jiggle never drags the block or steals the double-click-to-edit (that was the "can't type in a new block" glitch). (c) Layer reorder (▲/▼ + drag) changes **z-stacking only** (`renderBlocks` sets `div.style.zIndex=i+1`, `.is-selected` has NO z-index) — visible only when blocks OVERLAP; side-by-side blocks show no visual change (correct, not a bug — verified via elementFromPoint).
- **Editable prompt under every preset (2026-06-29):** each preset selector (Visual style, Mood, Lighting, Background — via `presetSelectRow`; the style row; the font row) has an ALWAYS-visible editable textarea (`.ts-ideoe-prompt`) showing the exact prose it feeds the model; typing in it flips the selector to «Своё» live (`sel.value="__custom__"`) WITHOUT clearing palettes (only an explicit preset/None pick touches palettes). Font uses a **slot-1 `font_desc` override** (replaces the snippet, both JS+Python `compose_text_desc`); style edits `art_style`/`photo` and clears `preset_id`. `onStyleChange` (renderBlocks+refreshJson, NOT renderInspector) keeps focus while typing. `applyStylePresetById` now ALSO seeds `aesthetics`/`lighting` (complete look; idea flow overrides them right after).
- **Per-idea text colour for contrast (2026-06-29):** layouts hardcode each text block's colour for THEIR palette, so a dark headline leaked onto dark-palette ideas (unreadable — 34 cases found by adversarial review). The assembler now sets `texts[].color` per idea when the layout colour's WCAG contrast vs the idea's background tone <2.5, picking whichever of light(`#F4F4F4`)/dark(`#141414`) contrasts MORE (NOT "avg<0.5→white" — mid-tone bg favours dark). Skips material-lettering colours (intentional gold/neon) + plated blocks. ~93/350 recolored; residual <2.5 are material colours (kept) + rely on outline.
- **Dead code removed (2026-06-29):** `ARTSTYLE_PRESETS` (unused 13-preset array), `PHOTO_MEDIUM` editor import. Also fixed: empty `background:""`/`elements:[]` no longer leak into the caption (omitted); shadowed `t` in applyBrief → `tx`; fragile `blocksLayer.children[indexOf]` → `querySelector([data-id])`; export name from HLD not always "design". STILL OPEN (low/edge): clone-block logic duplicated ×3 (`duplicateSelected`/`pasteBlock`/Alt-drag — could unify as `cloneBlock`); modal `paste`/`keydown`/`jsonTimer` only torn down in `close()` (leaks if the node is deleted while the editor is open); no-op `renderWarnings`/`updateBanner` scaffold remains.
