TS Model Resize (15.10.2026) — откуда взяты таблицы разрешений моделей, где сообщество ошибается, и два вида пресетов (бакеты и площадь на сетке)

Исходники темы: [ts_model_resize.py](../../nodes/image/ts_model_resize.py).

**Граница записи:** ниже сохранены исходные наблюдения и причины решений. Замеры, версии окружения и слова «сейчас» относятся к дате соответствующего наблюдения; это не повторная проверка на новом окружении. Порядок чтения и ограничения: [инженерная память](README.md#как-читать-записи).

**TS Model Resize** (`TS_ModelResize`, `nodes/image/ts_model_resize.py`,
`TS/Image/Size`) — картинку под родные разрешения модели; ориентацию нода
определяет сама (ближайшее соотношение сторон в лог-шкале). Просьба владельца
15.10.2026: «выбираю пресет WAN — картинка 1280×720, вертикальная — под неё».

Таблицы сверены с первоисточниками 15.10.2026:
- Wan — `SUPPORTED_SIZES` в `Wan-Video/Wan2.2/wan/configs/__init__.py`:
  A14B (t2v/i2v) 1280×720 и 832×480 в обе стороны; TI2V-5B — ТОЛЬКО
  1280×704 / 704×1280; S2V добавляет 1024×704. Квадрата у Wan нет — квадрат
  уходит в горизонталь (ничья по аспекту → первый бакет).
- Qwen Image — dict `aspect_ratios` в README QwenLM/Qwen-Image.
  ⚠️ 4:3 = 1472×1104. Сообщество (ноды, Reddit) пишет 1472×1140 — это НЕ
  таблица Qwen; тест стережёт.
- SDXL — таблица бакетов из arXiv 2307.01952 (взята до ~2.4:1).
- Z-Image Turbo — уровень 1024 из официального HF Space (источник —
  сторонняя нода, ссылающаяся на Space; не первоисточник).
- FLUX — шаг 16, ≤2 МП (help.bfl.ai). LTX-2/2.5 — шаг 32. HunyuanVideo 1.5
  720p — точных размеров в первоисточнике не нашёл, поэтому пресет по площади.

Два вида пресетов: «бакеты» (фиксированный список) и «площадь на сетке»
(форма картинки сохраняется, под сетку срезаются считанные пиксели).
`fit`: crop / pad / stretch; выход `mask` = 0 на полях pad (для аутпейнта);
альфа на полях прозрачна. ⚠️ Имена пресетов живут в графах — не
переименовывать. Krea 2 / Qwen 2.1 не добавлены: официальных таблиц не нашёл.

Гард: `tests/test_model_resize.py`.
