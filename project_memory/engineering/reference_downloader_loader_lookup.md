# Загрузчик моделей: «на диске» = «загрузчик найдёт»

24.09.2026, просьба владельца. Он раздаёт подписчикам готовые workflow: путь в
загрузчике и строка в TS Files Downloader — две независимые записи, и они обязаны
сходиться. Условие владельца дословно по смыслу: улучшение не имеет права
сломать автоматическую связь «путь в ноде ↔ путь в загрузчике».

## Правило

Зелёная точка ⇔ `folder_paths.get_full_path(категория, "<подпапка>/<файл>")`
находит файл. Это ТОТ ЖЕ вызов, что делают штатные загрузчики и наши
`TS_Locked*` (`nodes/loaders/_locked.py: resolve` — тот же перебор папок).
⚠️ Своего поиска (`os.walk`, `listdir`) в `_loader_path` быть не должно — гард
`test_the_answer_comes_from_comfyui_itself`.

До правки нода смотрела ровно в одну папку (`_known_model_folder_root` выбирает
одну), а загрузчик — во все папки категории, включая `extra_model_paths.yaml`.
Модель из общей папки качалась второй раз.

## Устройство (nodes/files/ts_downloader.py)

* `_loader_scopes(target_dir)` — папка строки → `[(категория, подпапка)]`.
  Берётся САМЫЙ ГЛУБОКИЙ зарегистрированный корень: пак, зарегистрировавший
  весь `models/` своей категорией, иначе перехватил бы все строки.
  `custom_nodes`/`datasets` исключены. Вне корней → `[]` → старые правила.
* `_loader_path(target_dir, name)` — что откроет загрузчик, или "".
* `_shadowing_file` — ДРУГОЙ файл (другого размера), который загрузчик откроет
  вместо скачанного: `is_default: true` в yaml ставит общую папку впереди
  `models/`. Одинаковый размер = та же модель, не тревога.
* Движок: `skip_existing` + файла в целевой нет + загрузчик находит его в
  другом месте + размер совпал с сервером (или проверка выключена / сервер
  размера не дал) → пропуск. В чужую папку НИЧЕГО не пишется (ни `.tsmeta`, ни
  распаковка). Папка назначения теперь создаётся только когда писать есть что.
* Быстрый путь без сети: запись `.tsmeta` засчитывается и в чужой папке, но
  только для того самого файла, который откроет загрузчик.
* После прогона `_report_shadowed` пишет ERROR на каждую затенённую строку.
* `fingerprint_inputs` учитывает копию в общей папке: удалили её — нода
  перезапустится.

⚠️ Файл в ДРУГОЙ подпапке или ДРУГОЙ категории остаётся «не скачан» и качается:
загрузчик графа его не найдёт. Сознательно; кнопку «связать» (жёсткая ссылка)
владелец отложил.

## Жалоба пользователя 24.09.2026 — три дефекта, все воспроизведены тестами на 12.11.5

«Открываю сторонний workflow — качает вчерашние модели, "Проверить" не помогает».

1. ⭐ **Главное: две папки на категорию в ШТАТНОМ ComfyUI.** `folder_paths.py`:
   `diffusion_models = [models/unet, models/diffusion_models]`,
   `text_encoders = [models/text_encoders, models/clip]`. Один автор пишет в
   списке `unet`, другой `diffusion_models` — загрузчику всё равно, а нода
   смотрела в одну папку. Не нужен никакой yaml — хватает двух чужих workflow.
   Лечится поиском через `get_full_path` (выше).
2. **Тот же файл по имени, другой по содержимому** (другой автор/сборка).
   Меньше серверного → файл переименовывался в `.part` и «докачивался» хвостом
   новой версии: HF-хэш выбрасывал гибрид (модель человека пропадала), без хэша
   — гибрид принимался. Больше → удалялся ДО загрузки. ⚠️ Файл под финальным
   именем НИКОГДА не наш недокачанный: движок пишет в `.part` и переименовывает
   после проверки. Теперь старый файл не трогается, новая версия качается
   целиком и заменяет его `os.replace` только после проверки.
3. **`%20` в адресе**: маршрут статусов не раскодировал имя, движок —
   раскодировал. Точка красная навсегда у скачанного файла. То же в отпечатке.

## Статусы (`_downloader_status.py`)

`ready` + `elsewhere: <папка>` — лежит в другой папке, которую загрузчик читает.
`shadowed` + `loaded: <путь>` — скачана, но откроется другой файл; красная точка.

## Сверка с загрузчиками графа (фронтенд)

`js/files/_downloader_graph.js` — чистый модуль (без `app`/`api`, тестируется
Node): `judgeLine(имя, папка строки, ожидания)` → `mismatch` (загрузчик ищет в
другой папке; кнопка «Исправить», только если папка одна), `unused` (ни один
загрузчик не выбирает; приглушённо, это не ошибка) или `null`.
⚠️ Туда же переехали `FOLDER_ALIASES`, `canonTarget`, `sameTarget`, `MODEL_EXT` —
«Взять модели из workflow» и сверка обязаны судить о папках одной функцией.
`MODEL_EXT` получил `tsmodel`, а таблица `TYPE_TO_FOLDER` — три `TS_Locked*`:
сервер их папку определить не может (`.tsmodel` нет ни в одной категории).

Ожидания = `graphExpectations(app.graph, loaderMap)` поверх того же
`visibleModelValues`. Пересчёт по `api` событию `graphChanged` (debounce 500 мс),
перерисовка только если отпечаток ожиданий изменился; отписка в `onRemoved`.
⚠️ Точка статуса — о ДИСКЕ, строчка сверки — о ГРАФЕ; смешивать нельзя.

⭐ **Сравнение ТОЧНОЕ, по ключу реестра, а не по имени папки.** Маршрут статусов
отдаёт для каждой строки `scopes` = `_loader_scopes(target)` →
список пар «категория, подпапка»; `/ts_downloader/loader_folders` отдаёт рядом с
`types` (папка — для показа) ещё `categories` (ключ реестра виджета). Общая
функция `sameDestination(target, {folder, category, sub}, scopes)` судит и
сверку списка, и кнопку «Взять модели из workflow» (`classify`, 4-й параметр
`scopesOf`). По имени папки (с синонимами `unet`/`clip`) — только когда
категория загрузчика неизвестна. Корень из yaml с любым именем, общий корень
`unet_gguf` + `diffusion_models` — судятся верно.
⚠️ Пока статус строки не пришёл (`scopes === null`), «не та папка» не
говорится: иначе строка мигала бы красным до точного ответа.

`_verified_elsewhere(target, url)` — запись `.tsmeta` НАШЕЙ загрузки в соседней
папке категории, по АДРЕСУ: только так находится модель, чьё имя дал сервер
(Civitai: `…/models/12345`). Засчитывается, только если загрузчик откроет
именно этот файл.
