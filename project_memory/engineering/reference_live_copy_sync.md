Разные checkout разработки и ComfyUI: сверка содержимого и история ошибок доставки исправлений.

**Текущая опора (2026-11-02):** Разработка и установленный пак могут быть разными checkout. Проверять нужно тот код, который отдаёт/исполняет сервер. Конкретные пути владельца — [окружение](../../doc/operations/environment.md); правила синхронизации и разрешений — [разработка](../../doc/operations/development.md). Упоминание активной image-studio ветки ниже — история 2026-08-03.

**Граница записи:** ниже сохранены исходные наблюдения и причины решений. Замеры, версии окружения и слова «сейчас» относятся к дате соответствующего наблюдения; это не повторная проверка на новом окружении. Порядок чтения и ограничения: [инженерная память](README.md#как-читать-записи).

`D:\AiApps\ComfyUI\comfyui\ComfyUI\custom_nodes\comfyui-timesaver` — **самостоятельная
копия** (git clone), а не junction на dev-папку: `os.path.samefile()` даёт `False`.
Штатно она обновляется `git pull` — но пока работа идёт в неслитой ветке
(`image-studio`), pull брать неоткуда, и правка в `Documents\...` **не видна ComfyUI**.

**Чем это кусается:** live-тест молча гоняет старый код. Реальный случай 2026-08-03 —
фикс потери промпта (`js/_studio/_controls.js`) был сделан, тест на UI по-прежнему
показывал пустой промпт, и это выглядело как «фикс не помог». На самом деле сервер
отдавал вчерашний файл. Рестарт ComfyUI не помогает и не при чём: aiohttp отдаёт
статику с диска (`Cache-Control: no-store`), проблема была в содержимом файла.

**How to apply:**
- Перед **любым** live/Playwright-прогоном после правки фронтенда — синхронизировать
  изменённые файлы `js/`, `nodes/`, `locales/` в живую копию.
- Сравнивать по содержимому с нормализацией переводов строк: копия хранит CRLF, dev —
  LF, поэтому побайтовое сравнение объявляет расхождением все 70+ файлов. С
  нормализацией сразу видно единственный реально изменённый.
- Быстрая проверка, что сервер уже отдаёт новое:
  `http://127.0.0.1:8188/extensions/comfyui-timesaver/<путь>.js` и поиск своей строки.
- Рестарт сервера нужен только для Python-изменений (`nodes/`), для `js/` достаточно
  копирования и перезагрузки страницы.
- На момент исходного наблюдения `tools/`, `tests/`, `CLAUDE.md`, `project_memory/` были локальными ignored-областями. При консолидации документация и память перестали быть локальным источником; текущий состав проверяйте по Git. `tools/` и тестовые скрипты остаются локальной лабораторией.

Связано: [feedback_runtime_only_locations](../owner/feedback_runtime_only_locations.md), [feedback_commit_then_sync](../owner/feedback_commit_then_sync.md),
[feedback_single_comfyui_window](../owner/comfyui-windows.md).

**Проверка одной командой.** `python tools/verify_live_sync.py` сверяет оба пака
(timesaver и artius) на трёх уровнях: файлы на диске (с нормализацией CRLF),
что реально отдаёт HTTP-сервер, и что загружено в процессе Python
(`/object_info`). `--sync` доливает отставшее. Код возврата 0 = всё совпало.
Правки JS требуют только копирования и Ctrl+F5; правки Python — рестарта
ComfyUI.

## Синхронизатор возил только текст (2026-08-05)

`verify_live_sync.py` копировал файлы с расширениями `.js .py .json .css .md`.
Пока в паке не было картинок, это никого не жало. С обложками паков вылезло
худшее сочетание: живая копия рисовала шесть пустых рамок, а инструмент при
этом честно докладывал `disk: in sync`.

Добавлены `BINARY_SUFFIXES` (`.webp .png .jpg .jpeg .gif .svg .ico .woff2`), и
сравнение для них двоичное: `_text()` с нормализацией переводов строк объявлял
бы каждую обложку вечно отличающейся.

Урок общий: список расширений в синхронизаторе — это список того, что вообще
может доехать до ComfyUI. Добавляя в пак новый тип файла, надо проверить, что
он там есть, иначе «синхронизировано» будет означать «синхронизирован код, а
данные нет».


## Корневые `.py` тоже едут (2026-08-08)

Тот же капкан, второй раз и с другой стороны: синхронизатор обходил только
подпапки `js/`, `nodes/`, `locales/`, а **корневые** `__init__.py`,
`ts_dependency_manager.py`, `ts_pasted_media_fix.py` не возил вовсе. Новый
корневой модуль в живую копию не попал, при этом отчёт был `disk: in sync` —
то есть ComfyUI грузил бы СТАРУЮ точку входа, а инструмент это подтверждал.

`compare()` теперь начинается с `dev.glob("*.py")`. Проверять после добавления
любого файла В КОРЕНЬ пака: правило «синхронизировано ≠ синхронизировано всё»
работает и для расширений, и для мест.

## Консоль сервера читается по HTTP (2026-09-17)

Окно ComfyUI запускается свёрнутым, и его вывод никуда не пишется: `latest.log`
и `user/comfyui.log` к нему отношения не имеют. Но у сервера есть
**`GET /internal/logs/raw`** — тот же буфер консоли в JSON (`entries[].m`, с
ANSI-кодами, снимать `\x1b\[[0-9;]*m`).

Это единственный способ увидеть `logger.info` СВОЕЙ ноды на живом прогоне —
например, сколько времени она потратила и на что. Так был разобран вопрос
«почему DLSS идёт медленно»: в отдельном процессе нода вела себя иначе, чем
внутри сервера, и только её собственная строка в консоли показала, что пол —
это сама сеть (см. [reference_dlss_upscaler](reference_dlss_upscaler.md)).

## После релиза: живая копия, в которую копировали `--sync` (12.13.0, 15.10.2026)

`verify_live_sync.py --sync` оставляет в клоне D: правки и неотслеживаемые
файлы — `git pull` на таком дереве споткнётся. Порядок без потерь:
1. `git fetch`; `git diff --ignore-cr-at-eol --stat origin/master` — в списке
   только «удалённые» новые файлы (они есть, но неотслеживаемые) и то, что
   `--sync` не копирует (CHANGELOG, README, pyproject, tests/contracts);
   неотслеживаемые сверить с `git show origin/master:<f>` без `\r`.
2. `git stash push -u`, `git pull --ff-only`, `verify_live_sync.py` → 0
   расхождений, потом `git stash drop`. reset --hard не нужен.
