# Prompt Builder: текущая реализация и история

Нода собирает промпт из TXT-блоков; прежняя заметка о семантических паках описывает другую, отсутствующую в текущем коде реализацию.

## Сверено 2026-11-02

Источник — [nodes/text/ts_prompt_builder.py](../../nodes/text/ts_prompt_builder.py):

- Публичная нода `TS_PromptBuilder` находится в одном файле `nodes/text/ts_prompt_builder.py`.
- `ts_prompts_dir()` сначала выбирает папку `nodes/prompts`, если она существует; запасной вариант — папка `prompts` в корне пака.
- `ts_list_prompt_files()` использует `os.listdir`: только TXT-файлы непосредственно в выбранной папке, без обхода подпапок.
- `config_json` задаёт порядок и галочки блоков, а также блоки `{type:"custom", id, text, enabled}`. Парсер принимает список либо объект с `blocks` или `order`. Файловые настройки новых нод хранятся в `ts-prompt-builder-config.json` выбранной папки; свой текст там не хранится.
- `execute()` выбирает по одной непустой строке каждого включённого TXT, вставляет включённый свой текст на соответствующем месте и соединяет через `, `. Положительный seed детерминирован по имени файла (`blake2b`); 0 использует `SystemRandom` и меняет fingerprint каждого запуска.
- Свой текст работает и без TXT. Пустые/выключенные блоки пропускаются, пути файлов проверяются `ts_safe_join`.
- Выполнение workflow больше не перезаписывает общие настройки: явный конфиг объединяется с наличными файлами только в памяти. Сохранение файловых defaults остаётся за UI/config route; текст фильтруется и на backend. Причина — изоляция графов и отсутствие пользовательского текста в общем файле пака.

## Полноэкранный редактор — 2026-11-02

[Frontend](../../js/text/ts-prompt-builder.js) переносит тот же DOM-контейнер через
общий [openFullscreenOverlay](../../js/_fullscreen.js), возвращает его в оболочку
DOM widget без изменения node.size и закрывает при удалении ноды. Fullscreen —
адаптивная сетка плиток, компактная нода — список. Несколько блоков «Свой текст»
можно переставлять, включать, удалять; содержимое сохраняется в workflow.

[Чистый helper состояния](../../js/text/_prompt_builder_state.js) читает старый
формат файлов, хранит custom-блоки при обновлении списка, добавляет новые TXT в
сохранённом workflow выключенными. File/custom имеют раздельную идентичность.
Перетаскивание ограничено MIME и ID владельца; доступна клавиатура Alt+стрелки
на переключателе блока. Ручка — нефокусируемый draggable div: button забирал
фокус до dragstart, общий fullscreen парковал его обратно и отменял drag.
Сам fullscreen helper ради одной ноды не меняется.

Записи файловых defaults сериализованы и объединяются, а HTTP-ответ не
подменяет live state. Это предотвращает потерю текста/порядка от запоздавшего
ответа. Перезагрузка файлов имеет generation guard и читает config_json после
ответа, чтобы поздняя загрузка workflow имела приоритет. Ввод не пересоздаёт
textarea и не отнимает фокус. Новые inputs/outputs не добавлялись.

По прямой просьбе владельца актуализированы TXT из установленной сборки:
28 обновлённых файлов и новый `dance-eros.txt`, побайтовая копия. Конфигурация
установленной сборки не копировалась в исходники и не перезаписывалась обратно;
новый файл добавлен в исходные defaults выключенным. Прежние исходные TXT
сохранены в локальном игнорируемом архиве. Частные nsfw*-паки не включались.

Проверено локально: 25 CPU/контрактных тестов (включая прежние регрессии
Prompt Builder), два браузерных сценария classic/Vue на установленном паке.
В браузере проверены native drag-and-drop, Alt+стрелки, ввод/Ctrl+Z, выключение
своего блока, закрытие/возврат DOM и неизменность размера ноды, смена workflow,
восстановление текста/порядка, HTTP 503 при Reload без потери правок и удаление
ноды с открытым fullscreen. Все 29 файлов с одной текстовой плиткой поместились
в окне 1600×1000; при меньшем окне сетка адаптируется, длинный список прокручивается.
Два живых API-запуска подтвердили порядок текста, переносы строк, стабильный
выбор файла по seed и неизменность общего config на диске. Ruff/синтаксис JS
и Python прошли. Исходные CRLF TXT сохранены; whitespace проверяется с cr-at-eol.

Семантические роли, совместимость, профили и модуль `_scene` из старой заметки этим кодом не читаются. Не использовать их как текущую спецификацию и не восстанавливать автоматически: это изменило бы поведение ноды.
