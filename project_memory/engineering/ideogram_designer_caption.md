Ideogram Designer: история редактора промпта, координаты JSON, палитры и raw desc.

Исходники темы: [_caption_json.py](../../nodes/_caption_json.py).

**Граница записи:** ниже сохранены исходные наблюдения и причины решений. Замеры, версии окружения и слова «сейчас» относятся к дате соответствующего наблюдения; это не повторная проверка на новом окружении. Порядок чтения и ограничения: [инженерная память](README.md#как-читать-записи).

## Undo/redo + graph-ref cleanup (2026-07-03, после ревью)
- **Undo/redo в редакторе**: снапшот-история `work` (JSON-строки, лимит 100) — срез каждые 500ms тем же поллером, что JSON-панель (серии правок сливаются в шаг), undo/redo делают force-flush перед шагом (ничего не теряется). `pushHistory` скипает mid-gesture (activeDragCleanup/inlineEl); `applyHistorySnapshot` мутирует work in place (контракт loadDesignIntoEditor) + восстанавливает selectedId. Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y + кнопки ↶↷ в header (disabled на границах; кнопка может быть disabled до ближайшего тика при незафлашенных правках — жмётся хоткеем). **КРИТИЧНО: хоткеи работают только благодаря keyAnchor-паттерну** — [reference_modal_hotkeys](reference_modal_hotkeys.md) (Comfy иначе перехватывает Ctrl+Z в graph ChangeTracker и убивает модалку). E2e: `tests/test_ideogram_editor_e2e.py` (live, add→undo→redo→кнопки→disabled-статусы).
- **TTL-очистка graph-ref**: `cleanup_stale_graph_refs()` при `register_routes()` удаляет `ts_ideogram_ref_*.png` старше 7 дней из КОРНЯ input dir (строгий regex имени; живая нода пересоздаёт реф при прогоне). Юнит-тест в test_ideogram_caption.py.
- Smoke-фильтр: THREE.Object3D ошибки core Load3D (headless без WebGL, чужой autosave-workflow) добавлены в NOISE test_browser_smoke.

## Режим «Промпт» и выбор модели (05.10.2026)

Просьба владельца: «можно просто обычный промпт, а не только навороченный JSON; обработка — high-quality Qwen 4B; галочка 2B/4B как у TS Super Prompt».

- Переключатель **Дизайнер / Промпт** в тулбаре ноды (`NODE_MODES` в `_ideogram_node.js`). Текст пишется в textarea на ноде → существующий скрытый вход `auto_prompt` (новых скрытых виджетов нет). `mode="prompt"` → `execute` зовёт `caption_from_prompt()` (`_generate_with_qwen`, пресет «Ideogram Prompt Enhance», seed = `auto_seed`). Старый `mode="auto"` при открытии графа уходит в designer, как и раньше.
- **`bigger_model`** — ОБЫЧНЫЙ видимый Boolean-виджет, добавлен ПОСЛЕДНИМ входом, **умолчание True (4B)** (у Super Prompt — False). Управляет режимом «Промпт» и обеими кнопками редактора; в карточке «Авто-макет» редактора — зеркальная галочка (`wantsBiggerModel`/`BIGGER_MODEL_INPUT` в `_ideogram_shared.js`, пишет тот же виджет).
- ⚠️⚠️ **Корень «модель отвечает прозой»**: пользовательский ход Super Prompt («Target output: … one polished English prompt» + «Hard rules … Return only the final prompt») стоял ближе системного промпта и перебивал требование JSON — и кнопка «Авто» редактора, и новый режим получали абзац. Лечение: `JSON_PRESETS` + `target_for_preset → "json"` в `super_prompt/_helpers.py`, ветка `prompt_target == "json"` в `_build_messages` без прозаических правил.
- ⚠️ **Даже с JSON 4B ломает структуру** (замерено, 6/6 непарсимы): склеенные элементы с повторными ключами, лишние `}`, `"#7A9CB3]`, дети вложены под ключ `"text"` родителя, потеря уровня скобок, bbox 1050/1100, выдуманная надпись (копия «БАЙКАЛ» из примера пресета), обрезанная («КОФЕ И КНИГ»). Всё это чинит общий `nodes/_caption_json.py`: голова капшена — JSON с балансировкой, элементы — **последовательность полей** (`type→bbox→text→desc→palette`, возврат по порядку = новый элемент), осиротевший desc → к ближайшему объекту выше, дубли схлопываются, bbox клампится; без картинки текст сверяется с кавычками идеи (восстановить, выкинуть лишнее, пустой текст ← незанятая цитата, цитата из desc объекта → свой элемент на верхней части объекта, потерянная вторая строка → под первой). Подключён в движке для JSON-пресетов и в ноде. Тесты `tests/test_caption_json.py` — на реальных ответах.
- Пресет «Ideogram Prompt Enhance» дополнен: «ONE FLAT array … desc always a plain string» и «детальная идея: каждый названный объект/надпись — свой элемент (до ~12)».
- **Итог на живом сервере**: короткие идеи 15/15 FULL (4B и 2B); длинный промпт владельца («избушка», 3 надписи) 7/7 — валидный JSON, все надписи на месте, 4–10 элементов, 25–40 с. ⚠️ Слабое место 4B — сами координаты (путает лево/право); редактор даёт их поправить.
- **Сравнение с Ideogram-энкодером через core `TextGenerate`** (`ideogram\qwen3vl_8b_fp8_scaled`, тип `ideogram4`, тот же системный промпт и сэмплинг): 9/9 сырых ответов валидны, надписи на месте, но **60–205 с** на ответ (в 3–5 раз медленнее 4B), и модель та же, что уже стоит в Ideogram-графе текстовым энкодером (лишнего скачивания нет). Раскладка не лучше 4B по смыслу координат.

## Описание сцены (HLD) и правка слоёв (05.10.2026)

Жалоба: шаблон food_typography_ad / идея «Ягодный десерт», заголовок переписан на «Вкусняшка», плашка цены удалена — Ideogram всё равно нарисовал плашку «ДУУ-HOW» (= BUY-NOW кириллицей). Причина: `high_level_description` — это `brief.v` идеи, ставится один раз в `applyBrief` и дальше за слоями не следит; плюс в RU-дизайне блок получает `tx.ru`, а предложение цитирует `tx.en` ('SWEET').

- `localizeBriefHld(brief, lang)` (`_ideogram_shared.js`): в предложении идеи EN-литерал заменяется литералом языка дизайна; `applyBrief` пишет его + `work.hld_brief_v = brief.v`.
- `hldIsStale(design)`: предложение идеи (по `hld_brief_v` или совпадению текста — для старых дизайнов) устарело, если роли объекта/текста идеи нет, у объекта другой desc, у текста литерал не en/ru идеи, или текст стал visual_only. Своё (отредактированное) предложение не устаревает никогда.
- Флаг `hld_stale` пишется ТОЛЬКО когда true (иначе ключ удаляется) — в `pushHistory` ДО снимка (иначе лишний шаг undo — ловил e2e), в `refreshJson` и перед `onSave`; нода пересчитывает его в `_tsIdeoSync` (старые графы чинятся без открытия редактора).
- Python `build_caption`: `hld_stale is True` → `auto_high_level_description(elements, style)` — «A photograph of <голова desc каждого obj>, with the text “…”.»; называет только то, что на артборде.
- Подсказка `hld_stale_note` под «Главной идеей». Тесты: `tests/test_ideogram_scene_sentence.py` (Python + браузер).
- ⚠️ НЕ починено (контент шаблонов): `photo` стиля gourmet_food говорит «high-speed flash freezing the splashes» (брызги на картинке), фон пресета «clean light seamless studio backdrop» не совпадает с предложением идеи («blush-pink surface dusted with sugar»); две креманки — вероятно, широкий bbox продукта (0.66 ширины кадра 16:9).

## Порядок координат в пресете — «каша» на длинном промпте (07.10.2026)

Жалоба: длинный промпт «избушки» в режиме «Промпт» → слои наложены друг на друга, каша. Замер (стенд `layout_ab.py` в скретчпаде сессии: 5 seed'ов на вариант через живой сервер, проверки «пара справа, избушка слева, город на горизонте, колодец справа, табличка на паре, вывеска на избушке»):
- пресет с y-первым bbox (схема Ideogram) — **14/44**; те же слова + правила расстановки, всё ещё y-первым — **12/44**;
- родной порядок grounding Qwen-VL `[x0,y0,x1,y1]` + правила — **30/43**. ⚠️ Qwen обучен на x-первом; попросишь y-первый — пишет x-первый всё равно, и Ideogram рисует сцену отражённой по диагонали.
- Решение: пресет «Ideogram Prompt Enhance» просит x-первый (примеры тоже переведены), а `XYXY_PRESETS` в `nodes/_caption_json.py` + `repair_caption_text(..., xyxy=True)` переворачивают ОДИН раз. Зовут: движок Super Prompt (`_qwen.py`), TS Qwen 3 (раньше отдавал ответ пресета сырым), обе RT-ноды через `super_prompt_rt/_helpers.finish_answer`. ⚠️ Повторный `repair` уже починенного капшена — без флага, иначе зеркалит обратно (ремень в `caption_from_prompt` так и зовёт).
- Gemma E4B на этом промпте раскладывает плохо при ЛЮБОМ порядке (3–4/24 против 1/22 — шум); перевод у неё ради единства смысла пресета.
- Попутно в починке: повтор объекта (тот же bbox или без bbox, начало desc похоже ≥0.6) схлопывается; потерянная строка надписи встаёт под предыдущую ТОЛЬКО если между ними в промпте нет конца предложения (табличка уезжала под вывеску «Timesaver»); надпись без bbox, чьи слова названы в desc объекта, садится на этот объект; восстановленная строка не наследует «large» и не удваивает хвост.
- НЕ сделано: «Json Image Capture» (с картинкой) всё ещё y-первый — не мерили; голубь стабильно склеивается с городом.

## Чужие акценты палитры и правка промпта в панели (14.10.2026)

Жалоба: шаблон material_typography / «Ледяные буквы» (ХОЛОД) → на картинке
лишняя розовая надпись «РО». Промпт, присланный владельцем, был чистым (две
надписи), но палитра стиля `studio_3d_render` несёт неоновый `#FF2E97` (для
контрового света). ⚠️ **Ideogram пытается поставить в кадр КАЖДЫЙ цвет палитры.**
A/B на живом Ideogram 4 (граф `timesaver/Image Gen Ideogram.json`, Turbo,
1024², 2 сида): с розовым — розовая первая буква «В» и розовая искра в углу; без
него — чисто. «РО» у владельца — тот же механизм на другом сиде.
- `harmonizeStylePalette(palette, ideaColors)` в `_ideogram_shared.js`:
  насыщенные цвета стиля дальше 60° по оттенку от ВСЕХ собственных цветов идеи
  отбрасываются; нейтральные остаются всегда; нет своих цветов → палитра целиком.
- Зовётся в `applyBrief`. ⚠️ Якоря — ТОЛЬКО цвета надписей идеи (`brief.texts[].color`)
  и палитры объектов, НЕ фон: с фоном менялось 70/180 идей и неверно (у «Mango
  Season» уходил оранжевый, у «Hot Sauce» красный). Без фона — 6/180, все в
  material_typography, все верно (лёд −розовый, огонь −бирюзовый, вода −золото,
  мех −голубой, неон −голубой/жёлтый, фрукты −зелёный).
- «Ледяные буквы»: настроение `tech` → `cinematic`.
- ⚠️ Риск остаётся у идей БЕЗ своих цветов, чей стиль несёт контрастные акценты
  (напр. «Liquid-Glass Ballerina» тоже на studio_3d_render) — не мерили рендером.

**Панель JSON-промпта — двусторонняя.** «Изменить» (или щелчок по тексту) →
textarea; ввод/вставка → через 400 мс `parseCaptionObject` + `captionToDesign`
→ `loadDesignIntoEditor(design, {keepInspector:true})` (инспектор НЕ
перерисовывается, иначе каретка теряется); статус «обновлено / пока не JSON».
«Готово» → `renderInspector` + серверный промпт. Ctrl+V с JSON, когда фокус не
в поле, раскладывает сразу (`onPaste`).
- ⚠️ **`raw_desc`** у текстового блока: `captionToDesign` кладёт desc надписи
  ДОСЛОВНО (+ `raw_palette`), `compose_text_desc` (Py и JS) отдаёт его как есть.
  Раньше desc шёл в `desc_override`, и сборщик обкладывал его шрифтом, весом,
  размером, цветом и обводкой — вставил промпт, получил другой. Правка самого
  текста описания в поле «Стиль текста» оставляет raw; любой другой контроль
  надписи (шрифт, вес, регистр, цвет, обводка, плашка, добавка) → `leaveRaw`:
  текст переезжает в `font_desc`, описание снова собирается.
- `captionToDesign` теперь сбрасывает `style.preset_id` (у вставленного свой стиль).
