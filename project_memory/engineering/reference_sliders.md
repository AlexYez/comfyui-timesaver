TS Int/Float Slider — рабочий диапазон в node.properties, жёсткие границы в схеме, миграция старых ±1e9 и ловушка порядка загрузки

Исходники темы: [_slider_helpers.js](../../js/utils/sliders/_slider_helpers.js).

**Граница записи:** ниже сохранены исходные наблюдения и причины решений. Замеры, версии окружения и слова «сейчас» относятся к дате соответствующего наблюдения; это не повторная проверка на новом окружении. Порядок чтения и ограничения: [инженерная память](README.md#как-читать-записи).

Код: `js/utils/sliders/_slider_helpers.js` (общий), `nodes/utils/ts_{int,float}_slider.py`.
Тесты: `tests/test_slider_ranges.py` (Node + браузер в обоих режимах).

- **Две пары границ.** Схема на Python — ЖЁСТКИЕ пределы (Float 0…10000,
  Int 0…100000), они же `TS_SLIDER_SPECS.limits` в JS; тест стережёт, что
  совпадают. Рабочий диапазон ползунка живёт в `node.properties`
  (min/max/step/default, их правит владелец в панели свойств).
- До 12.12.4 новая нода копировала в properties границы схемы (±1e9, ±2³¹) —
  панель показывала миллиарды. Теперь новая нода стартует с `range`
  (Float 0…10, Int 0…2048). Старые точные ±1e9/±2³¹ заменяются при открытии,
  диапазон расширяется до текущего значения.
- ⚠️ **Порядок загрузки.** При `configure` свойства приходят ПО ОДНОМУ и каждое
  дёргает `onPropertyChanged` ДО того, как виджет получил сохранённое значение.
  Синк в этот момент судит по значению по умолчанию и переписывает диапазон
  (Float ±1e9 со значением 24 терял 24). Лечение: в `onConfigure` заново взять
  min/max/step/default из `info.properties`.
- Не трогать: значение вне сетки шага, привязанной к default, при загрузке
  сдвигается — так было и до правки (Video Gen Pro LTX: 704 → 960 при 320…1088
  шаг 128, default 768). Отдельная история, не путать с миграцией.

Владелец пользуется слайдерами для шагов, fps, мегапикселей, разрешения —
отрицательные не нужны (его просьба 03.10.2026). Смежное: [reference_dom_widget_pitfalls](reference_dom_widget_pitfalls.md).
