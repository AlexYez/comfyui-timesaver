Вход `prompt` у TS Super Prompt и RT — отдельное гнездо (не поле-виджет), приоритет над полем, стандартная нода улучшает провод при запуске, результат показывается в панели, НЕ в поле (кэш)

Исходники темы: [_prompt_wire.py](../../nodes/llm/_prompt_wire.py), [_prompt_wire.js](../../js/llm/_prompt_wire.js).

**Граница записи:** ниже сохранены исходные наблюдения и причины решений. Замеры, версии окружения и слова «сейчас» относятся к дате соответствующего наблюдения; это не повторная проверка на новом окружении. Порядок чтения и ограничения: [инженерная память](README.md#как-читать-записи).

# Промпт с провода у TS Super Prompt / RT (27.09.2026)

Просьба владельца: в обе ноды должна подключаться строка с другой ноды, с
приоритетом над полем.

## Почему отдельное гнездо, а не поле-виджет

Редактор ноды ПРЯЧЕТ виджет `text` через `hideWidget` — вместе с его гнездом
(иначе в Nodes 2.0 ломается раскладка). Подключённое поле показывало бы в
редакторе текст, который запуск уже не читает, а диктовка писала бы туда же.
Поэтому — `IO.String.Input("prompt", force_input=True, optional=True)`,
ПОСЛЕДНИМ (после `images` / `audio`): гнёзда сохранённых графов не
перенумеровываются, в позиционный `widgets_values` ничего не встаёт.

## Правило (одно на обе ноды — `nodes/llm/_prompt_wire.py`)

* провод принёс непустой текст — работает он; пусто/нет провода — поле;
* ⚠️ текст с провода по умолчанию уходит КАК ЕСТЬ. Улучшение — переключатель
  `enhance_prompt` (Boolean, default False, последним — виджет). Владелец
  попросил отдельно: подключение провода само по себе модель не запускает.
  Переключатель показан в панели над полем (штатный виджет скрыт `hideWidget`),
  панель получает get/set функциями — `_dom_widget.js` тянет `app`, и модуль
  перестал бы проверяться Node;
* **стандартная нода**: без провода по-прежнему ПЕРЕДАЁТ поле (улучшает
  кнопка, `SUPER_PROMPT_ENHANCE_ON_EXECUTE = False`); провод + галочка —
  улучшение при запуске (кнопке текст с провода недоступен);
* **RT**: поле при запуске улучшается как раньше, галочка касается только
  провода; при `prompt` + `audio` расшифровка дописывается ПОСЛЕ текста с
  провода; без улучшения модель, поднятая ради расшифровки, выгружается
  (если не `keep_loaded`).

## ⚠️ Результат — в панель, НЕ в поле

Нода отдаёт `ui={"ts_super_prompt_result": [text]}` только при подключённом
проводе; `js/llm/_prompt_wire.js` показывает его под строкой «Промпт приходит
со входа» с кнопкой «Копировать». Запись в виджет `text` изменила бы входы ноды
→ ComfyUI при следующем запуске пересчитал бы всё ниже, включая сэмплер.

Обработчики `onConnectionsChange`/`onExecuted` ставятся на ноду ОДИН раз
(`__tsPromptWireHooked`) и ищут текущую панель через `node.__tsPromptWire` —
интерфейс ноды пересобирается при смене вкладки, обёртки не должны копиться.

Тесты: `tests/test_prompt_wire.py`, хвосты `test_super_prompt_contract.py` и
`test_super_prompt_rt.py`.
