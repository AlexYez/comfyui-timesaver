Исходники темы: [ts_lora_loader.py](../../nodes/utils/ts_lora_loader.py), [_lora_stack.js](../../js/utils/_lora_stack.js), [ts-lora-loader.js](../../js/utils/ts-lora-loader.js).

**Граница записи:** ниже сохранены исходные наблюдения и причины решений. Замеры, версии окружения и слова «сейчас» относятся к дате соответствующего наблюдения; это не повторная проверка на новом окружении. Порядок чтения и ограничения: [инженерная память](README.md#как-читать-записи).

# TS LoRA Loader (v10.1+, `nodes/utils/ts_lora_loader.py`)

Стопка модельных LoRA в одной ноде. Файлы:

- `nodes/utils/ts_lora_loader.py` — нода; `parse_stack`, `known_loras`.
- `js/utils/_lora_stack.js` — список и правила БЕЗ DOM (проверяется без браузера).
- `js/utils/ts-lora-loader.js` — интерфейс (`ts.loraLoader`).
- `tests/test_lora_stack.py` (модель), `tests/test_lora_loader_node.py` (подграф),
  `tests/test_lora_loader_ui.py` (браузер, Nodes 1.0 и 2.0).

## Нода сама LoRA НЕ грузит

`enable_expand=True` + `GraphBuilder` → цепочка родных `LoraLoaderModelOnly`.
Ради двух вещей: поведение один в один как у ручной цепочки, и кэш ComfyUI
считает каждое звено отдельно (правка последней силы не пересчитывает
предыдущие). LoRA, которой нет в папке, пропускается по одной, прогон не
валится — workflow часто приходят с чужой машины. Нулевая сила = файл не
читается вовсе.

## Хранение — одна строка JSON

`loras_json` (скрытый виджет) + зеркало в `node.properties`. Причина —
[reference_widgets_values_positional](reference_widgets_values_positional.md): `widgets_values` позиционный, и виджеты,
приходящие вместе со строками списка, сдвигали бы значения соседей.
Регидратация — в `loadedGraphNode` через `node._tsLoraRehydrate`, без пересборки
DOM-виджета ([reference_dom_widget_rehydrate](reference_dom_widget_rehydrate.md)).

## ⚠️ `preventDefault` в `pointerdown` отбирает у поля фокус

Числовое поле, которое можно «тянуть» вбок, обязано гасить нажатие — иначе
холст начинает тащить ноду. Но вместе с нажатием пропадает и фокус: щёлкнуть и
напечатать значение становится НЕЛЬЗЯ, хотя подсказка это обещает. Playwright
этого не ловит сам по себе — `page.fill()` наводит фокус программно и идёт мимо
той дороги, по которой ходит человек.

Лечение — порог: жест и щелчок различаются по сдвигу указателя.

```javascript
input.addEventListener("pointermove", (event) => {
    if (!dragging) return;
    const shift = event.clientX - startX;
    if (!moved && Math.abs(shift) < 3) return;   // ещё не жест
    moved = true;
    /* ... крутим значение ... */
});
const stop = (event) => {
    dragging = false;
    input.releasePointerCapture?.(event.pointerId);
    if (!moved) { input.focus(); input.select(); return; }  // это был щелчок
    render();   // ⚠️ при щелчке перерисовка ЗАПРЕЩЕНА: она заменит поле
};
```

Тест — `test_the_strength_can_be_typed_after_a_plain_click`: настоящий
`locator.click()`, потом `keyboard.type`. Правило шире одной ноды: любое поле со
скрабом проверять НАСТОЯЩИМ щелчком, а не `fill`.

## ⚠️ Выпадающий список — только в корне документа

Жалоба: «в выпадающем списке вообще ничего не видно». Данные были ни при чём —
сервер отдавал 170 имён. Сложились ТРИ причины, и каждая по отдельности давала
пустоту:

1. **Внутри ноды места нет.** Нода по умолчанию выходит ~300×146. `defaultHeight`
   у `addResizableDomWidget` тут не спасает: он применяется только вместо
   ОТСУТСТВУЮЩЕГО размера, а LiteGraph свой уже проставил — дальше работает
   только `minHeight`. Списку находок оставалось 20 пикселей.
2. **`element.hidden` не работает против своего `display`.** Правило
   `.ts-lora__list{display:flex}` перебивает браузерное `[hidden]{display:none}`
   — список не прятался и делил высоту с поиском. Любое своё `display` обязано
   иметь пару `[selector][hidden]{display:none}`.
3. **Колонка-флекс сжимает детей.** 170 кнопок в `flex-direction:column`
   ужимались до 8 px каждая. Строкам нужен `flex:0 0 auto`.

Решение — панель в `document.body` (`position:fixed`, свой z-index), позиция
считается от кнопки, раскрытие вверх, если снизу тесно. Внутри виджета
absolute-панель не годится: она вылезает за его прямоугольник, и по кнопкам не
попасть — сверху холст графа («canvas intercepts pointer events» в Playwright).

Плата за корень документа — **уборка обязательна**: `node.onRemoved` снимает
элемент и слушатели (`pointerdown` в фазе перехвата, `wheel`, `resize`), иначе
панель остаётся висеть после удаления ноды. Гард —
`test_the_picker_is_actually_visible_in_a_node_of_default_size`, и он НЕ задаёт
размер ноды: прежние тесты ставили 340×280, места хватало, и ошибка проходила
мимо. Правило шире одной ноды: интерфейс проверять на ноде такого размера, какой
её видит человек, вытащивший её из меню.

## Замена щелчком по имени и колёсико (03.10.2026)

Просьба владельца — «как у родной Load LoRA»: щелчок по имени строки открывает
тот же список в режиме замены (`replaceIndex`, якорь — имя строки), весь, без
обрезки до 200, текущая подсвечена `is-active` и прокручена в центр. Выбор —
`setName` из `_lora_stack.js`: сила, `on`, `unmerged` остаются. Раньше щелчок
по имени ВЫКЛЮЧАЛ строку — это снято, выключатель есть отдельно.

⚠️ Колёсико: слушатель `wheel` на окне (закрыть список, когда холст уезжает)
обязан пропускать события, чья цель внутри списка, — иначе список закрывался
от первой же попытки его прокрутить. Холст колёсико над списком не получает:
список в корне документа. Тест — `test_a_chosen_lora_can_be_replaced_and_the_list_scrolls`.

⚠️ Шум в браузерных тестах: `Unknown message type tsab:health` — пак Artius
Browser шлёт `tsab:*` всем вкладкам, а слушает их только открытая панель.
`test_the_stack_is_built_reordered_and_survives_a_reload` от этого плавает
(то 1.0, то 2.0). К этой ноде отношения не имеет.
