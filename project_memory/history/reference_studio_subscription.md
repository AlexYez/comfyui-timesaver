История: Подписка TS Image Studio — пропуск, наборы, два репозитория, где что лежит и что можно сломать

TS Image Studio снята из текущего пака. Код до удаления доступен в [истории Git](https://github.com/AlexYez/comfyui-timesaver/tree/c1668b3cfa2161e36bf9b9fa91288b949b4b0b1f/nodes/image/studio); удаление зафиксировано [коммитом a2251b1](https://github.com/AlexYez/comfyui-timesaver/commit/a2251b1). Записанное решение владельца датировано 2026-09-27, коммит — 2026-09-28: это разные события.

**Историческая запись, не описание текущей реализации и не действующее разрешение.** Даты и результаты ниже относятся к указанным сессиям. Пути `tests/`, `tools/`, `dist/` и `archive/` с артефактами — локальная лаборатория; они не гарантированы в чистом клоне.

Студия бесплатна; платными бывают **наборы** — архивы граф-файлов, которые
доезжают отдельно. Полное описание — `nodes/image/studio/ARCHITECTURE.md` §9;
здесь то, что нужно знать до того, как открывать код.

## Ключевое, что легко понять неправильно

**Пропуск не изобретался заново.** Механизм уже носит ComfyUI-лаунчер
(`comfyui-launcher/tools/license-tool` + `src/license.js`). `nodes/_pass.py` —
его Python-двойник: тот же публичный ключ Ed25519, тот же формат токена, те
же коды месяца. Не строй второй механизм и не меняй формат — сломаешь ключи,
которые уже у людей. Лаунчер читать **только на чтение**.

**Заперто отсутствующее, а не платное.** Установленный набор работает всегда,
включая после конца подписки. В списке моделей серым показано то, чего на
машине нет («в наборе»), и клик открывает витрину. Замка на установленном
быть не должно — если он появился, это регресс.

**Секреты уровней меняются каждый месяц.** Платный набор пересобирается и
перезаливается вместе с выпуском ключей. `--license-tool` берёт тот выпуск,
который уже на руках у подписчиков (месяц ≤ текущего), а не самый новый на
диске — ключи выпускаются с запасом вперёд, и публикация под будущим
секретом отрезала бы всех текущих.

## Репозитории

| Что | Где |
|---|---|
| Исходники платных семейств + `packs.json` + медиа | `AlexYez/comfyui-timesaver-studio` (приватный) |
| Каталог, обложки, зашифрованные наборы | `AlexYez/ts-studio-packs` (публичный) |
| Сборщик и генератор обложек | `tools/studio_pack.py`, `tools/studio_media.py` |

Локальные клоны — соседи пака: `../comfyui-timesaver-studio`.

## Почему архивы зашифрованы

Схема лаунчера прячет платное за неугадываемой папкой `paid/<секрет>/`. На
файловом хостинге без листинга этого хватает, **в git-репозитории — нет**:
дерево видно целиком, и секрет уровня был бы напечатан рядом с файлом,
который он защищает. Поэтому для публичного репозитория набор шифруется
AES-GCM ключом `sha256("ts-studio-pack:" + секрет уровня)`, а адрес публичный.
Обе схемы живы: выбор делает флаг `--encrypt` при сборке.

## Админка — в лаунчере, а не здесь

Наборами управляет вкладка «Студия» в `comfyui-launcher/tools/workflow-admin/`
(добавлена 2026-08-03 из этой сессии, с разрешения владельца). Причина: у
платных workflow лаунчера и у студии один подписчик, один код месяца, одни
секреты и один хостинг — две админки означали бы две одинаковые кнопки.

Формат набора остаётся здесь: вкладка запускает `tools/studio_pack.py`, а не
повторяет его. Если будешь править сборку — правь Python, интерфейс подхватит.
Заметка на стороне лаунчера: `comfyui-launcher/project_memory/reference_studio_tab.md`.

Публикация общая: собранные наборы попадают в `publish/studio/` лаунчера и
уезжают вместе с workflow и ключами. Поэтому каталог читается сначала с
хостинга и только потом с GitHub-зеркала.

## Сборка и публикация

```bash
cd ../comfyui-timesaver-studio
python ../comfyui-timesaver/tools/studio_pack.py build \
    --catalog packs.json --source families \
    --license-tool ../comfyui-launcher/tools/license-tool \
    --out ../comfyui-timesaver/dist/studio --encrypt \
    --base-url "https://raw.githubusercontent.com/AlexYez/ts-studio-packs/main"
```

Дальше содержимое `dist/studio/` копируется в клон `ts-studio-packs` и
пушится. `dist/` в паке — gitignored.

Перевод модели между категориями — `studio_pack.py tier <family> <0|2|3>`:
тир прописан в манифесте самого графа, отдельной таблицы прав нет.

## Режим тестирования

Включается файлом `user/default/ts-studio/dev.json`; без него ни панели в
настройках, ни POST-роута у пользователя нет. Меняет ровно две вещи: откуда
читается каталог (можно `file:///…/dist/studio`) и каким показывается ключ
(`off | none | expired`). Правила не смягчает — в подменённом состоянии нет
секретов, поэтому платный набор при `simulate: none` действительно не
скачивается.

```bash
python tools/studio_pack.py dev --status     # что сейчас на машине
python tools/studio_pack.py dev --dist dist/studio
python tools/studio_pack.py dev --simulate none
python tools/studio_pack.py dev --off
```

Рабочий лист для совместного тестирования — `doc/TESTING_STUDIO.md`.

## Грабли, на которые уже наступили

- **Корень ComfyUI — `D:\AiApps\ComfyUI\comfyui\ComfyUI`**, а не
  `…\comfyui`. Установка набора в `--comfy …\comfyui` создаёт мёртвое дерево,
  которого сервер не видит: `/api/userdata?dir=ts-studio%2Fworkflows` вернёт
  `[]`. См. [reference_live_copy_sync](../engineering/reference_live_copy_sync.md).
- **`pack.json` рядом с графами** — штамп установки, не бэкенд. Загрузчик
  бэкендов его пропускает явно; без этого он читался бы как сломанный граф.
- **`verify_live_sync.py` теперь удаляет лишнее.** До этого удалённый в
  dev-дереве файл продолжал жить в установке, и живой тест спокойно гонял код,
  которого больше нет. Именно так и вышло, когда krea2/ideogram уехали в набор.
- **Кнопка Run в тестах — только внутри студии** (`.ts-istudio__runwrap button`).
  Поиск `button` с текстом «Run» по всей странице попадает в кнопку самого
  ComfyUI и ставит в очередь граф с холста пользователя: я так дважды запустил
  чужой workflow и минут двадцать разбирал его ошибку как свою. Селекторы
  модели и промпта тоже скоупить: `.ts-studio select`, `.ts-studio textarea`.
- Медиа в каталоге должны быть **полными URL**: витрина вешает их на `<img>`,
  и относительный путь разрешился бы относительно ComfyUI. Абсолютизацию
  делает сборщик.

## Что проверено вживую

Полный путь на чистой машине: моделей нет → серые «в наборе» → клик →
витрина → «Получить доступ» → токен → «Установить» → скачивание с GitHub,
расшифровка, распаковка → модели стали настоящими. «Забыть» в настройках
возвращает состояние без ключа, не трогая установленное; «Удалить» набор
возвращает модели в серые.

Обе платные модели из набора реально считают, а не только ставятся:
Krea 2 t2i (1008², `images/krea2/`), Krea 2 upscale (1008² → 2016², тайловый),
Ideogram t2i (1344×736, `images/ideogram/`). У всех в PNG лежит снимок
`ts_studio` с бэкендом из набора — восстановление сессии работает.

Режим тестирования: без файла-маркера в настройках только две строки; с ним
появляются переключатели, ключ показывается отсутствующим при живом настоящем,
каталог читается из `file:///…/dist/studio`, «Как есть» возвращает настоящий
ключ, «Выйти» убирает файл.

## Цикл автора, проверенный настоящими файлами (2026-08-04)

Прогон на выпуске 2027-01 (сделан во временной папке и удалён после проверки):

1. `node issue.js 2027-01` — три ключа (BAS/PRO/ULT), `keys/*.txt`,
   `posts.txt`, `secrets.json` с секретами трёх уровней.
2. Каждый токен проходит `_pass.verify_token` в паке: тир, `notAfter`
   (2027-04-01, потолок «выпуск + полгода»), секрет уровня внутри. Токен с
   подменённой подписью отвергается.
3. Сборка **без** `--encrypt` кладёт набор в `paid/<32 hex>/image/…zip` —
   неугадываемая папка для файлового хостинга.
4. Сборка **с** `--encrypt` даёт `paid/image/…zip.enc`: магия `TSPK1`,
   читаемого JSON внутри нет; в каталоге у записи `enc: true`.
5. Расшифровка: секретом СВОЕГО тира открывается в настоящий zip (`PK`),
   секретом чужого тира — `ValueError`, обрезанный на байт файл — `ValueError`.
6. Каталог называется `index.json` (не `catalog.json`) и лежит в корне сборки;
   пачки внутри `products.<продукт>.packs[]`.

Ключ выпускается на месяц, но живёт до `notAfter`; секреты уровней из
`secrets.json` — то же, чем шифруются наборы, поэтому один выпуск связывает
подписку и доставку.

[reference_comfyui_python](../engineering/reference_comfyui_python.md).

## Пак = модельная линия, а не пачка (2026-08-05)

Раньше набор был пачкой семейств (`image/pro-2026-08` = krea2 + ideogram).
Владелец развернул это по моделям: человек выбирает модель, а не набор
неизвестного состава.

| Уровень | Паки |
|---|---|
| Free (0) | `image/z-image`, `image/seedvr2` |
| Pro (2) | `image/flux2-klein`, `image/qwen-image` (+ qwen-image-edit) |
| Ultimate (3) | `image/krea2`, `image/ideogram` |

Pro — это уровень, который идёт с лаунчером (стандартная подписка Boosty).
Лесенка та же, что в `_pass.py`; старший уровень открывает младшие.

**Два каталога, и это не дублирование.** `js/image/studio/packs/catalog.json`
едет в сборке и описывает, ЧТО такое пак (имя, текст, обложка, уровень,
состав). Удалённый `index.json` описывает ДОСТАВКУ (версия, файл, шифрование).
Сливает `merge_catalogs` по id, презентация сборки побеждает: она переведена,
соответствует реально отгруженным графам и работает офлайн.

**Тир живёт в манифесте графа** и гейтит только доставку — каталог его лишь
показывает. Разойдясь, они дали бы пак, который в менеджере Ultimate, а
качается как бесплатный; за этим следит
`tests/test_studio_pack_manager.py::test_graph_manifests_and_the_catalogue_agree_on_tiers`.

## Спрятать пак можно двумя способами — и это разные вещи

`nodes/_studio_pack_state.py`:

- **выключен человеком** — `user/default/ts-studio/packs-state.json`. Ничего не
  удаляется, возврат в один клик. Модели удалять — отдельная история, позже.
- **выше потолка уровня** — `viewTier` в `dev.json`, только режим тестирования.

Ответ — причина (`"off" | "tier" | ""`), а не булево: одна причина предлагает
переключатель, другая — сам пак. На фронтенде то же делает `applyPackState()`
в `_backends.js`, и скрытое семейство остаётся в списке серым: иначе выключение
читалось бы как пропажа модели.

**Потолок прячет и никогда не открывает.** Платный пак по-прежнему качается
только с настоящим ключом — иначе режим тестирования доказывал бы не то
поведение, которое едет пользователю.

## Зачем понадобился потолок

Вся сборка сейчас едет одним куском (все шесть паков внутри), и автор видит то,
чего не видит ни один пользователь. Без потолка тестируется экран паков, а сама
студия — нет: бесплатный пользователь должен найти в списке три модели, а не
шесть.

```bash
python tools/studio_mode.py --status
python tools/studio_mode.py --as free|pro|ultimate|author
python tools/studio_mode.py --disable image/krea2
python tools/studio_mode.py --off     # выключенные паки НЕ трогает
```

То же мышкой: «Настройки» → «Тестирование» → «Показывать студию как».

## Обложки — настоящие кадры

Каждая посчитана тем семейством, которое рекламирует, в самой студии, на
нейтральном промпте; `tools/studio_covers.py` приводит кадр к 4:3 webp 640×480.
У SeedVR2 пара «до/после» из одного и того же куска кадра — один кадр про
восстановление не говорит ничего. Ideogram считает на платном API, поэтому его
обложка взята из готовых работ владельца (`output/images/ideogram/`), а не
посчитана заново: тратить чужие кредиты на обложку — не то решение, которое
принимают молча.

## Экран паков не должен ждать сеть

`/api/ts_studio/packs` идёт к хосту: два адреса, у каждого свой таймаут. Пока
менеджер читал только его, экран стоял пустым, а первая живая проверка вообще
насчитала ноль карточек — я успел решить, что сломан рендер.

Теперь два чтения, и порядок здесь — поведение, а не оптимизация:

1. `/api/ts_studio/packs/state` — только эта машина, без сети. Отдаёт полный
   каталог сборки, уже склеенный с пропуском и состоянием. Карточки видны
   сразу.
2. `/api/ts_studio/packs` — доставка (версии, архивы). Пришла — перерисовали.

Упавшее второе чтение не затирает первое: у пака остаётся имя, текст и
обложка, добавляется только пометка «каталог недоступен».

## Семейства в каталогах записаны ДВУМЯ способами

Каталог сборки перечисляет их строками (`"krea2"`), собранный каталог доставки
— описаниями (`{"family": "krea2", "label": …, "modes": […]}`). Код, знающий
одну форму, тихо не находит ничего: именно так устаревший `image/pro-2026-08`
(krea2 + ideogram одной пачкой) остался висеть в менеджере после разделения
паков по моделям — фильтр сравнивал строки со словарями. Разбирает обе формы
`_family_names()` в `_studio_packs.py`.

Правило: пак из удалённого каталога, все семейства которого уже едут в сборке,
не показывается. Он ничего не добавляет, а карточка «не установлен» рядом с
теми же моделями сбивает с толку.
