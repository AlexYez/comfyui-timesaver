# Два источника бэкендов — и молчаливое перекрытие

`loadBackends` (`js/_studio/_backends.js`) собирает бэкенды из **двух** мест:

1. **Встроенные** — `js/image/studio/workflows/` пака, по `index.json`.
2. **Пользовательские** — `user/default/ts-studio/workflows/**` в ComfyUI,
   листинг через `/userdata?dir=ts-studio%2Fworkflows&recurse=true`.

Пользовательский файл с тем же `manifest.id` **побеждает** встроенный. Это не
баг, а механизм доставки платных наборов: установленный набор кладёт свои графы
туда и подменяет ими встроенные.

## Ловушка

Перекрытие **молчаливое**. 2026-08-04 это выглядело так: правки графов krea2 и
ideogram делались в `comfyui-timesaver-studio/families/`, `verify_live_sync.py`
рапортовал «in sync», страница перезагружалась — а работал всё это время старый
граф из установленного набора `image-pro-2026-08`. Час замеров качества ушёл в
разброс сидов; ничто на это не указывало. Обнаружилось только когда правка
`p_context` не появилась в панели.

Признаки, по которым узнать:

* правка значения в графе не меняет ничего в поведении;
* результаты «прыгают» от прогона к прогону без связи с правками;
* в панели показано старое умолчание контрола.

## Что теперь стережёт

`tools/verify_live_sync.py` → `shadowing_packs()`: сверяет `manifest.id` каждого
файла в `user/default/ts-studio/workflows/**` с встроенными и печатает
`перекрытие <id>: установленный … ОТЛИЧАЕТСЯ — работает установленный`, а также
поднимает код возврата. Запускать **до** любого живого замера.

## Как отключить набор

Переименование папки не помогает — листинг рекурсивный, `*.disabled` внутри
`workflows/` всё равно подхватится. Набор нужно **вынести из-под `workflows/`**:

```
user/default/ts-studio/workflows/image-pro-2026-08
   → user/default/ts-studio/packs-disabled/image-pro-2026-08
```

## Состояние на 2026-08-04

По решению владельца («пока всё не доведём до ума — всё синхронизируем, платное
будет позже») семейства `krea2` и `ideogram` **возвращены в бесплатную сборку**:
их каталоги перенесены в `js/image/studio/workflows/`, `tier` в манифестах = 0,
`index.json` содержит 18 бэкендов. Установленный набор вынесен в
`packs-disabled`. В `comfyui-timesaver-studio/packs.json` оставлена заметка
`_note`; каталоги `families/krea2` и `families/ideogram` там удалены и при
возврате платного разделения восстанавливаются из истории git.

## Перекрытие теперь слышно (2026-08-05)

`js/_studio/_backends.js` при склейке источников пишет в консоль
`[TS Studio] installed pack '…' overrides the built-in '…'` и ставит на запись
`shadows`. Раньше замена шла молча — правки в графе не действовали, и понять,
почему, можно было только через `verify_live_sync.py`.

Сравнивать версии пока нечем: в манифестах встроенных графов нет поля
`version` (есть только `id`, `family`, `family_label`, `mode`, `tier`). Пока
его нет, правило остаётся прежним — установленный набор побеждает встроенный,
независимо от того, какой из них новее. Отсюда прямое следствие для
разработки: **установка набора во время работы над графами откатывает студию
на опубликованную версию.** Чтобы вернуться к своим графам, набор нужно снять
(кнопка Remove в витрине) или вынести папку из-под
`user/default/ts-studio/workflows/`.

## Второй вкус той же ловушки: кэш браузера (2026-08-08)

Правки в манифестах доехали до живой установки, сервер отдавал новые файлы
(проверено `curl` — в ответе новый список пропорций), `verify_live_sync`
докладывал `in sync` и перекрытий не находил, — а в студии правок не было.

Причина: ComfyUI отдаёт `/extensions/**` с `ETag` и `Last-Modified`, но **без
`Cache-Control`**. По эвристике свежести браузер вправе взять свою копию, вообще
не спрашивая сервер. Перезагрузка ГРАФА тут не помогает вовсе (это не
перезагрузка страницы), а обычная перезагрузка страницы — не всегда.

Починено в `js/_studio/_backends.js`: `fetchJson` просит `cache: "no-cache"` —
это «спроси с ETag», а не «не кэшируй»: неизменённый файл приходит как 304.
⚠️ Оба поставщика в `_app.js` обязаны ПРОБРАСЫВАТЬ опции
(`(url, options) => fetch(url, options)`), иначе просьба теряется по дороге.
Гард — `tests/test_studio_backend_freshness.py`.

Признак именно этой ловушки, а не рассинхрона: `curl` отдаёт новое, а страница
показывает старое. Быстрая проверка руками — Ctrl+F5 или DevTools → Network →
Disable cache.
