Коммит и пуш только по прямой команде; до неё — проверка и синхронизация установленной копии.

## Действующее правило с 2026-08-08

Владелец сказал:

> «Пуши не делай без моей команды, делай только пока синхронизацию с
> рантайм-копией, а коммит и пуш будешь делать по моей команде.»

Проверить относящиеся к задаче изменения и синхронизировать установленный пак. Коммит и пуш — только по прямой команде; полный набор тестов — только по отдельной команде. Разработку и Git-операции вести из dev checkout, не из установленной копии. Причина: владелец должен иметь возможность увидеть результат до создания истории; правка может быть отменена.

Текущие процедуры: [разработка](../../doc/operations/development.md), [релиз](../../doc/operations/release.md), [проверки](feedback_tests_on_demand.md).

## Почему правило изменилось

Ранее действовал автоматический порядок «после каждой завершённой правки — commit + push». Его цель — не оставлять полузаконченные изменения без истории и не проверять старый код в установленном клоне. После уточнения владельца 2026-08-08 результат сначала синхронизируется для просмотра; автоматические commit/push отменены. Несколько завершённых задач допускают отдельные осмысленные коммиты, когда владелец уже попросил их сделать.

Старое требование «синхронизация только через Git» относилось к прежнему разделению dev/runtime. Поздняя команда разрешает промежуточное копирование без публикации; финальное обновление установленного клона после релиза — через Git с сохранением локальных изменений. Точные команды и проверка содержимого находятся в операционной документации, а не в этой записи предпочтения.
