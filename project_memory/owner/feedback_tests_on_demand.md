полный тестовый набор гонять ТОЛЬКО по прямой команде пользователя — исключений нет, релиз тоже не повод; по умолчанию тестируются затронутые ноды и общие модули, которые в них задействованы

Пользователь (2026-08-07): «И каждый раз весь тестовый сьют запускать не надо,
только по моей команде.»

Уточнение (2026-09-14): «Обнови правила нашего пака: полный прогон только по
моей команде. А так, при изменении нод или добавлении нод, тестируется только
то, что с ними связано, общие модули, в которых они задействованы, и эти ноды.»

⚠️ **Оговорка «или перед публикацией версии» СНЯТА.** Она стояла здесь с августа
и один раз уже сработала не туда: 14.09.2026 на «Патч и Push» я завёл полный
прогон как «гейт перед релизом», и его пришлось останавливать командой. Бамп и
пуш — НЕ повод. Повод ровно один: человек попросил.

**Почему:** полный набор идёт десятки минут и занимает машину, на которой человек
в это время работает в ComfyUI. Прогон «на всякий случай» — это его время и его
видеопамять, а не только мои токены.

**Объём по умолчанию** — от того, что правилось, а не от осторожности:

1. тесты самой ноды (`tests/test_<нода>.py`);
2. тесты общих модулей, которые эта нода задействует, — и тесты ДРУГИХ нод,
   которые эти же модули используют (правка в `js/_studio/_compare.js` задевает и
   TS Image Studio, значит её тесты тоже идут);
3. `compileall` для Python и `node --check` для JS;
4. статические гарды, если правка их касается (`test_theme_compliance` при
   изменении CSS, `test_node_contracts` при изменении схемы).

**Как применять:**

- Перед прогоном прикинуть, кто ещё импортирует затронутый модуль
  (`grep -rn "from .*<модуль>" js/ nodes/`), и включить их тесты. Это дешевле
  полного набора и честнее, чем «прогнал один файл».
- Полный `pytest tests` — ТОЛЬКО по прямой просьбе, и сказать об этом вслух.
- Уже запущенный лишний прогон — остановить (`TaskStop`), а не «пусть досчитает».
- В verification summary честно писать, что полный набор не гонялся и почему.
- Правило verify → commit → push из [feedback_commit_then_sync](feedback_commit_then_sync.md) остаётся;
  меняется только объём verify.
