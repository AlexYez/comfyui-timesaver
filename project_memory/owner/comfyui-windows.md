Использовать одно окно сервера и существующую страницу, не засорять рабочее место тестами.

# Одно рабочее окно, без лишних процессов

При разрешённом запуске/проверке использовать существующий сервер и открытую страницу. Не создавать дополнительный ComfyUI и не плодить CMD-окна или вкладки браузера. Каждый лишний сервер занимает порт и VRAM; пользователю становится непонятно, чьи логи и результат он видит.

До любых операций жизненного цикла действует [требование прямой команды](comfyui-lifecycle.md). Для проверки наличия сервера достаточно read-only инвентаризации процессов и порта. Не завершать пользовательский Chrome и процессы, не созданные текущей проверкой.

Если владелец разрешил рестарт, сохранять реальное окружение и аргументы его процесса. На Windows фоновый запуск должен быть скрытым; `--disable-auto-launch` предотвращает новую страницу ComfyUI. После запуска проверить, что сервер ровно один. В автоматизированном браузерном тесте закрывать только созданные тестом контекст/браузер, в том числе при исключении.

## Почему прежние рецепты не надо копировать буквально

Старое указание запускать `start.bat` свёрнутым приводило к оставшимся CMD-окнам; более поздняя запись указывала запускать Python напрямую, скрыто. Ключ `--windows-standalone-build` также мог открывать браузер заново. Локальный `comfy.ps1` существовал в скретчпаде сессии и в репозиторий не входил: это не обязательная утилита проекта. Для Windows PowerShell 5.1 был важен BOM в скриптах с русскими комментариями; это наблюдение о старой среде, а не требование ко всем исходникам.

Конкретные пути и параметры машины владельца собраны в [описании окружения](../../doc/operations/environment.md); они не являются переносимыми значениями по умолчанию.
