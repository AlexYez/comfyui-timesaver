## Critical

### 1. Бесконечный цикл при OOM — нода не завершается, ComfyUI приходится убивать
`nodes/video/ts_frame_interpolation.py:409-455`

В `_interpolate_batch_adaptive` единственное состояние, переносимое между итерациями `while True`, — `current_tile_size`. При OOM на полнокадровом пути (`current_tile_size <= 0`) код ставит `current_tile_size = _initial_tile_size(h, w, align, tile_size=_MIN_TILE_SIZE * 4)` (=1024), а `_initial_tile_size` возвращает `0 if requested_tile_size >= max_dim else requested_tile_size`, то есть для любого кадра с `max(h, w) <= 1024` — снова **0**. Следующая итерация повторяет идентичный вызов `_run_model_batch(...)`.

Почему критично: аварийного выхода нет — проверка `if next_tile_size == current_tile_size: raise` есть только в тайловой ветке. Проглоченный здесь OOM не доходит до внешнего обработчика в `execute` (663-671), который вдвое уменьшил бы `max_timestep_batch` — единственный механизм, реально сокращающий аллокацию, оказывается недостижим. Проверок прерывания в цикле нет, поэтому рабочий поток не снимается.

**Воспроизведение:** интерполяция кадров 512×512 / 768×768 / 832×480 / 1024×576 на GPU, где батч по умолчанию (`max_timestep_batch=8`) не помещается. В логе бесконечно повторяется `OOM detected, retrying with tile size 0`.

**Фикс:** счётчик попыток либо прогрессивное уменьшение (ронять `max_timestep_batch` прямо здесь); при отсутствии прогресса — пробрасывать OOM наружу, чтобы сработал внешний обработчик. Добавить проверку прерывания в тело цикла.

### 2. Падение воркфлоу на RGBA-батче с разными границами альфы
`nodes/image/ts_resolution_selector.py:170-195`

`_crop_alpha_to_bbox` для каждого элемента батча добавляет тензор **своего** размера: обычная ветка — `rgb[i, y_min:y_max+1, x_min:x_max+1, :]` по собственному bbox, а ветка пустой альфы (175) — кадр целиком `src_h × src_w`. Перед `torch.cat(output, dim=0)` (195) нет ни ресайза, ни паддинга, а `torch.cat` требует совпадения всех измерений кроме нулевого.

Путь достижим: `_fit_image_to_canvas` вызывает функцию безусловно при `image.shape[3] >= 4` (204), `execute` не ограничивает размер батча. Такие данные производит сам пак — `ts_bgrm_birefnet.py` собирает RGBA пофреймово и возвращает `torch.cat(processed_images, dim=0)`.

**Воспроизведение:** прозрачный RGBA-выход BiRefNet по видеоряду (объект движется → bbox альфы отличается покадрово) на вход `image` Resolution Selector → `RuntimeError: Sizes of tensors must match except in dimension 0`, весь прогон падает. При `B=1` или одинаковых bbox проблемы нет.

**Фикс:** приводить кропы к общему размеру — объединённый bbox по батчу либо паддинг каждого кропа до максимального размера перед конкатенацией.

## Warning

### 3. Переполнение при конвертации в uint8 без клампа
`nodes/image/ts_qwen_canvas.py:82`, `nodes/image/ts_qwen_safe_resize.py:67`, `nodes/image/ts_wan_safe_resize.py:98`

Во всех трёх местах `(img_tensor.cpu().numpy() * 255).astype(np.uint8)` без ограничения диапазона. Выход `VAEDecode` не кламплен и штатно выходит за `[0,1]`: `1.03 → 262.6 → 6` (пересвет становится почти чёрным), `-0.02 → -5.1 → 251` (тень — почти белой). Эталон рядом: `nodes/image/_image_utils.py:81` использует `np.clip(255.*..., 0, 255)`.
**Фикс:** добавить `np.clip(..., 0, 255)` (или `.clamp(0,1)` до умножения) во всех трёх местах.

### 4. LUT применяется к дважды закодированному сигналу
`nodes/image/ts_film_emulation.py:206-209`

`image_for_lut = cls._linear_to_srgb(processed_image)`, но `processed_image` уже sRGB-кодирован — на пути от `image.float().clamp(0,1)` до этой строки в линейный свет ничего не переводит. Значение 0.2 превращается в 0.484, LUT сэмплируется по неверным координатам, затем `_srgb_to_linear` декодирует уже выход LUT. Подсказка обещает «Apply the LUT in sRGB space», а `gamma_correction` по умолчанию `True` — дефолтный путь External LUT делает обратное задекларированному. Ошибка пропорциональна тому, насколько LUT гнёт тон (для identity round-trip самоинверсен).
**Фикс:** при `gamma_correction=True` не конвертировать вовсе — сэмплировать LUT прямо по sRGB-значениям.

### 5. Нулевой размер тайла на легальных значениях виджетов
`nodes/image/ts_auto_tile_size.py:70-71`

`tile_width = round(tile_w / divide_by) * divide_by` без нижней границы. При `divide_by=512`, `tile_count=4`, 512×512, `padding=0`: сетка (2,2), `tile_w=256`, `round(0.5)=0` (банковское округление) → `tile_width = 0`. Без банковского округления: 64×64, `tile_count=16`, `divide_by=512` → `round(0.031)=0`. Схема такие значения допускает (`divide_by` max=512), клампа в `execute` нет. Нода молча отдаёт 0, а падает потребитель — ошибка указывает на чужую ноду. Аналогичное место в `ts_crop_to_mask.py:170-171` защищено ceil-делением.
*(Кандидат был отброшен в v9.76 как низкоуверенный; теперь воспроизведён на легальных значениях схемы.)*
**Фикс:** `max(divide_by, ...)` либо ceil-деление, как у соседа.

### 6. Роут очистки Lama удаляет произвольные файлы из `input/` и `output/`
`nodes/image/lama_cleanup/_lama_helpers.py:285-315` (роут — `985-998`)

Проверок две: `_is_inside_allowed_root(path_obj)` — но `_allowed_view_roots()` (136-150) возвращает `(input_dir, output_dir, temp_root)`, то есть input и output разрешены; и `path_obj.name.startswith(f"{safe}_")`, где `safe` получается из **присланного клиентом** `session_id` — префикс подбирается под цель. Собственный докстринг функции утверждает, что файлы должны лежать «inside the allowed temp root»; соседний `_cleanup_session_files` действительно ограничен `_temp_root().glob(...)`.

Пак сам пишет подходящие файлы: `OUTPUT_SUBDIR = "images/cleanup"`, `OUTPUT_NAME_TAG = "cleanup"` → `session_id="cleanup"` покрывает все сохранённые результаты. Шире: удаляется любой файл в input/output, в имени которого есть `_`, включая дефолтные `ComfyUI_00001_.png` (`session_id="ComfyUI"`). При обычной работе не срабатывает — фронтенд шлёт только временные пути из своей истории; это дефект области видимости, а не источник случайной потери данных.
**Фикс:** ограничить роут `_temp_root()`, как уже сделано в `_cleanup_session_files`.

### 7. Гонка за общей моделью SAM3 при предпросмотре
`nodes/image/sam_media_loader/_sam_media_helpers.py:1048-1071, 1303-1325`

`_get_preview_lock` ключует `asyncio.Lock` по имени чекпойнта, поэтому запросы с разными чекпойнтами **никогда не конкурируют**, хотя оба резолвят один синглтон `_Sam3PreviewModel.instance()`. `ensure_loaded` держит `self._load_lock` только на время загрузки, `_unload_locked` обнуляет `self._model`. `segment_first_frame` читает это поле вне блокировки — и на проверке, и на самом инференсе, — причём вызывается через `asyncio.to_thread`, то есть в настоящем рабочем потоке. Результат: либо ложное `SAM3 preview model not loaded`, либо инференс на весах другого чекпойнта. Достижимо при двух нодах SAM с разными загрузчиками (у каждой свой JS-state, защиты in-flight нет) или при смене чекпойнта во время предпросмотра. Для одиночного пользователя с одним чекпойнтом вероятность низкая.
**Фикс:** один общий lock на модель (а не по чекпойнту) либо блокировка инференса на время подмены.

### 8. Имя файла из `Content-Disposition` не читается никогда
`nodes/files/ts_downloader.py:675`, `458-469`, `755-767`

`_probe_remote_file` сохраняет `"headers": dict(response.headers)`. `CaseInsensitiveDict.__iter__` отдаёт **исходный регистр** ключей, поэтому в обычном dict оказывается `"Content-Disposition"`, а `_get_filename_from_header_map` ищет `headers.get('content-disposition')` — всегда `None`. Соседний `_extract_remote_size_from_headers` получает живой `response.headers` и потому работает. Последствия: имя берётся только из URL, логика «предпочесть уже существующий кандидат» (764-767) не срабатывает. Для хостов с непрозрачным путём (Civitai `/api/download/models/12345`) файл сохраняется как `12345`, а при повторном запуске с `skip_existing` не находится и качается заново.
**Фикс:** не разворачивать `response.headers` в обычный dict либо нормализовать ключи в нижний регистр.

### 9. Дублирование весов Whisper в кэше
`nodes/_whisper_engine.py:221-262`

`cache_key = (name, target_device, use_fp16)`, но кэшируемый объект от `whisper.load_model(...)` не зависит от `use_fp16` — dtype-аргумента нет, постобработки модели нет (`.half()` в паке вызывается только для BiRefNet и ViTMatte). `use_fp16` используется лишь как опция декодирования. Путей вытеснения нет вовсе. Переключение виджета `precision` на CUDA загружает вторую полную копию тех же весов (для `large-v3` ~6 ГБ) и не освобождает ни одну до конца жизни процесса. Докстринг модуля декларирует обратное.
**Фикс:** убрать `use_fp16` из ключа кэша.

### 10. Выход `processed_image` не является исходным изображением
`nodes/llm/ts_qwen3_vl.py:354-392`

Подсказка выхода (282) обещает «Input image passed through (unchanged)», но `execute` на **всех** путях возвращает `engine.pil_to_tensor(processed_images)`, где список наполняется через `tensor_to_pil_list` (`np.clip(...)*255 → uint8`, обратно `/255.0`) — безусловное 8-битное квантование, включая ветку `enable=False`. В основной ветке дополнительно работает `resize_and_crop_image(..., max_image_size)`: LANCZOS-даунскейл и центральный кроп до кратности 32, то есть меняется и разрешение. Если ни изображение, ни видео не подключены, `pil_to_tensor([])` возвращает `torch.zeros((1, 64, 64, 3))` — вниз по графу молча уходит чёрный кадр 64×64 вместо ошибки.
**Фикс:** возвращать исходный тензор без round-trip (обработанные PIL-кадры использовать только для модели) либо переписать подсказку и не подменять пустой вход чёрным кадром.

### 11. Локальный путь к модели Qwen не работает вопреки подсказке
`nodes/llm/_qwen_engine.py:1049-1069`

Подсказка (`ts_qwen3_vl.py:184`) обещает «HuggingFace repo id … or a full local path», но `ensure_model_available` безусловно делает `repo_name = model_id.split("/")[-1]` и `local_dir = os.path.join(models_dir, repo_name)` — проверки `os.path.isdir(model_id)` нет нигде на пути от `_resolve_model_id`. Уточнение валидатора: на Windows нативный путь (`C:\models\qwen`) случайно срабатывает, потому что `os.path.join` сбрасывается на абсолютный путь; ломается всегда для POSIX-путей и для Windows-путей с прямыми слэшами — они уходят в `snapshot_download(repo_id="/home/...")` и падают на «All mirrors failed» либо на offline-ошибке с указанием не того каталога.
**Фикс:** короткое замыкание `if os.path.isdir(model_id): return model_id` до резолва репозитория.

### 12. Утечка document-слушателя Escape в библиотеке стилей
`js/text/ts-style-prompt.js:1119-1152`

`doc.addEventListener("keydown", onKey, true)` снимается только в `close()`, который начинается с `if (!modalRoot) return;`. Но путь очистки другой: `node._tsStyleSelectorCloseLibrary` (вызывается из `teardown()` → `onRemoved` и при повторном `setupStyleSelector`) удаляет DOM и обнуляет `modalRoot`, **не снимая слушатель**. После удаления ноды с открытой модалкой слушатель живёт вечно и на каждый Escape выполняет `preventDefault()` + `stopPropagation()`, а `close()` при этом ничего не делает — Escape перестаёт работать во всём ComfyUI.
**Фикс:** снимать слушатель в самом `_tsStyleSelectorCloseLibrary` (или дать ему доступ к `onKey`/`doc`).
