# Проверка LiteRT-LM 0.19.0 — 2026-11-02

Обновление ускорило генерацию текста на существующих Gemma E2B/E4B; оно не
превратило их в точные анализаторы музыки, звуковых событий или движения.

## Что сравнивали

Windows, NVIDIA GeForce RTX 3080 Ti Laptop GPU, 16 384 MiB; Python портативной
ComfyUI. Старый `litert-lm-api==0.16.1` против стабильного `0.19.0`.
Использованы уже установленные полные мультимодальные abliterated-артефакты
`hfmaster/Gemma-4-RT`, без замены, сжатия или повторного скачивания:

| Файл | Размер, байт |
|---|---:|
| gemma-4-E2B-it-abliterated.litertlm | 2 588 147 712 |
| gemma-4-E4B-it-abliterated.litertlm | 3 659 530 240 |

Основной benchmark запускался последовательно, отдельным процессом на каждую
пару версии/модели/режима, при выключенной ComfyUI. Text/vision — GPU,
audio encoder — CPU, окно 8192, максимум четыре изображения. Для каждой версии
и модели выделен отдельный native cache: старые рабочие кэши не использовались
для изолированного сравнения. Выполнены десять комбинаций: OFF/ON для 0.16.1,
OFF/ON/ADAPTIVE для 0.19.0, обе модели.

Четыре задания: русский запрос → LTX, русский запрос → H3, картинка → image
prompt и отдельная творческая проба разнообразия seed. На задание один короткий
прогрев, затем seed 11 и 29; одинаковые инструкции и параметры внутри каждой
пары версий. Проба seed не добавлялась в пользовательские пресеты.

## Скорость и MTP

Средняя скорость декодирования по восьми ответам, **MTP выключен**:

| Модель | 0.16.1, ток/с | 0.19.0, ток/с | Изменение |
|---|---:|---:|---:|
| E2B | 62,1 | 83,3 | +34% |
| E4B | 40,6 | 54,2 | +33% |

Это скорость декодирования, а не ускорение всего workflow или распознавания
звука. Ответы различались по длине. Один компьютер, два seed — локальный
сравнительный замер, не универсальная характеристика модели.

Warm reload: E2B 2,35 → 1,39 с, E4B 7,72 → 2,60 с. Это по одному повторному
открытию; первая загрузка включала разное состояние компиляционных кэшей,
поэтому сравнения «холодного старта» из этих чисел делать нельзя.

На 0.16.1 с MTP все четыре задания возвращали одинаковые ответы при разных
seed. На 0.19.0 в творческой пробе обе модели дали разные ответы с ON и ADAPTIVE.
Совпадение двух низкотемпературных ответов само по себе не считалось багом.
Ускорение MTP зависит от задания: например, E2B image decode при seed 11 —
83,9 ток/с OFF, 74,7 ON, 76,5 ADAPTIVE. Поэтому **MTP оставлен выключенным**.
Закрытие upstream issue не требуется для признания наблюдаемой разницы;
открытый issue также не доказывает, что каждый старый симптом сохранился.

Замер VRAM включал загрузку, мультимодальные проходы, закрытие и повторную
загрузку. Пики не изолируют память декодирования: например, E2B 2541/3805 MiB
для старого/нового runtime. Снижение памяти не заявляется. WebGPU-память по-прежнему
учитывается отдельно от PyTorch; `keep_loaded=False` сохранён.

## Проверка модальностей

Проверялся настоящий общий адаптер, `TS_RTPromptEnhancer.execute` и голосовой
helper, а не отдельная имитация передачи медиа. Изменены были только каталоги
тестовых temp/native cache. Затем выполнены проверки установленного пака через
HTTP очереди ComfyUI и обработчики TS Super Prompt RT.

| Задача | Материал и проверка | Результат |
|---|---|---|
| Русская речь | WAV владельца, 19 с, 48 kHz stereo → штатное mono 16 kHz | Полная расшифровка; редкое название может быть ошибочным. |
| Речь с известным текстом | Системный русский голос, 19,011875 с | Обе модели/версии сохранили слова; пунктуация различается. |
| Длинная речь | Тройное повторение известной записи, 57,035625 с | Штатные сегменты 30 с с перекрытием; E4B передала все повторения, E2B ошибалась в словах/кавычках на стыках. |
| Подача голоса | Запись владельца: язык, темп, подача, музыка | Модели дали описание разговорной русской речи без музыки; это субъективное описание, не измерение эмоций. |
| Изображение | Фото девушки с микрофоном в студии | Основные предметы, одежда и свет распознаны; встречаются неверные детали причёски и фона. |
| Видео | 9 кадров → штатные 4; красный квадрат движется вправо, синий круг неподвижен | Обе модели приписывали кругу движение, путали направления/число кадров. Точная хронология не прошла. |
| Звуки | 3 высоких коротких сигнала, затем 3 низких удара, без речи | Ответы «тишина», «музыка», один сигнал или выдуманный источник. Точность не прошла. |
| Музыка | Контролируемый инструментал: арпеджио, бас, пульс 100 BPM, без вокала | E4B часто верно отмечала отсутствие вокала, но неверно описывала тембры/структуру; E2B придумывала вокал. |
| Настоящий музыкальный файл | Первые 20 с локального OCEAN BLUE | ACE-Step вернул текстовый caption; без независимой разметки тембров/жанра это проверка выполнения, не доказательство точности. |
| Кадры + звук | Те же четыре кадра и сигналы одним запросом | Запрос выполняется, но модель может пропускать звук и ошибаться в движении. |

### Дословный эталон владельца

> Вот такой образец простой речи мы будем использовать. Мы будем рассказывать про Stable Diffusion, про ComfyUI, про различные нейросети, и самое главное здесь — это то, что мы будем использовать качественные названия. Первое название у нас — это Artius Diffusion.

Эталон не передавался модели. Для WER приведены к нижнему регистру слова,
удалена пунктуация, `ё` приравнена к `е`; 38 слов. Расстояние Левенштейна по
словам в изолированных проходах:

| Runtime | E2B | E4B |
|---|---:|---:|
| 0.16.1 | 0/38 | 0/38 |
| 0.19.0 | 0/38 | 1/38 (2,63%) |

В ошибочном проходе E4B написала **Artus Diffusion** вместо **Artius Diffusion**.
Один пример и один проход не позволяют объявить регрессию ASR всей модели.
Время уже загруженной модели на этой записи: 3,50/2,83 с (E2B/E4B старой
версии), 3,54/2,66 с новой. Загрузки и компиляции здесь не включены.

### Что изменено в инструкциях

В трёх **существующих** аудиопресетах добавлен приоритет слышимого референса:
запись важнее примеров, нельзя придумывать числовой BPM, источник звука,
инструмент или развитие вне фрагмента. Названия, порядок, параметры генерации и
параметры остальных пресетов сохранены. Файл общий для Gemma и Qwen.

В повторе E2B исчез выдуманный `128 BPM`; E4B продолжила писать caption без
числового BPM. Но неверные инструменты/вокал/число звуков остались. Промпты
уменьшают часть домыслов, **не исправляют способности весов**. Голосовой
системный промпт не подгонялся под Artius или предоставленный эталон.

Отдельная проверка выявила навязанный watercolor/animation в LTX и сочетание
static camera с push-in в H3. Они встречались до изменения соответствующих
инструкций; процент ускорения выше измерялся на прежних одинаковых промптах.

Обновлены **существующие** LTX/H3: стиль берётся из задания/реальной картинки,
нельзя ссылаться на отсутствующее изображение, движение камеры исключает
static camera, отсутствующая длительность не придумывается. Один H3-пример
переписан на приближение камеры, чтобы не все примеры показывали статичный план.
На двух моделях повторены обычная сцена с приближением и заданная акварель со
статичной камерой. В финальной обычной LTX-сцене обе модели обошлись без
навязанной акварели/анимации и без ссылки на отсутствующую картинку; E2B всё ещё
добавила неуклюжее «visual style with no specified style». В H3 исчезли
противоречивая static camera и выдуманные четыре секунды. Модель всё ещё может
пропустить (S1) или пунктуацию реплики: это не отчёт об идеальных промптах.

## Изменения реализации

- `RUNTIME_REQUIREMENT`, optional extra `litert` и команды установки — 0.19.0.
- Новый `SpeculativeDecodingConfig(OFF/ON)` вместо deprecated boolean;
  fallback для старого Python API сохранён.
- Публичные входы/выходы, defaults, каталог моделей, окно, сегментация и
  автоматическая выгрузка не изменены.
- Справка/tooltip честно описывают точность анализа звуков и кадров.
- Сервер запускается только по прямому разрешению владельца от 2026-11-02.

## Проверки и воспроизводимость

Локальные receipts и harness: `tests/.cache/litert-upstream-20261102/`.
Каталог игнорируется Git: включает DLL runtime, native cache и тестовые медиа.
Он не является обязательным содержимым чистого клона. В репозитории сохранены
методика, числовые результаты и отрицательные результаты выше.

В локальной лаборатории:

```powershell
python -m pytest tests/test_super_prompt_rt.py tests/test_rt_prompt_enhancer.py tests/test_super_prompt_contract.py -q
python -m ruff check nodes/llm/_litert_engine.py nodes/llm/ts_rt_prompt_enhancer.py
git diff --check
```

**119 passed**, Ruff и diff whitespace — без ошибок. Полный suite не запускался.
Первичная живая проверка: **16 успешных запросов** — на каждой модели кнопочный
обработчик ASR, графы картинки/кадров со звуком/музыки/transcribe/подачи голоса,
обработчики Enhance LTX/H3. В графах проверено получение текста через PreviewAny;
после каждой такой генерации статус engine.loaded=false. Тестовый потолок
256 токенов местами обрезал длинное описание картинки; это smoke выполнения,
а содержательную проверку описаний проводили отдельными проходами выше.

Дополнительно выполнены восемь повторов LTX/H3 после правки примеров и финальные
LTX-повторы после уточнения отсутствия изображения. Сервер оставлен работающим,
автовыгрузка Gemma проверена; cancel честно возвращает cancelled=false, как и
раньше — новая отмена в середине генерации не реализовывалась. UI микрофона,
полноэкранные панели и живой браузер этими HTTP-проверками не покрыты.
