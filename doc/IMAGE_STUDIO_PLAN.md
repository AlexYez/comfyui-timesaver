## 0. Операционные решения владельца (2026-08-02)

- **Никаких облачных API** — только локальные генерации. Ideogram 4 —

  шаблоны ComfyUI (включая сабграфы) как основу.

## 1. Что строим

Полноэкранное приложение генерации и редактирования изображений внутри
ComfyUI: одна нода `TS_ImageStudio` («TS Image Studio»), открывающая
студию с режимами **Generate / Edit / Inpaint / Upscale**, галереей сессии,
референсами и сквозным drag-and-drop. Приложение — клиент собственного API
ComfyUI: генерация выполняется **нативными нодами** через отправку
отдельного prompt в очередь (`/prompt`), не затрагивая граф пользователя.

Второй потребитель архитектуры — будущие TS Video Studio и TS Audio Studio:
всё, что не специфично картинкам, уезжает в переиспользуемый кит.

## 2. Ключевые архитектурные решения (зафиксированы)

| # | Решение | Причина |
|---|---|---|
| 1 | Бэкенд любого режима — **workflow-файл ComfyUI** с маркерными нодами | один механизм для встроенных и пользовательских бэкендов; новая модель = новый файл, ядро не меняется |
| 2 | Отправка через **`/prompt` + WebSocket**, не node expansion | бесплатно: очередь, отмена, прогресс, live-превью, кэш моделей |

| 6 | Тема — **родные CSS-переменные ComfyUI** через токены `--ts-*` | см. §8: реагирует на смену темы живьём; классы PrimeVue нестабильны |

## 3. Структура файлов

```
nodes/image/studio/
  ts_image_studio.py        # нода-мост: выход IMAGE = выбранный результат сессии
  ts_studio_markers.py?     # маркерные ноды — см. открытый вопрос §13.1
js/_studio/                 # КИТ (общий для будущих Video/Audio Studio)
  _shell.js                 #   каркас: рейка режимов (data-driven), дека, статус
  _runner.js                #   патч → /prompt → прогресс → отмена своих заданий
  _markers.js               #   поиск/валидация маркеров, схема манифеста
  _backends.js              #   реестр workflow: встроенные + userdata, override
  _dnd.js                   #   единый drag-and-drop (§7)
  _assets.js                #   AssetProvider: Artius + fallback (§7.2)
  _gallery.js               #   плёнка сессии, «отправить в…», A/B
  _session.js               #   session id, версионированные файлы, восстановление
  _history.js               #   единый undo/redo-стек (§6)
js/image/studio/
  ts-image-studio.js        # entry: registerExtension, кнопка Open Interface
  _app.js                   # композиция кита + image-режимы
  _stage.js                 # холст: зум/пан, letterbox, live-превью, A/B-шторка
  _mask.js                  # рисование маски (движок, выделенный из LamaCleanup)
  _modes/{generate,edit,inpaint,upscale}.js
  workflows/                # встроенные бэкенды (см. §5)
docs (js/docs/TS_ImageStudio/{en,ru}.md) + example_workflows/ + locales/
```

Маркерные ноды (Python): `TS_StudioInputImage / Mask / Text / Number / Seed`,
`TS_StudioOutput`, `TS_StudioManifest`, **`TS_StudioLoraStack`**. Все —
passthrough/константы, без тяжёлой логики. Контракты (имена, входы)
фиксируются в snapshot-тесте с первого дня — их менять нельзя, на них
ссылаются workflow-файлы.

`TS_StudioLoraStack` — особый маркер: passthrough **только MODEL** (один
вход `model`, один выход `model`), точка вставки цепочки лор. Автор бэкенда
ставит его между лоадером и сэмплером; патчер разворачивает его в prompt
JSON в цепочку нативных **`LoraLoaderModelOnly`** — по одной ноде на каждую
лору из стека, в заданном порядке; слайдер силы = `strength_model`
(отрицательные значения допустимы). CLIP лоры не трогают — сознательное
решение: проще граф, предсказуемее результат, один вход/один выход.
Пустой стек — маркер схлопывается в прямое соединение.

## 3.5. Архитектурные правила: модульность и точки расширения

Цель: новая функция = **регистрация в реестре или новый файл данных**,
а не правка ядра. Изменение функции = правка одного модуля за ясной
границей. Правила обязательны для всего кода студии.

### Слои и направление зависимостей

```
data (workflows/*.json, манифесты, styles.json)      ← только данные
  ↑ читает
core (_markers, _backends, _runner, _session,
      _history, _store)                               ← БЕЗ DOM. Чистая логика
  ↑ импортирует
ui-kit (_shell, _dnd, _gallery, _assets + ts-ui-*)    ← DOM-компоненты
  ↑ композирует
app (js/image/studio/_app.js + _modes/*)              ← только wiring
```

Импорт разрешён **только вниз**. `core` не знает про DOM (юнит-тестится в
Node без браузера); `ui-kit` не знает про режимы студии; `_app.js` не
содержит логики — только связывание. Нарушение слоя = замечание ревью.

### Состояние: один store, односторонний поток

Единый observable session-store (свой, ~60 строк, без фреймворков):
`getState()` / `dispatch(action)` / `subscribe(selector, cb)`. Мутации —
только через actions; UI подписывается селективно и перерисовывает своё.
Undo-стек (§6) — слушатель store: он записывает переходы, а не
вклинивается в каждый обработчик. Прямая мутация состояния из UI запрещена.

### Реестры — единственный способ добавлять функциональность

| Реестр | Что регистрирует | «Добавить X» = |
|---|---|---|
| modes | режимы (id, icon, deck-layout, stage-tools) | новый файл в `_modes/` + 1 строка регистрации |
| control kinds | рендереры контролов манифеста (`prompt`, `size`, `loras`, ...) | новый renderer, манифесты его уже могут называть |
| asset providers | источники ассетов (§7.2) | новый провайдер |
| dnd sources | распознаватели payload (§7.1) | новый normalizer |
| upscale methods | данные из манифестов | новый workflow-файл |
| prompt tools | кнопки тулбара поля (§9.1) | новая запись: icon + action + detect() |

Реестры принимают регистрации до и после инициализации (late-binding) —
будущий TS Video Studio регистрирует свои режимы в тот же кит.

### Контракты и их эволюция

Единый раздел истины — этот документ + snapshot-тесты:

- **Манифест**: semver `schema_version`; изменения ТОЛЬКО аддитивные
  (новое опциональное поле). Ломающее изменение = новая мажорная версия
  схемы + чтение обеих на переходный период.
- **Маркерные ноды**: id и имена входов заморожены contract-тестом.
- **WS-события** (`fetch_progress`, прогресс runner-а): поля только
  добавляются; потребитель обязан игнорировать незнакомые.
- **Store actions** и события bus: имена — часть контракта кита.

### Гигиена модулей

- Один модуль — одна ответственность; ориентир ≤ 400 строк; превысил —
  делится ДО мержа, а не «потом».
- Межслойное общение — через store/реестры, не прямыми импортами соседей.
- Никаких синглтонов с DOM-состоянием в core; всё состояние — в store
  или в замыкании компонента.
- Каждый core-модуль сопровождается юнит-тестом при рождении (Node,
  без браузера); ui-kit — браузерным смоуком.

## 4. Манифест бэкенда (схема v1)

Нода `TS_StudioManifest` в workflow несёт JSON:

```jsonc
{
  "id": "flux2-klein/t2i",          // уникален; user-файл с тем же id ПЕРЕОПРЕДЕЛЯЕТ встроенный
  "label": {"en": "Generate", "ru": "Генерация"},
  "family": "flux2-klein",          // группа переключателя моделей
  "family_label": "Flux 2 Klein 9B",
  "mode": "t2i",                    // t2i | edit | inpaint | upscale (список открыт — видео добавит свои)
  "order": 10,
  "controls": [                     // ЧТО показать в деке; param → маркер
    {"param": "prompt",  "kind": "prompt",  "superprompt": true},
    {"param": "size",    "kind": "size",
      // Сетка соотношений + слайдер разрешения в МЕГАПИКСЕЛЯХ.
      // Оптимум задаёт СЕМЕЙСТВО модели: base_mp — дефолт, mp — допустимый
      // диапазон, snap — кратность сторон. UI считает W×H из аспекта и MP.
      "aspects": ["1:1","16:9","9:16","3:2","2:3","4:3","3:4"],
      "base_mp": 1.5, "mp": [0.5, 4.0], "snap": 64},
    {"param": "seed",    "kind": "seed"},   // поле + режим: ручной / randomize
    {"param": "loras",   "kind": "loras",  "max": 8, "strength": [-2.0, 2.0]},
    {"param": "steps",   "kind": "number",  "advanced": true, "min": 1, "max": 50}
  ],
  "refs": {"max": 3, "optional_branches": true},   // 0 = нет слотов
  "negative_prompt": false,          // Flux: поле не рисуется вовсе
  "models": [                        // файлы, которые студия проверит/предложит скачать
    {"param": "model_file", "folder": "diffusion_models", "match": "klein.*9b"}
  ],
  "dependencies": [{"pack": "LanPaint", "nodes": ["LanPaint KSampler"]}],
  "min_pack_version": "10.1"
}
```

Валидация при загрузке (жёсткая, с внятными причинами): манифест есть и один;
обязательные параметры режима присутствуют (inpaint ⇒ image+mask); Output
есть; все типы нод существуют в `/object_info`; файлы моделей находятся или
предлагаются к докачке через TS Files Downloader. Невалидный бэкенд виден
серым с причиной — не исчезает молча.

**Upscale — только workflow, два встроенных метода** (family: `*` — работают
с любым изображением):

1. `upscale/seedvr.json` — **SeedVR**: диффузионный restoration-апскейлер,
   собственный workflow на его нодах; медленнее, «дорисовывает» детали.
2. `upscale/diffusion-secondpass.json` — **второй проход той же генеративной
   моделью**: тайловый апскейл (наши tile-ноды `TSAutoTileSize` и родня) +
   низкий денойз; манифест объявляет параметр `family_model` — какой
   моделью догонять детали, по умолчанию активной в студии.

Карточки методов в деке — из манифестов; пользовательский третий метод —
просто ещё один файл.

**Универсальный инпэйнт — СОБСТВЕННАЯ нода** (решение владельца
2026-08-02): `TS_UniversalInpaintSampler` — training-free инпэйнт по методу
ланжевеновских «think»-итераций, реализованный С НУЛЯ по опубликованной
статье (TMLR 2025, arXiv: LanPaint). Никакого заимствования GPL-кода: своя
реализация математики (метод не копирайтится), свои параметры
(think_steps / lambda / step_size / friction), ноль внешних зависимостей и
JS. Кроп-обвязка та же: `TSCropToMask → наш сэмплер → TSRestoreFromCrop`.
Должна работать и с eps-, и с flow-моделями (Z-Image, Krea2, Qwen — flow
matching). Пак LanPaint из зависимостей исключается.

Inpaint-режим — два под-режима на одном холсте с общей маской:
**Cleanup** (LaMa, живые роуты, без промпта, результат на отпускание кисти)
и **Repaint** (диффузия по таблице выше, промпт + Run).

## 6. Undo/Redo (единый стек)

- Одна хронологическая лента команд на сессию: штрих маски · применение
  LaMa · принятый результат Repaint · замена исходника · очистка маски ·
  переключение версии. **Ctrl+Z откатывает последнее действие, чем бы оно
  ни было.**
- Пиксельные состояния — версионированные файлы
  (`{session}_{tag}_{nanos:020d}`, append-only, паттерн LamaCleanup);
  undo пиксельной команды = сдвиг указателя, мгновенно, переживает
  перезагрузку. Штрихи маски — лёгкие in-memory команды между ними.
- Redo живёт до первого нового действия. Кнопка History — лента шагов с
  миниатюрами, клик = переход. Генерации никогда не разрушают: каждый Run —
  новая версия в плёнке.
- Фокус-якорь `openFullscreenOverlay` уже гарантирует, что Ctrl+Z не уйдёт
  в ChangeTracker графа.

## 7. Drag-and-drop и ассеты

### 7.1. Один модуль `_dnd.js`
`normalizeDrop(event)` приводит всё к `{type, getBlob()|comfyRef}`:
файлы ОС · MIME Artius (`application/x-timesaver-artius-asset`, single и
массив) · `text/uri-list` · вставка из буфера · наш внутренний MIME
`application/x-ts-studio-asset` (перетаскивание из плёнки в слот референса).
`makeDropZone(el, {accept, onDrop})` — единые подсветка/валидация/teardown
(правила CLAUDE.md §12.5.11 закодированы один раз). Байты дальше всегда
одним путём: `POST /upload/image` → имя файла → патч маркера; дисковые пути
через границу не ходят.

### 7.2. AssetProvider
`{id, label, detect(), mount(host,{filter,multi,onPick}), dragMimes}`.
**ArtiusProvider**: detect по `window.tsArtiusBrowser`; до появления в Artius
экспорта `mountPanel` работает drag-only (MIME принимается уже сейчас);
задача на embed-API — отдельно, в репозитории Artius.
**FallbackProvider** (всегда): выбор файла ОС + вставка + недавние из
`/history` + галерея сессии.

## 7.5. Скачивание моделей: прозрачно, по одной, с двумя уровнями прогресса

Требование: пользователь видит процесс полностью — детальный прогресс по
каждому файлу и общий; модели скачиваются **индивидуально**, а не «всё для
workflow» одной непрозрачной операцией.

### Архитектура

Движок уже существует и оттестирован — TS Files Downloader (докачка Range,
SHA256 на лету, `.tsmeta.json`, зеркала, allowlist токенов). Студия его
**не дублирует**, а получает как сервис: в пак downloader-а добавляются
HTTP-роуты (рядом с существующим `/ts_downloader/hf_search`, у которого
уже есть паттерн прогресс-событий через PromptServer):

```
POST /ts_downloader/fetch   {url, target, operation_id} → {job_id}
POST /ts_downloader/cancel  {job_id}
GET  /ts_downloader/jobs    → активные и завершённые джобы сессии
события WebSocket: ts_downloader.fetch_progress
  {job_id, filename, done_bytes, total_bytes, speed_bps, eta_s,
   status: queued|running|verifying|done|error|cancelled, error?}
```

- **Одна модель = одна джоба.** «Скачать все» — это просто N джоб.
- Параллельность: максимум 2 активных загрузки, остальные `queued`
  (диск и канал; очередь видна пользователю).
- События троттлятся (~4/с на джобу) — WebSocket не заспамлен.
- Отмена оставляет `.part`; повторный запуск докачивает (движок уже умеет).
- `GET /jobs` — восстановление после перезагрузки страницы: прогресс-бары
  оживают, ничего не теряется.
- Очередь ComfyUI (`/prompt`) НЕ используется: загрузка не должна ни
  занимать слот генерации, ни зависеть от неё.

### UI

- Валидатор бэкенда показывает недостающие модели списком: имя · размер
  (HEAD) · источник · кнопка **«Скачать»** у каждой строки индивидуально.
- Строка активной загрузки: детальный бар (проценты, скорость, ETA),
  пауза недоступна — только отмена (докачка делает её безопасной);
  статус `verifying` показан отдельно («проверка SHA256»).
- Над списком — **общий бар: суммарные байты всех джоб** (байты, не счётчик
  файлов — файлы разного размера делают счётчик лживым).
- Уехал в другой режим — в шапке деки остаётся компактный индикатор общего
  прогресса; клик возвращает к списку.
- По завершении джобы валидатор перепроверяет бэкенд автоматически: серые
  пункты оживают без действий пользователя.

## 8. Тема: реакция на светлую/тёмную ComfyUI

Требование: интерфейс переключается вместе с родной темой ComfyUI.

Механизм — **существующий** в паке, студия его наследует целиком:

- Токены `--ts-*` строятся на родных переменных ComfyUI
  (`--comfy-menu-bg`, `--comfy-input-bg`, `--input-text`, `--border-color`);
  остальные оттенки подмешиваются `color-mix()` в сторону цвета текста —
  на светлой теме шаг **автоматически инвертируется** (THEME.md §2).
- Смена палитры ловится живьём: `MutationObserver` в `_theme.js` сбрасывает
  кеш `getThemeColors()` — canvas-отрисовка (шахматка, шторка A/B, кольцо
  кисти) перечитывает цвета без перезагрузки.
- Почему именно переменные, а не CSS-классы фронтенда ComfyUI: классы —
  внутренности PrimeVue/Vue-сборки, они меняются между версиями фронтенда и
  не являются контрактом. Переменные — публичный контракт тем, на нём
  построены и сами палитры ComfyUI. Это «родное» в единственно надёжном
  смысле.
- Новые компоненты кита не вводят ни одного константного цвета
  (гард `test_theme_compliance.py` распространяется на них автоматически);
  допустимые исключения — только поверх пользовательского контента
  (letterbox, кольцо кисти) с комментарием, по CLAUDE.md §12.6.
- В чек-лист приёмки каждой фазы входит скриншот-прогон **обеих** тем
  (Playwright, `locale='en-US'`, переключение палитры через настройку).

## 9. Интерфейс (макет v2, по референсу Artius Diffusion)

Каркас слева направо:

1. **Рейка режимов** 44 px (data-driven из манифестов).
2. **Дека управления** 320–360 px — **СЛЕВА**: модель → промпт (кнопка
   SuperPrompt внутри поля) → референсы (до 3 слотов) → **Формат** (сетка
   соотношений 1:1 / 16:9 / 9:16 / 3:2 / 2:3 / 4:3 / 3:4; **каждая карточка
   несёт миниатюру-прямоугольник реальной пропорции** — пользователь видит
   форму кадра до выбора, подпись-цифры под фигурой; активная — акцентная
   заливка фигуры) → **Разрешение**
   (слайдер в мегапикселях; диапазон и дефолт — оптимум активной модели из
   манифеста, стороны кратны `snap`) → **Seed** (поле + переключатель
   ручной/randomize) → **LoRA-стек** → «Дополнительно» → **Run** (внизу,
   единственная акцентная).
3. **Холст** — всё оставшееся пространство; плавающий тулбар инструментов
   (в Inpaint: Cleanup/Repaint, кисть, undo/redo, история).
4. **Браузер ассетов** — **СПРАВА, сворачиваемый практически в ноль**
   (до рейки ~28 px с кнопкой разворота и бейджем новых результатов).
   Вкладки: «Сессия» (результаты, live-пополнение) и «Библиотека»
   (AssetProvider: Artius, при отсутствии — fallback §7.2). Поиск, грид
   миниатюр, drag в слоты референсов/на холст. Отдельной нижней плёнки НЕТ —
   её роль выполняет вкладка «Сессия»; выбранный кадр = выход ноды.

### 9.1. Промпт-поле — медиакомбайн на сервисах SuperPrompt

Поле промпта — не textarea с одной кнопкой, а главный инструмент. Все
возможности берутся из **существующих** сервисов пака (студия — клиент,
нулевое дублирование):

Тулбар поля (компактные иконки в нижней кромке textarea):

| Кнопка | Что делает | Под капотом |
|---|---|---|
| 🎤 Диктовка | запись с микрофона, текст добавляется в поле | MediaRecorder → `POST /ts_voice_recognition/transcribe`; выбор Whisper-модели и High Quality — как в ноде TS SuperPrompt (`/preload`, `/status` — прогрев с прогрессом) |
| 🖼 Из картинки | приложить изображение (drop-зона/выбор/из сессии) | загрузка через `/upload/image` → `attached_image` |
| ✨ AI | улучшение промпта; **если приложена картинка — комбинирует её с текстом**, ровно как нода TS SuperPrompt | `POST /ts_super_prompt/enhance` (принимает текст + attached_image, вне очереди) |
| Пресет ▾ | пресеты SuperPrompt (cinematic, photoreal, ...) | `preset_options` из `_qwen.py` — тот же список, что у ноды |
| Модель ▾ | выбор Qwen-модели enhance + High Quality | параметры того же роута |
| Стили ▾ | селектор стилей — интеграция TS Style Prompt Selector | библиотека `styles/styles.json`; выбранные стили — чипы под полем, применяются к промпту тем же шаблоном, что нода `TS_StylePromptSelector` |

Поведение: приложенная картинка видна миниатюрой в углу поля (× — убрать);
✨ с картинкой = image+text → Qwen VL, без — чистое улучшение текста.
Диктовка дописывает в позицию курсора, не затирает. Чипы стилей снимаются
кликом; в параметры результата в галерее пишется финальный собранный промпт
и список стилей. Статусы (прогрев Whisper, генерация) — в строке поля,
с прогрессом, не блокируя остальной UI. Если нужного роут-сервиса нет
(урезанная установка) — кнопка гаснет с подсказкой, поле остаётся обычным.

### 9.2. Встроенный Help (два уровня, локализованный)

1. **Обучающие hover-подсказки** — на КАЖДОМ контроле подробный tooltip:
   что делает, как пользоваться, горячая клавиша. Реализация: единый
   `_help.js` в ките — реестр `help[controlId] = {en, ru}`; компоненты кита
   вешают подсказку автоматически по своему id, не вручную. **Функция
   отключаемая**: переключатель в настройках студии (шестерёнка на рейке);
   в выключенном виде остаются только короткие native-title.
2. **Полноценный встроенный хелп** — кнопка `?` на рейке открывает панель
   поверх холста: оглавление по режимам, страницы Markdown из
   `js/image/studio/help/{en,ru}/*.md` (генерация в стиле `js/docs/`,
   единый источник — README-раздел студии, сборка `tools/build_node_docs.py`
   расширяется). Контекстность: открытый хелп показывает страницу текущего
   режима.
3. **Локализация — 100%**, включая обе части Help: словари через
   `pickLocaleStrings` (en/ru), язык следует настройке ComfyUI
   `Comfy.Locale` (смена языка перезагружает страницу — штатный механизм
   пака, живой перерисовки не требуется). Ни одной жёсткой строки в
   разметке — гард-тест локалей кита.

**LoRA-стек**: кнопка «+ LoRA» → выпадающий список с поиском по
установленным лорам (списки из `/object_info` LoraLoader). Каждая строка:
ручка перетаскивания (☰) · имя · слайдер/поле силы **−2.0…+2.0** · ×.
Порядок строк = порядок цепочки, меняется drag-and-drop (через общий
`_dnd.js`). Стек сохраняется в параметрах результата в галерее — «взять
параметры» возвращает и лоры.

**Плотность и линии (дизайн-контракт).** Разделители колонок и секций —
исключительно hairline `1px var(--ts-border)` (полупрозрачный), никаких
толстых рамок и двойных бордеров; панели отделяются цветом поверхности, а
не обводкой. Компактная плотность: строки контролов 26–28 px, вертикальный
ритм 8 px, заголовки секций `--ts-fs-xs` верхним регистром приглушённым
цветом. Вся хромированная часть визуально «тихая» — внимание пользователя
принадлежит изображению. (Толстые разделители на генеративном превью —
артефакт картинки, не дизайна: в вёрстке толщина зафиксирована токенами.)

Принципы прежние: холст — главный; прогрессивное раскрытие; **один
акцент** — залита только Run; всё из токенов. Upscale — карточки методов +
шторка A/B. Горячие клавиши: Ctrl+Enter Run · 1–4 режимы · B/E ·
`[`/`]` · X под-режим · Ctrl+Z/Y · Space «до» · Tab — свернуть/развернуть
браузер ассетов. A11y: `role="dialog"`, tablist, live-region прогресса,
`:focus-visible`, `prefers-reduced-motion`. Локализация en/ru через
`pickLocaleStrings` с первого коммита.

Что сохраняется при переключении модели: промпт, сид, исходник, маска,
референсы (лишние слоты гаснут, но не очищаются), LoRA-стек — с проверкой
совместимости папки лор семейства (несовместимые строки гаснут с бейджем).
Специфичные параметры — к дефолтам манифеста; разрешение пересчитывается к
оптимуму новой модели с сохранением выбранного аспекта.

## 10. Нода-мост и совместимость

- `TS_ImageStudio`: категория `TS/Image`, вход не обязателен (опциональный
  IMAGE «использовать как исходник»), выход `IMAGE` — выбранный результат;
  hidden-виджеты `session_id`, `result_path` + зеркало в `node.properties`
  (§12.5.13); `fingerprint_inputs` — от result_path + mtime.
- Контракты с первого релиза: id нод(ы) и маркеров, имена параметров,
  схема манифеста v1 (расширяется только добавлением полей).
- Эволюция нод пака: каждый встроенный workflow валидируется в CI против
  текущих схем (расширение `build_node_contracts` / отдельный тест) — смена
  контракта ноды падает в коммите, не у пользователя. В рантайме — проверка
  против живого `/object_info` с внятной ошибкой и указанием, что обновить.

## 11. Тесты (минимум на приёмку фаз)

1. Snapshot маркерных нод и `TS_ImageStudio` в contract-тесте.
2. Схема манифеста: pytest-валидация всех встроенных workflow-файлов.
3. Патчер: подстановка параметров/референсов, выкусывание пустых optional-веток,
   отказ при недостающих маркерах — офлайн, на фикстурах.
4. Живой тест (skip без сервера): каждый встроенный workflow против
   `/object_info` — все ноды и входы существуют.
5. Браузерный smoke: студия открывается, режимы переключаются, консоль чистая,
   обе темы; JS-парсер (`test_js_syntax.py`) покрывает кит автоматически.
6. Undo-стек: юнит-тесты ленты команд (порядок, redo-инвалидация, версии).
