# Backend: данные, ресурсы и границы

У каждого тензора, кэша, файла и процесса должен быть явный владелец и понятный жизненный цикл.

## Тензоры и устройства

IMAGE — [B,H,W,C], обычно float32 в 0..1; MASK — [B,H,W]. AUDIO содержит
waveform [B,C,T] и sample_rate. LATENT — словарь с samples, форма которого
зависит от модели: изображение обычно 4D, видео обычно 5D, а H3 аудио+видео
может использовать NestedTensor. Не переносите предположение SDXL о 4D на H3/LTX.

Не терять batch dimension через image[0] и не мутировать входной тензор:
перед изменением clone. Сохранять dtype/device там, где это обещано контрактом.
Clamp нужен на границе диапазона, а не автоматически после любой операции.
Inference без обучения — torch.no_grad/inference_mode согласно движку.

Для общего PyTorch-пути использовать comfy.model_management.get_torch_device(),
не cuda:0. Специализированный backend может иметь собственные ограничения:
DLSS/VFX требуют RTX/Windows по своему runtime, LiteRT использует внешний
движок, Whisper сознательно работает на CPU. Это не универсальные MPS/CUDA баги.
Большие модели загружать лениво; module-level register folder/route/injector
не равен module-level загрузке модели и является частью действующей архитектуры.

## Зависимости и внешние бинарники

Core/optional зависимости объявлены в [pyproject](../../pyproject.toml),
инструкции установки — в [operations](../operations/development.md).
Optional-пакеты проверяются при execute через
[TSDependencyManager](../../ts_dependency_manager.py); failure даёт понятную
ошибку с TS-префиксом. Не запускать pip из ноды и не менять постоянно env пользователя.
Менеджер кэширует неудачный import на время процесса: установка пакета требует
перезапуска, а не retry на каждом execute. Guard сохраняет async execute асинхронным
и нормализует Exception в RuntimeError; typed-V1 fallback в нынешнем менеджере отсутствует.

ffmpeg искать через [nodes/_ffmpeg.py](../../nodes/_ffmpeg.py): сначала
imageio-ffmpeg, затем PATH. Своих копий резолвера не заводить — раньше четыре
пути давали четыре разных непонятных ошибки. PyTorch не заменяет codecs/demux/encode.
PyAV в медиа-подсистеме и отдельно установленный VE_CLI у DLSS v21 — другие
явно реализованные тракты; не заменять их общим shell-вызовом ради единообразия.

Внешние процессы запускаются списком аргументов, без shell=True/os.system
и без сборки исполняемой команды из пользовательского текста. При отмене
завершать только принадлежащий текущей операции процесс, затем закрыть дескрипторы
и очистить свои временные файлы. Не убивать процессы по общему имени программы.

## Отмена и память

ProgressBar не проверяет Cancel. Длинный цикл регулярно вызывает
raise_if_interrupted из [общего модуля](../../nodes/_shared.py) либо штатную
проверку comfy.model_management. Не поглощать InterruptProcessingException
широким BaseException, кроме cleanup с обязательным повторным raise.

ModelPatcher память и собственные PyTorch/native-кэши — разные владельцы.
Unloading собственной модели должен соблюдать её lock; «занято» лучше, чем
закрыть движок в середине inference. shared register_memory_release и held_or_busy
кодируют именно этот контракт. Никогда не освобождать чужие модели произвольно
из обработчика UI или одного шага текущей ноды.

## Пути, сеть и конфигурация

Пути входа/выхода/моделей получать через folder_paths; активные каталоги
[окружения](../operations/environment.md) — пример машины владельца, не константы кода.
Для нового файлового назначения проверить конечный resolved path внутри
разрешённого корня. Распаковка не выпускает файл через ../ или абсолютное имя.
Секреты не выводятся в лог и не встраиваются во frontend; HF token не пересылается
на произвольное зеркало. Ограничения HTTP маршрута и входа графа различаются:
URL из workflow явно вводится владельцем, а route вызывается внешним браузером.

В импортированном коде уже есть утверждённые адаптации чужого runtime:
[ts_pasted_media_fix.py](../../ts_pasted_media_fix.py) расширяет LoadImage
INPUT_TYPES для подпапок input; [compat/proactor_guard.py](../../compat/proactor_guard.py)
обрабатывает Windows asyncio transport. Обе подключает _apply_core_patches
в корневом загрузчике и допускают повторную установку. Это существующие
исключения, не общее разрешение добавлять monkey-patch ComfyUI или stdlib.

## Python и логи

Python 3.10+ по requires-python, pathlib, явные типы нетривиального публичного
API, полезные docstrings, конкретные исключения. Логировать через logging с
TS-префиксом, без ANSI/emoji/секретов и без лишних полных пользовательских путей.
DEBUG — внутренняя диагностика, INFO — операция, WARNING — восстанавливаемая
проблема, ERROR — failure. Подробности получения логов —
[диагностика](../operations/troubleshooting.md).
