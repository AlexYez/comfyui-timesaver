## Метод статической проверки

Охват: собственные Markdown-файлы непосредственно в корне, `doc/**`, `project_memory/**`, `js/docs/**`; в заключительный проход дополнительно включён `nodes/text/prompt_library/README.md`. Исторический снимок до добавления этого отчёта обработал **461 файл**, включая **189 файлов памяти**, и **1721 относительную цель** Markdown-ссылок/изображений и HTML `href`/`src`.

Проверялось:

- существование относительных целей с разрешением относительно страницы-источника и percent-decoding;
- локальные Markdown anchors: явные HTML id/name, заголовки, повторяющиеся заголовки и Unicode slug;
- размер каждого файла как UTF-8 на диске: не более 25 000 байт;
- YAML frontmatter памяти через PyYAML: поля `name`, `description`, `metadata`, уникальность имён;
- достижимость каждой memory-страницы от `MEMORY.md` по ссылкам и непосредственное включение каждой темы в README/index-hub;
- упомянутые пути: автоматический список отсутствующих inline-code кандидатов с последующей ручной классификацией путей исходников, истории, лаборатории и runtime.

Скрипт воспроизведения: локальный `tests/.cache/memory-consolidation/cold-check.py`; JSON-результат находится рядом. Это игнорируемая временная лаборатория, не зависимость публичного клона. Команда локального повторения — `python tests/.cache/memory-consolidation/cold-check.py`.

Ограничения: это целевая статическая проверка обычного Markdown репозитория, а не универсальный Markdown-парсер. Проверка существования файлов не подтверждает фактическое поведение указанной функции. Внешние URL, старые числовые anchors строк исходников и сторонние API не проверялись сетевыми запросами. Plain-code текст не является Markdown-ссылкой; сокращённый путь оценивался по контексту, а не объявлялся отсутствующим файлом автоматически.

- примеры, glob, routes и выражения вроде `width/height`: синтаксически похожий на путь текст сам по себе не обещает файл.
