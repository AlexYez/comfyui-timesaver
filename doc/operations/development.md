# Установка, запуск и разработка

Пак запускается загрузчиком ComfyUI; самостоятельного `main.py`, npm-проекта или шага сборки frontend здесь нет. Источники: [точка входа](../../__init__.py), [зависимости](../../requirements.txt), [метаданные](../../pyproject.toml).

## Чистая установка

Через ComfyUI Manager найдите Timesaver и установите пак. Для ручной установки выполните из каталога ComfyUI:

```sh
cd custom_nodes
git clone https://github.com/AlexYez/comfyui-timesaver
cd comfyui-timesaver
python -m pip install -r requirements.txt
```

Здесь и далее `python` означает **тот интерпретатор, которым запускается ComfyUI**, а не любой Python в PATH. В Windows portable это обычно встроенный Python дистрибутива; имя каталога зависит от сборки. Пример конкретной машины — в [окружении](environment.md#машина-владельца-проверено-2026-11-02).

Требования и минимальные версии берите из `pyproject.toml`, не из старых записей памяти. Сначала установите сам ComfyUI и его зависимости. У пака нет собственного wheel/build-процесса, необходимого пользователю: он загружается из `custom_nodes`.

## Запуск

Запустите ComfyUI обычным для вашей установки способом. При запуске из исходников команда относится к **каталогу ComfyUI**:

```sh
python main.py
```

Откройте адрес, который сообщил сервер. В интерфейсе найдите ноду по префиксу `TS`. Имена нод и входов — часть сохранённого workflow; их нельзя переименовывать при косметической правке.

На рабочей машине владельца агент **не перезапускает сервер без прямой команды**. Изменения Python вступают в силу после согласованного рестарта, изменения JS — после копирования в установленный пак и обновления страницы. Подробности требований — [память владельца](../../project_memory/owner/README.md).

## Обновление

Из установленного клона:

```sh
git status --short
git pull --ff-only
python -m pip install -r requirements.txt
```

Если есть локальные правки, сначала выясните их происхождение и сохраните резервную копию. Не применяйте `reset --hard` или удаление клона как обычный способ обновления. Перезапуск выполняет владелец или агент по прямой команде.

## Дополнительные зависимости

Они перечислены в [optional-dependencies](../../pyproject.toml). Нода должна сообщать об отсутствии необязательной библиотеки, не ломая загрузку остальных нод.

| Возможность | Источник инструкции |
|---|---|
| NVIDIA RTX Video | [TS RTX Upscaler](../../js/docs/TS_RTX_Upscaler/ru.md): нужен индекс NVIDIA. |
| DLSS v9 и внешний v21 | [TS DLSS Upscaler](../../js/docs/TS_DLSSUpscaler/ru.md): Windows/RTX, разные способы установки движка. |
| Gemma на LiteRT | [TS Super Prompt RT](../../js/docs/TS_SuperPromptRT/ru.md): отдельный LiteRT runtime. |
| Qwen и квантизация | [TS Qwen 3](../../js/docs/TS_Qwen3_VL_V3/ru.md): доступность точности зависит от платформы и библиотек. |
| Музыка и TTS | [Справочник](../nodes/README.md): раздел Audio и конкретная нода. |

## Как продолжать разработку

1. Из корневого [AGENTS.md](../../AGENTS.md) откройте только правила нужной подсистемы.
2. Сверьте существующую схему с [контрактами](../../tests/contracts/node_contracts.json).
3. Изменяйте dev checkout, а не установленный рабочий клон.
4. Проведите [проверки по теме](testing.md), обновите справку и память, если изменились решения.
5. Коммит и push — только по команде владельца; затем следуйте [процедуре релиза](release.md).
