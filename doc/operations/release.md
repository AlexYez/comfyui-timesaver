# Релиз и обновление установленного пака

Версия задаётся в [pyproject.toml](../../pyproject.toml). Её изменение запускает существующую публикацию через [publish_action.yml](../../.github/workflows/publish_action.yml); сам workflow этой консолидацией не менялся.

## Разрешение владельца

Коммит и push выполняются по прямой команде. «Патч» означает увеличить последнюю цифру SemVer, «минорный» — среднюю с обнулением последней, «мажорный» — первую. Не выбирайте новый номер при обычной реализации. Дословные требования и причины — в [памяти владельца](../../project_memory/owner/README.md).

## Последовательность

1. Прочитайте `git status --short` и diff; отделите свою правку от посторонних файлов. Получите актуальные refs origin. Не меняйте рабочую ветку пользователя без необходимости.
2. Проведите [проверки по теме](testing.md). Полный suite не входит в релиз автоматически. Отдельно сообщите непроверенное.
3. По согласованному типу бампа измените версию в `pyproject.toml`, добавьте запись в [историю изменений](../../CHANGELOG.md). Корневые README ссылаются на источник версии и больше не требуют синхронного ручного бампа значков.
4. Добавляйте файлы в индекс явным списком. Не используйте `git add -A` вслепую: локальные токены, модели и отчёты не должны попасть в релиз. Сверьте `git diff --cached --check` и `git diff --cached --stat`.
5. Создайте понятный коммит без AI/Co-Authored-By footer. Выполните обычный push, без force.
6. Проверьте GitHub run и **сам шаг `Publish Custom Node`**, а не только зелёную проверку версии. Пример read-only проверки:

```sh
gh run list --repo AlexYez/comfyui-timesaver --workflow publish_action.yml --limit 3
gh run view RUN_ID --repo AlexYez/comfyui-timesaver
```

`RUN_ID` здесь — идентификатор нужного запуска, не готовая команда с конкретным числом. Если версия не менялась, workflow может успешно завершиться без публикации.

7. После успешного push обновите установленный клон через `git pull --ff-only`. Если туда копировали предварительные изменения, сохраните backup и сравните содержимое: stash/drop допустимы только после проверки, что зафиксированный релиз содержит эти изменения. Посторонние правки не удаляйте.
8. Сверьте SHA dev/origin/runtime, состав файлов и чистоту клона. Python-изменения потребуют рестарта ComfyUI **по прямой команде владельца**; сам push разрешения на рестарт не даёт.

## Публикация и упаковка

Внешняя action закреплена на SHA в текущем workflow; не заменяйте её по старому совету памяти о `@main`. Важно сохранить работающий процесс публикации, а не «обновить» его без задачи.

Документация, инструкции и память должны быть доступны из клона. Локальная лаборатория, архивные zip, модели, результаты и секреты остаются исключёнными из Git. Проверьте [границы окружения](environment.md) перед добавлением новых файлов.

Подготовка документации сама по себе не разрешает публикацию: для коммита и push действует то же требование прямой команды владельца.
