# Проверки и их границы

Клон содержит исходники, [настройки Ruff](../../pyproject.toml), [workflow CI](../../.github/workflows/ci.yml) и [снимок 88 контрактов](../../tests/contracts/node_contracts.json). Полная локальная лаборатория pytest, Playwright и вспомогательные Python-скрипты исключены из Git. Не считайте их обязательным содержимым клона.

## Проверки, доступные из чистого клона

В корне пака, Python-окружением ComfyUI:

```sh
python -m compileall -q nodes compat __init__.py ts_dependency_manager.py ts_pasted_media_fix.py
python -m ruff check nodes/video/dlss/ts_dlss_upscaler.py
```

Во второй команде указан пример затронутого файла: замените его файлами своей правки. Ruff — отдельный инструмент разработчика; при отсутствии установите его в выбранное dev-окружение. Не устанавливайте зависимости в случайный системный Python.

Синтаксис JavaScript проверяют в режиме ES modules; в репозитории нет `package.json`, `npm run build`, `npm run test` и каталога Playwright `tests/e2e`. Такие команды в старом CLAUDE были шаблоном, а не работающей инфраструктурой.

Статическая проверка подтверждает синтаксис, но не импорт через V3 loader, качество модели, сохранение файлов или поведение интерфейса.

## Локальная лаборатория владельца

На машине владельца доступны игнорируемые Git каталоги с pytest-тестами и инструментами. Они не перенесены в публичный репозиторий этой документационной задачей. Старые записи с конкретными именами таких файлов описывают локальную лабораторию; в чистом клоне их может не быть.

Для имеющегося локального тестового файла команда имеет вид:

```sh
python -m pytest tests/test_dlss_upscaler.py -q
```

Объём: затронутая нода, используемые общие модули и другие потребители этих модулей. Не запускайте несколько конкурирующих pytest-процессов. Для документационной правки нужны сверка фактов, ссылок, размеров и неизменности кода, а не GPU-прогоны.

**Полный набор — только по прямой команде владельца. Релиз не является исключением.** Причина и дословные указания — в [требованиях владельца](../../project_memory/owner/README.md).

## Живая проверка

Подключайтесь к уже работающему серверу. Тестовый скрипт не должен запускать или останавливать ComfyUI. Для проверки Python-изменений сначала нужен разрешённый владельцем рестарт; до него API отражает старый код в памяти процесса.

У сохранителей подтверждайте **новый файл на диске**, а не только превью. В UI проверяйте нужный язык и режим нод. Не называйте непроведённый сценарий проверенным.

## GitHub Actions: код и состояние сервиса

На 2026-11-02 проверено командой `gh workflow list --repo AlexYez/comfyui-timesaver --all`:

| Workflow | Файл в клоне | Состояние сервиса |
|---|---|---|
| CI | [ci.yml](../../.github/workflows/ci.yml): push/PR, compile/lint и CPU import smoke | `disabled_manually`; автоматически не запускается. |
| macOS smoke | [macos_smoke.yml](../../.github/workflows/macos_smoke.yml): `workflow_dispatch` | `active`, только ручной запуск. |
| Registry publish | [publish_action.yml](../../.github/workflows/publish_action.yml): push с изменением pyproject или вручную | `active`. |

Это снимок внешнего состояния, не вечная гарантия. Наличие push-триггера в YAML не означает, что workflow включён. Не включайте CI и не запускайте платные/долгие проверки без команды. Подробности публикации — [релиз](release.md).
