# TS Image Studio — устройство подсистемы

Карта самой большой ноды пака. Отвечает на вопросы «где что лежит», «как
проходит один запуск», «куда добавлять новое» и «обо что здесь уже спотыкались».

Читать вместе с: [`doc/IMAGE_STUDIO_PLAN.md`](../../../doc/IMAGE_STUDIO_PLAN.md)
(проектные решения), [`doc/THEME.md`](../../../doc/THEME.md) (дизайн-система),
[`CLAUDE.md`](../../../CLAUDE.md) §12.5–12.6 (правила фронтенда).

---

## 1. Что это

Студия — **фронтенд-приложение**, которое собирает обычные ComfyUI-графы и
отправляет их в `/prompt`. Нода на графе — только представитель приложения:
кнопка «Open Interface» и выход IMAGE.

Из этого следуют три инварианта, на которых держится всё остальное:

1. **Никакой своей очереди и своего исполнения.** Запуск студии неотличим от
   запуска из графа: та же очередь, та же отмена, тот же кэш моделей.
2. **Модели не зашиты в код.** Что умеет студия — определяют файлы
   `js/image/studio/workflows/**.json`. Добавить модель = добавить файл.
3. **Приложение не знает про конкретные семейства.** Дека рисуется из
   манифеста бэкенда через реестр контролов; ни один `if (family === ...)` в
   слое приложения не появляется.

## 3. Путь одного запуска

```
клик Run
  → _app.js: собирает runValues из контролов (только те, что объявил бэкенд)
  → стили из промпт-панели дописываются к промпту
  → семейство с дизайнером (Ideogram) сперва получает design/caption
  → buildStudioState(): снимок сессии
  → patchBackend(): значения в маркеры, ветки пустых опций удаляются,
                    перед выходом врезается TS_ImagePromptInjector
  → runner.submit(): POST /prompt + extra_data.extra_pnginfo.ts_studio
  → ComfyUI исполняет обычный граф
  → TS_StudioOutput сохраняет в output/images/<модель>/<модель>_<дата>_<время>
  → результат приходит в галерею сессии
```

Три вещи, которые легко упустить:

- **Что уходит в граф — только объявленные параметры.** `run()` фильтрует по
  `target.spec.params`; лишнее молча отбрасывается, а не ломает граф.
- **Промпт пишется дважды**: в маркер (для генерации) и через
  `TS_ImagePromptInjector` в метадату (чтобы браузеры видели текст).
- **Снимок `ts_studio`** едет в `extra_data.extra_pnginfo`, потому что студия
  не отправляет LiteGraph-воркфлоу вообще.

## 4. Бэкенды: как устроен один файл

Файл — обычный API-граф ComfyUI плюс нода `TS_StudioManifest`, чей JSON
описывает деку. Индекс — `workflows/index.json`.

```
семейство/режим.json
  studio_manifest → {id, family, family_label, mode, order, controls[],
                     refs, requires[], models[], literals{}, designer{}}
  p_*             → маркеры (значения подставляет студия)
  studio_out      → TS_StudioOutput
```

`models[]` — как найти файл модели: `{title, input, folder, match}`. Если файл
из графа установлен, берётся он; иначе — первый подходящий под regex. Отсюда
правило: **литерал в графе важнее матчера**, и именно он должен указывать на
модель из ваших рабочих воркфлоу.

### 4.1 Что сейчас есть

| Семейство | t2i | edit | inpaint | upscale | Особенность |
|---|:--:|:--:|:--:|:--:|---|
| `flux2-klein` | ✓ | ✓ | ✓ | ✓ | инпейнт через `TSSmartInpaint` (кроп + референс объекта) |
| `z-image` | ✓ | | ✓ | ✓ | апскейл с tile-ControlNet |
| `krea2` | ✓ | | ✓ | ✓ | |
| `qwen-image` | ✓ | | ✓ | ✓ | Lightning-LoRA, 4 шага |
| `qwen-image-edit` | | ✓ | | | |
| `ideogram` | ✓ | | ✓ | ✓ | всё ведёт нода-дизайнер; пресеты Quality/Normal/Turbo |
| `seedvr2` | | | | ✓ | реставратор, не дорисовывает |

### 4.2 Чужие ноды под капотом

Студия ничего не реализует сама, если в паке или в ComfyUI это уже есть.

**Из пака:** `TSSmartInpaint`, `TS_IdeogramDesigner`, `TS_MultiReference`,
`TS_ImageTileSplitter` / `TS_ImageTileMerger`,
`TS_ImageBatchToImageList` / `TS_ImageListToImageBatch`.

**Из ComfyUI и сторонних:** `KSampler`, `SamplerCustomAdvanced`, `CFGGuider`,
`DualModelGuider`, `CFGOverride`, `CFGNorm`, `Ideogram4Scheduler`,
`Flux2Scheduler`, `SplitSigmasDenoise`, `ZImageFunControlnet`,
`ModelPatchLoader`, `LanPaint_*`, `SeedVR2*`, загрузчики и VAE.

Отсюда важное следствие: **обновление этих нод может изменить поведение
студии**. При изменении их входов правьте графы бэкендов, а не код приложения.

## 5. Ключевые механизмы

### 5.1 Дека строится из данных

`manifest.controls[]` → `getControlRenderer(kind)` → `{element, get, set}`.
Контракт контрола: **`set()` обязан сообщить о значении через `ctx.onChange`**
— дека пересобирается на каждой смене модели и режима, и липкие значения
возвращаются именно вызовом `set()`. Молчаливый `set()` однажды стоил нам
пустого промпта в графе при заполненном поле ввода
(guard: `tests/test_studio_controls_contract.py`).

Липкие виды: `prompt, seed, size, loras, refs` (`STICKY_KINDS` в `_app.js`).

Вид `choice` умеет нести **набор** значений в одной опции (пресеты Ideogram
двигают steps/mu/std вместе).

### 5.2 Режимы интерфейса ≠ режимы бэкендов

`UI_MODES`: `generate = [t2i, edit]`, `inpaint`, `upscale`. В Generate
заполненный слот референса сам переводит запуск на edit-граф семейства.

### 5.3 Два маршрута перетаскивания

- **HTML5**: `makeDropZone()` + реестр источников (файлы ОС, карточки Artius,
  галерея студии, URL превью).
- **Указателем**: `makePointerDragSource()` — призрак за курсором, подсветка
  зоны, приём через тот же `onDrop`. Зоны помечены `data-ts-dropzone`.

Второй маршрут появился потому, что нативный drag из встроенной панели
браузера оказался ненадёжен, а проверить его в headless нельзя вовсе.

Дроп в Inpaint и Upscale — **всегда источник**, даже если это студийный PNG.
Восстановление сессии — отдельное действие.

### 5.4 Восстановление сессии

Снимок в чанке `ts_studio`: бэкенд, семейство, режим интерфейса, значения,
LoRA, стили, размер, пути исходников, id сессии. Восстанавливают:
кнопка «Повторить» под картинкой, дроп PNG в Generate, кнопка **R** и пункт
меню в Artius.

Ушедшие бэкенды переводятся картой `RETIRED` в `applyStudioState`
(`secondpass/upscale` → `z-image/upscale`).

## 6. Грабли, на которых уже стояли

1. **`pickLocaleStrings` возвращает новый объект.** Сравнение
   `STRINGS.ru === t` не работает никогда — язык берётся из `getUiLanguage()`.
   Иначе все подписи из манифестов уходят в английский.
2. **Скрытый виджет ≠ невидимый.** `widget.type = "hidden"` не убирает строку
   входа, которую рисует фронтенд: нужен `hideWidget()` из `js/_dom_widget.js`
   плюс `node.removeInput()`. И то же самое — для нод, сохранённых до
   изменения схемы: LiteGraph восстанавливает их по файлу.
3. **Оверлей и фокус.** Полноэкранный оверлей паркует фокус, чтобы глушить
   горячие клавиши графа; во время перетаскивания это его отменяет — фокус
   не трогается между `dragstart` и `dragend`.
4. **Живая копия ≠ dev-папка.** `custom_nodes/comfyui-timesaver` — отдельный
   клон. Перед любым живым тестом: `python tools/verify_live_sync.py --sync`.
5. **Ветку не смешивать с рецептом.** Меняя модель у семейства, правьте
   литерал в графе; матчер `models[].match` — только запасной путь.

## 7. Связь с Artius Browser

Две точки, обе необязательные, ни один пак не импортирует другой.

**Действия над ассетом.** Студия публикует записи в `window.tsAssetActions`
(`_asset_actions.js`):

| id | Что делает | Где видно |
|---|---|---|
| `ts-image-studio.recreate` | восстановить сессию | кнопка **R**, меню |
| `ts-image-studio.use-source` | отдать картинку в открытый режим | кнопка **S**, меню |

Контракт: `{id, label:{en,ru}, order, supports(asset), run(asset)}`;
`asset = {id, filename, url, type, extension}`; ответ `{ok, message}`.

**Тег студии.** Artius при скане читает чанк `ts_studio` и показывает бейдж
«режим · модель» на превью. Детали — в его
`doc/STUDIO_INTEGRATION.md`.

## 8. Куда добавлять новое

| Задача | Куда |
|---|---|
| Новая модель/режим | новый JSON в `workflows/`, строка в `index.json` |
| Новый вид контрола | `registerControlKind()` в `_controls.js` |
| Новый источник дропа | `registerDropSource()` в `_dnd.js` |
| Новый провайдер библиотеки | `registerAssetProvider()` в `_assets.js` |
| Новый внешний редактор | `registerEditorProvider()` в `_editors.js` |
| Новая настройка | `SETTINGS` в `_settings.js` + чтение там, где применяется |
| Новое действие для браузеров | `publishAssetAction()` в `ts-image-studio.js` |

Правило: если для задачи пришлось трогать `_app.js` — вероятно, вы добавляете
не то и не туда. Слой приложения только связывает.
