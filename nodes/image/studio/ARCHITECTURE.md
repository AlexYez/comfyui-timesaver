# TS Image Studio — устройство подсистемы

Карта самой большой ноды пака. Отвечает на вопросы «где что лежит», «как
проходит один запуск», «куда добавлять новое» и «обо что здесь уже спотыкались».

Читать вместе с: [`doc/IMAGE_STUDIO_PLAN.md`](../../../doc/IMAGE_STUDIO_PLAN.md)
(проектные решения), [`doc/THEME.md`](../../../doc/THEME.md) (дизайн-система),
[`CLAUDE.md`](../../../CLAUDE.md) §12.5–12.6 (правила фронтенда).

---

## 1. Что это

Студия — **фронтенд-приложение**, которое собирает обычные ComfyUI-графы и
отправляет их в `/prompt`. Нода на графе — только представитель приложения:
кнопка «Open Interface» и выход IMAGE.

Из этого следуют три инварианта, на которых держится всё остальное:

1. **Никакой своей очереди и своего исполнения.** Запуск студии неотличим от
   запуска из графа: та же очередь, та же отмена, тот же кэш моделей.
2. **Модели не зашиты в код.** Что умеет студия — определяют файлы
   `js/image/studio/workflows/**.json`. Добавить модель = добавить файл.
3. **Приложение не знает про конкретные семейства.** Дека рисуется из
   манифеста бэкенда через реестр контролов; ни один `if (family === ...)` в
   слое приложения не появляется.

## 3. Путь одного запуска

```
клик Run
  → _app.js: собирает runValues из контролов (только те, что объявил бэкенд)
  → стили из промпт-панели дописываются к промпту
  → семейство с дизайнером (Ideogram) сперва получает design/caption
  → buildStudioState(): снимок сессии
  → patchBackend(): значения в маркеры, ветки пустых опций удаляются,
                    перед выходом врезается TS_ImagePromptInjector
  → runner.submit(): POST /prompt + extra_data.extra_pnginfo.ts_studio
  → ComfyUI исполняет обычный граф
  → TS_StudioOutput сохраняет в output/images/<модель>/<модель>_<дата>_<время>
  → результат приходит в галерею сессии
```

Три вещи, которые легко упустить:

- **Что уходит в граф — только объявленные параметры.** `run()` фильтрует по
  `target.spec.params`; лишнее молча отбрасывается, а не ломает граф.
- **Промпт пишется дважды**: в маркер (для генерации) и через
  `TS_ImagePromptInjector` в метадату (чтобы браузеры видели текст).
- **Снимок `ts_studio`** едет в `extra_data.extra_pnginfo`, потому что студия
  не отправляет LiteGraph-воркфлоу вообще.

## 4. Бэкенды: как устроен один файл

Файл — обычный API-граф ComfyUI плюс нода `TS_StudioManifest`, чей JSON
описывает деку. Индекс — `workflows/index.json`.

```
семейство/режим.json
  studio_manifest → {id, family, family_label, mode, order, controls[],
                     refs, requires[], models[], literals{}, designer{}}
  p_*             → маркеры (значения подставляет студия)
  studio_out      → TS_StudioOutput
```

`models[]` — как найти файл модели: `{title, input, folder, match}`. Если файл
из графа установлен, берётся он; иначе — первый подходящий под regex. Отсюда
правило: **литерал в графе важнее матчера**, и именно он должен указывать на
модель из ваших рабочих воркфлоу.

### 4.1 Что сейчас есть

| Семейство | t2i | edit | inpaint | outpaint | upscale | Особенность |
|---|:--:|:--:|:--:|:--:|:--:|---|
| `flux2-klein` | ✓ | ✓ | ✓ | ✓ | ✓ | инпейнт через `TSSmartInpaint`; расширение кадра — только здесь |
| `z-image` | ✓ | | ✓ | | ✓ | апскейл с tile-ControlNet |
| `krea2` | ✓ | | ✓ | | ✓ | |
| `qwen-image` | ✓ | | ✓ | | ✓ | Lightning-LoRA, 4 шага |
| `qwen-image-edit` | | ✓ | | | | |
| `ideogram` | ✓ | | ✓ | | ✓ | всё ведёт нода-дизайнер; пресеты Quality/Normal/Turbo |
| `seedvr2` | | | | | ✓ | реставратор, не дорисовывает |

**Раздел живёт, пока его держит хотя бы одно семейство.** `availableModes()` в
`_app.js` собирает рельс по тем режимам, которые реально есть у загруженных
бэкендов, и пересобирает его после каждой перечитки: выключили пак Klein —
вкладка «Outpaint» исчезает сразу, включили — возвращается. Пустых вкладок в
студии не бывает: модели приезжают паками, и раздел без модели — обещание,
которое нечем выполнить.

### 4.1.1 Расширение кадра: как это устроено

Повторяет рабочий workflow владельца (`Outpaint.json`) и держится на трёх
вещах, каждая из которых обязательна:

1. **`TS_ResolutionSelector`** строит новый кадр: вписывает исходник по центру
   холста выбранной пропорции. Всё, что вокруг, — то самое пустое место,
   которое предстоит дорисовать. Пропорция и бюджет мегапикселей приходят из
   деки, а не зашиты в граф.
2. **`ReferenceLatent`** удерживает исходную часть. Сэмплер идёт по ВСЕМУ
   холсту (у Flux 2 Klein нет частичного денойза), и без референс-латента он
   перерисовал бы и то, что расширять не просили.
3. **`TS_Color_Match`** возвращает палитру, сверяясь с ИСХОДНОЙ картинкой, а не
   с холстом: проход по всему кадру уводит цвет, и без этого шага расширенная
   часть не сходится с оригиналом.

На сцене до запуска стоит рамка будущего кадра (`js/_studio/_outframe.js`):
исходник на месте, новые области заштрихованы, под рамкой — итоговый размер.
«21:9» само по себе ничего не говорит человеку о том, сколько допишется слева
и справа; первое же превью рамку снимает — дальше кадр говорит сам за себя.

### 4.2 Чужие ноды под капотом

Студия ничего не реализует сама, если в паке или в ComfyUI это уже есть.

**Из пака:** `TSSmartInpaint`, `TS_IdeogramDesigner`, `TS_MultiReference`,
`TS_ImageTileSplitter` / `TS_ImageTileMerger`,
`TS_ImageBatchToImageList` / `TS_ImageListToImageBatch`.

**Из ComfyUI и сторонних:** `KSampler`, `SamplerCustomAdvanced`, `CFGGuider`,
`DualModelGuider`, `CFGOverride`, `CFGNorm`, `Ideogram4Scheduler`,
`Flux2Scheduler`, `SplitSigmasDenoise`, `ZImageFunControlnet`,
`ModelPatchLoader`, `LanPaint_*`, `SeedVR2*`, загрузчики и VAE.

Отсюда важное следствие: **обновление этих нод может изменить поведение
студии**. При изменении их входов правьте графы бэкендов, а не код приложения.

## 5. Ключевые механизмы

### 5.1 Дека строится из данных

`manifest.controls[]` → `getControlRenderer(kind)` → `{element, get, set}`.
Контракт контрола: **`set()` обязан сообщить о значении через `ctx.onChange`**
— дека пересобирается на каждой смене модели и режима, и липкие значения
возвращаются именно вызовом `set()`. Молчаливый `set()` однажды стоил нам
пустого промпта в графе при заполненном поле ввода
(guard: `tests/test_studio_controls_contract.py`).

Липкие виды: `prompt, seed, size, loras, refs` (`STICKY_KINDS` в `_app.js`).

Вид `choice` умеет нести **набор** значений в одной опции (пресеты Ideogram
двигают steps/mu/std вместе).

### 5.1.1 Память параметров

Дека пересобирается на каждом переключении модели и режима, поэтому всё
введённое живёт не в контролах, а в `js/_studio/_memory.js` (localStorage,
ключ `ts.studio.values`). Две области:

| Область | Что в ней | Почему |
|---|---|---|
| общая | промпт, сид, формат, LoRA, стили | это про то, **что** делают, а не про то, каким графом |
| по графу | denoise, steps, scale, пресеты, переключатели | «сила перерисовки» в Inpaint и в Upscale — разные числа |

Значение пишется **в момент изменения**, а не только при разборке деки: вкладку
могут закрыть. При сборке деки запомненное читается **до** создания контрола —
контрол при рождении объявляет свой дефолт, и эта запись легла бы поверх того,
что мы собираемся восстановить.

Ключ снимка — не `activeBackend` (он к началу пересборки уже указывает на новый
граф), а `deckGraphId`, зафиксированный вместе с декой. Иначе значения Inpaint
уезжали в Upscale.

Референсы держатся только в пределах сеанса: это ссылки на загруженные файлы, и
восстановленное имя из прошлого месяца показало бы битую миниатюру.

Сброс — «Настройки → Запомненные настройки». На время сброса снимок выключается
флагом `suppressCapture`, иначе он вернул бы значения в только что очищенную
память.

### 5.2 Режимы интерфейса ≠ режимы бэкендов

`UI_MODES`: `generate = [t2i, edit]`, `inpaint`, `upscale`. В Generate
заполненный слот референса сам переводит запуск на edit-граф семейства.

### 5.3 Два маршрута перетаскивания

- **HTML5**: `makeDropZone()` + реестр источников (файлы ОС, карточки Artius,
  галерея студии, URL превью).
- **Указателем**: `makePointerDragSource()` — призрак за курсором, подсветка
  зоны, приём через тот же `onDrop`. Зоны помечены `data-ts-dropzone`.

Второй маршрут появился потому, что нативный drag из встроенной панели
браузера оказался ненадёжен, а проверить его в headless нельзя вовсе.

Дроп в Inpaint и Upscale — **всегда источник**, даже если это студийный PNG.
Восстановление сессии — отдельное действие.

### 5.4 Восстановление сессии

Снимок в чанке `ts_studio`: бэкенд, семейство, режим интерфейса, значения,
LoRA, стили, размер, пути исходников, id сессии. Восстанавливают:
кнопка «Повторить» под картинкой, дроп PNG в Generate, кнопка **R** и пункт
меню в Artius.

Ушедшие бэкенды переводятся картой `RETIRED` в `applyStudioState`
(`secondpass/upscale` → `z-image/upscale`).

Работы сессии после перезагрузки страницы поднимает `restoreResults`
(`_studio/_session.js`) — из истории сервера, сверяя **поле `session` в том же
снимке**, а не путь файла. Файлы лежат в `output/images/<семейство>/`, то есть
о сессии не говорят ничего; попытка искать их по папке `ts_studio/<сессия>/`
молча давала пустую галерею до 2026-08-04. Порядок — как в истории,
хронологический.

## 6. Грабли, на которых уже стояли

1. **`pickLocaleStrings` возвращает новый объект.** Сравнение
   `STRINGS.ru === t` не работает никогда — язык берётся из `getUiLanguage()`.
   Иначе все подписи из манифестов уходят в английский.
2. **Скрытый виджет ≠ невидимый.** `widget.type = "hidden"` не убирает строку
   входа, которую рисует фронтенд: нужен `hideWidget()` из `js/_dom_widget.js`
   плюс `node.removeInput()`. И то же самое — для нод, сохранённых до
   изменения схемы: LiteGraph восстанавливает их по файлу.
3. **Оверлей и фокус.** Полноэкранный оверлей паркует фокус, чтобы глушить
   горячие клавиши графа; во время перетаскивания это его отменяет — фокус
   не трогается между `dragstart` и `dragend`.
4. **Живая копия ≠ dev-папка.** `custom_nodes/comfyui-timesaver` — отдельный
   клон. Перед любым живым тестом: `python tools/verify_live_sync.py --sync`.
5. **Ветку не смешивать с рецептом.** Меняя модель у семейства, правьте
   литерал в графе; матчер `models[].match` — только запасной путь.
6. **Установленный набор молча перекрывает встроенный бэкенд.** Файл из
   `user/default/ts-studio/workflows/**` с тем же `manifest.id` побеждает
   встроенный — так работает доставка платных наборов. Правки графа в
   репозитории при этом не действуют, и ничто об этом не сообщает. Ловит
   `tools/verify_live_sync.py` (строки «перекрытие …»). Отключить набор
   переименованием папки нельзя — листинг рекурсивный, каталог нужно вынести
   из-под `workflows/`.
7. **Значение вне диапазона контрола пропадает молча.** Умолчание ползунка не
   зажималось в `[min, max]`: манифест просил 60 при потолке 50, ползунок
   вставал в конец, а в граф уходило старое значение. Зажим добавлен в
   `_controls.js`; поднимая умолчание, поднимайте и `max`.
8. **`node.properties` обнуляются посреди работы.** ComfyUI пересобирает граф
   у себя, и узел получает свойства из снимка на диске. Всё, что студия
   записала после него (сессия, путь результата), исчезает. Сессия дублируется
   в карте `sessionByNode` внутри `ts-image-studio.js`; для любого нового
   долгоживущего значения нужен такой же второй канал.
9. **Доработка не увеличивает вырез.** Увеличенный вырез — интерполированные
   пиксели; модель «дорисовывает по ним детали» и запекает результат в сетку
   трещин. Замерено по одному изменению за раз: ни LanPaint, ни Differential
   Diffusion, ни тип маски к этому отношения не имели — только масштаб.
10. **LanPaint думает только при полной замене.** На доработке его внутренний
   цикл уводит результат вдвое дальше запрошенной силы. `LanPaint_NumSteps = 0`
   численно совпадает с обычным `KSampler` (0.057 из 255), поэтому второй ветки
   в графе не понадобилось — приложение шлёт ноль, когда режим не «замена».
11. **Резолюшн-зависимый планировщик должен считать по вырезу.**
   `Ideogram4Scheduler` сдвигает сигмы по разрешению; ему подавался размер
   исходного кадра, а сэмплируется вырез — модель получала чужое расписание
   шума и сваливалась в тёмное пятно.

## 7. Связь с Artius Browser

Две точки, обе необязательные, ни один пак не импортирует другой.

**Действия над ассетом.** Студия публикует записи в `window.tsAssetActions`
(`_asset_actions.js`):

| id | Что делает | Где видно |
|---|---|---|
| `ts-image-studio.recreate` | восстановить сессию | кнопка **R**, меню |
| `ts-image-studio.use-source` | отдать картинку в открытый режим | кнопка **S**, меню |

Контракт: `{id, label:{en,ru}, order, supports(asset), run(asset)}`;
`asset = {id, filename, url, type, extension}`; ответ `{ok, message}`.

**Тег студии.** Artius при скане читает чанк `ts_studio` и показывает бейдж
«режим · модель» на превью. Детали — в его
`doc/STUDIO_INTEGRATION.md`.

## 8. Куда добавлять новое

| Задача | Куда |
|---|---|
| Новая модель/режим | новый JSON в `workflows/`, строка в `index.json` |
| Платная модель | семейство в приватный репозиторий, запись в его `packs.json` |
| Новый вид контрола | файл в `js/_studio/controls/` + строка в списке `_controls.js` |
| Новый источник дропа | `registerDropSource()` в `_dnd.js` |
| Новый провайдер библиотеки | `registerAssetProvider()` в `_assets.js` |
| Новый внешний редактор | `registerEditorProvider()` в `_editors.js` |
| Новая настройка | `SETTINGS` в `_settings.js` + чтение там, где применяется |
| Новое действие для браузеров | `publishAssetAction()` в `ts-image-studio.js` |

Правило: если для задачи пришлось трогать `_app.js` — вероятно, вы добавляете
не то и не туда. Слой приложения только связывает.

## 9. Подписка: пропуск и наборы

Пак остаётся бесплатным целиком; платными бывают **наборы** — архивы графов,
которые доезжают отдельно.

### 9.1 Пропуск

Механизм не новый: его уже носит ComfyUI-лаунчер, а `nodes/_pass.py` —
Python-двойник его `license.js`. Код месяца одинаков для всех подписчиков и
разный по уровням (1 base, 2 pro, 3 ultimate). По коду скачивается токен
`base64url(payload).base64url(подпись)`, подписанный Ed25519; публичный ключ
зашит в паке. Внутри `payload.sec` лежат секреты уровней ≤ своего.

Срок: `expiresAt = min(момент активации + 35 дней, notAfter)` — месяц идёт с
активации, а не с выпуска. Пропуск лежит в `user/default/ts-pass/pass.json`;
если ComfyUI запущен внутри лаунчера, пропуск подхватывается оттуда и второй
раз код не спрашивается.

### 9.2 Наборы

Набор — zip из граф-файлов и текста; ничего исполняемого. Ставится в
`user/default/ts-studio/workflows/<id>/`, то есть в ту же user-полку, которую
загрузчик бэкендов и так читает и предпочитает встроенным. Поэтому доставка
не потребовала менять чтение бэкендов вообще.

Каталог `index.json` публичный и незашифрованный: он и есть витрина. Платные
архивы зашифрованы AES-GCM ключом `sha256("ts-studio-pack:" + секрет уровня)`
— адрес может быть каким угодно публичным. Второй поддерживаемый вариант —
неугадываемая папка `paid/<секрет>/` без шифрования, для файлового хостинга
без листинга; выбор делает флаг `--encrypt` при сборке.

Распаковка считает архив враждебным: `..`, абсолютные пути, симлинки и всё,
что не данные, отвергаются целиком, а подмена папки происходит только после
того, как весь архив признан годным.

### 9.2.1 Пак — это модель, а не пачка

Единица набора — **одна модельная линия** со всеми её режимами: генерация,
перерисовка, апскейл. Человек выбирает модель, а не «набор» неизвестного
состава, и уровень читается как свойство модели:

| Уровень | Паки | Семейства |
|---|---|---|
| Free (0) | `image/z-image`, `image/seedvr2` | z-image, seedvr2 |
| Pro (2) | `image/flux2-klein`, `image/qwen-image` | flux2-klein, qwen-image (+ qwen-image-edit) |
| Ultimate (3) | `image/krea2`, `image/ideogram` | krea2, ideogram |

Лесенка та же, что в `nodes/_pass.py` (`{1: base, 2: pro, 3: ultimate}`), и
пропуск старшего уровня открывает младшие.

Описание паков — **в самой сборке**: `js/image/studio/packs/catalog.json`. Там
имя, текст, обложка, уровень и состав; доставка (версия, файл, шифрование)
приезжает из удалённого `index.json` и подмешивается по `id`
(`_studio_packs.merge_catalogs`). Так менеджер осмысленно работает и офлайн:
что пак ЕСТЬ и что он делает — свойство сборки, а не хоста.

Тир по-прежнему живёт в манифесте каждого графа и гейтит только доставку.
Каталог его лишь показывает; расхождение этих двух мест ловит тест
`test_graph_manifests_and_the_catalogue_agree_on_tiers` — иначе получился бы
пак, который в менеджере Ultimate, а качается как бесплатный.

Обложки настоящие: каждая посчитана тем семейством, которое рекламирует, на
нейтральном промпте, в самой студии (`tools/studio_covers.py` приводит кадр к
4:3 webp). У апскейлера пара «до/после» — она меняется по наведению, потому
что один кадр про восстановление не говорит ничего.

### 9.3 Что заперто, а что нет

Заперто **отсутствующее**, а не платное. Установленный набор работает всегда,
в том числе после конца подписки: платят за получение нового, не за запуск.
В списке моделей то, чего здесь нет, показано серым «в наборе» — по клику
открывается витрина. Замка на установленном не бывает.

**Спрятать** пак могут две разные вещи, и путать их нельзя (`_studio_pack_state.py`):

- **выключен человеком** — его выбор, хранится в
  `user/default/ts-studio/packs-state.json`. Ничего не удаляется: графы и
  модели на месте, возврат — тот же переключатель. Шесть моделей в списке,
  когда работают тремя, — шум, но удалять из-за шума нечего;
- **выше потолка уровня** — только режим тестирования (`viewTier` в
  `dev.json`). Прячет и никогда не открывает.

Оба ответа сходятся в `active_families()`, поэтому остальной студии не нужно
знать, какая из причин сработала. На фронтенде то же делает
`applyPackState()` в `js/_studio/_backends.js`, и скрытое семейство остаётся в
списке моделей серым — иначе выключение выглядело бы как пропажа модели.

### 9.4 Режим тестирования

Всё в подписке по природе удалённое: каталог на хосте, архив за ключом, ключ
со сроком. Для пользователя это правильно, для отладки — мучение: каждая
попытка означала бы коммит, пуш и ожидание.

Режим включается наличием файла `user/default/ts-studio/dev.json` — у
пользователя его нет, и вся поверхность (панель в настройках, POST-роут)
просто отсутствует. Меняются только две вещи: **откуда** читаются наборы и
**каким** показывается ключ. Правила — подпись, срок, тиры, распаковка —
работают ровно как у пользователя, иначе тест ничего не доказывал бы: при
`simulate: none` секретов в состоянии нет, и платный набор действительно не
скачивается.

```bash
# включить, читать из локальной сборки
python tools/studio_pack.py dev --dist dist/studio

# показать студию как машину без ключа
python tools/studio_pack.py dev --simulate none

# что сейчас на машине: режим, ключ, наборы
python tools/studio_pack.py dev --status

# выйти
python tools/studio_pack.py dev --off
```

Переключатели есть и в самой студии: «Настройки» → «Тестирование». После
смены студия перечитывает ключ, каталог и бэкенды — перезапуск ComfyUI не
нужен, хватает перезагрузки страницы.

Третий переключатель — **потолок уровня**: «Показывать студию как» → Free /
Pro / Ultimate / Всё, он же `tools/studio_mode.py --as free`. Он нужен потому,
что вся сборка сейчас едет одним куском: без него автор физически не может
увидеть студию глазами бесплатного пользователя — экран паков был бы честным,
а список моделей нет. Паки выше потолка ведут себя как недоставленные.

```bash
python tools/studio_mode.py --status
python tools/studio_mode.py --as free
python tools/studio_mode.py --disable image/krea2
python tools/studio_mode.py --off        # выключенные паки при этом не трогаются
```

### 9.5 Админка — одна на всё

Наборами управляет **вкладка «Студия» в админке лаунчера**
(`comfyui-launcher/tools/workflow-admin/`), а не отдельный инструмент: у
платных workflow лаунчера и у студии один подписчик, один код месяца, одни
секреты уровней и один хостинг. Разводить это по двум окнам значило бы дважды
жать одни и те же кнопки.

Что там есть: список семейств с переводом между категориями, редактор
авторского каталога наборов, сборка (хостинг или GitHub-зеркало) и включение
режима тестирования на своей машине. Публикация общая: собранные наборы
ложатся в `publish/studio/`, и одна кнопка отправляет каталог workflow, ключи
месяца и наборы вместе.

Формат набора при этом остаётся **здесь**: админка запускает
`tools/studio_pack.py`, а не повторяет его логику. Командная строка тоже
никуда не делась — всё, что делает вкладка, делается и вручную (см.
`doc/TESTING_STUDIO.md`).

Каталог студия читает с двух адресов по очереди: сначала хостинг (туда
публикует админка), затем GitHub-зеркало. Откуда пришёл каталог — оттуда же
качается и набор.

### 9.6 Репозитории

| Что | Где |
|---|---|
| Исходники платных семейств, авторский каталог, медиа | `AlexYez/comfyui-timesaver-studio` (приватный) |
| Каталог, обложки, зашифрованные наборы | `AlexYez/ts-studio-packs` (публичный) |
| Сборщик | `tools/studio_pack.py` в этом паке |

Адрес каталога переопределяется переменной `TS_STUDIO_PACKS_URL`.

Секреты уровней меняются с каждым выпуском ключей, поэтому платный набор
пересобирается и перезаливается вместе с ключами месяца — как платные
workflow лаунчера. `--license-tool` берёт тот выпуск, который у подписчиков
уже на руках, а не самый новый на диске.

4. **Только потом** E2E лаунчера: он поднимает свой процесс на том же порту
   и гасит живой ComfyUI (проверено на себе — обрывает прогон на середине).
