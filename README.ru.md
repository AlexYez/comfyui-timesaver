# 🚀 Timesaver Nodes для ComfyUI

**Дружелюбный набор из 73 нод, чтобы убрать рутину из ваших ComfyUI-графов.**

Не важно, что вы строите — пайплайн для генерации изображений, видео, аудио или просто хотите облагородить промпты — у Timesaver есть подходящая нода.

>

Алгоритмы реализованы clean-room по публичной математике [RES4LYF](https://github.com/ClownsharkBatwing/RES4LYF) (код не копировался).

## 📦 Установка

### Вариант 1 — ComfyUI Manager (рекомендуется)

1. Откройте ComfyUI Manager → **Custom Nodes Manager**.
2. Найдите `Timesaver` и нажмите Install.
3. Перезапустите ComfyUI.

### Вариант 2 — Вручную

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/AlexYez/comfyui-timesaver
cd comfyui-timesaver
python -m pip install -r requirements.txt
```

Перезапустите ComfyUI.

> 🪟 **Windows portable**: запускайте `pip` из встроенного Python (`python_embeded\python.exe`), иначе зависимости установятся не туда.

> 🍎 **macOS / Linux**: используйте тот же Python, с которым запускается ComfyUI. Активируйте venv перед `pip install`.

### Опциональные зависимости

Несколько нод требуют дополнительных пакетов. Они мягко падают и сообщают, чего не хватает, если вы попробуете их запустить:

| Нода | Нужно поставить |
|---|---|
| TS Cube ↔ Equirectangular | `py360convert` |
| TS Music Stems | для роформеров ничего; `demucs` только ради старых `htdemucs*` |
| TS Silero TTS / Stress | `silero`, `silero-stress` |
| TS RTX Upscaler | `nvvfx` (только NVIDIA RTX) |
| TS Qwen 3 VL int4/int8 | `bitsandbytes` (нет колеса под Apple Silicon) |
| TS Video Upscale With Model | `spandrel` |

### Платформы

Windows, Linux и macOS на Apple Silicon. Чем мак отличается — замерено на
macOS-раннерах GitHub, а не предположено:

- **Для видео и звука ничего доустанавливать не нужно.** Все ноды, которым нужен
  ffmpeg, берут бинарник, который привозит `imageio-ffmpeg`; системный ffmpeg —
  запасной путь, а не требование.
- **Metal используется там, где оператор есть в PyTorch.** Двух не хватает —
  `linalg.eigh` и `linalg.lstsq`, — и они нужны TS Color Match: нода считает эти
  маленькие разложения на CPU, а всё остальное оставляет на GPU.
- **TS Whisper на маке всегда работает на CPU.** openai-whisper на Metal идёт
  ненадёжно, поэтому устройство не предлагается вовсе — это лучше, чем предложить
  и сломать.
- **int4 / int8 для TS Qwen 3 VL недоступны**: у `bitsandbytes` нет колеса под
  Apple Silicon. Нода это замечает и откатывается на fp16/fp32 с предупреждением.

## 🎯 Быстрый старт

1. Запустите ComfyUI.
2. **ПКМ → Add Node** или двойной клик по пустому месту канваса.
3. В строке поиска начните печатать `TS` — у каждой ноды Timesaver есть префикс `TS`.
4. Выберите ноду, подключите входы/выходы, запустите.

**Соглашение об именовании:**

```
TS_<NodeName>     ← id класса (используется в воркфлоу и поиске)
TS <Display Name> ← то, что вы видите на ноде
TS/<Категория>    ← путь в меню ПКМ
```

**Самые частые типы выходов:**

| Тип | Что это |
|---|---|
| `IMAGE` | Батч кадров `[B, H, W, 3]`, значения `[0, 1]` |
| `MASK` | Одноканальная маска `[B, H, W]`, значения `[0, 1]` |
| `AUDIO` | `{"waveform": [B, C, T], "sample_rate": int}` |
| `LATENT` | Латент `{"samples": ...}` |
| `CONDITIONING` | Список пар `(cond, meta)` для семплеров |
| `STRING` / `INT` / `FLOAT` | Обычные значения |

ComfyUI сам подсвечивает совместимые сокеты при перетаскивании — типы запоминать не обязательно.

## 🔄 Обновление

Уже установлен через git?

```bash
cd ComfyUI/custom_nodes/comfyui-timesaver
git pull
python -m pip install -r requirements.txt
```

Перезапустите ComfyUI. Id нод, входы и значения по умолчанию заморожены между версиями, поэтому сохранённые воркфлоу продолжают работать.

## 📚 Справочник нод

Под каждой нодой — её реальный вид в ComfyUI (английский UI). Кликните по любой картинке, чтобы открыть в полном размере.

---

<a id="image"></a>
### 🖼️ Изображения (20 нод)

Всё, что касается пикселей: ресайз, цвет, маски, удаление фона, кеер, тайлы, панорамы и инпейнтинг.

#### TS Image Resize
<img src="doc/screenshots/ts_image_resize.png" alt="TS Image Resize" width="450" />

Тот самый ресайз, который вам действительно нужен. Выбирайте один из режимов: точные размеры (`target_width` × `target_height`), одна сторона (`smaller_side` / `larger_side`), мегапиксели или коэффициент масштаба. Опция `divisible_by` подгоняет результат под кратность, нужную семплерам (8, 16, 32, …). `dont_enlarge` запрещает увеличение, если исходник уже меньше цели.

**Когда использовать:** подготовка входов для SDXL / Flux / WAN, batch-ресайз фото к максимальной стороне, унификация размеров видео.

---

#### TS Resolution Selector
<img src="doc/screenshots/ts_resolution_selector.png" alt="TS Resolution Selector" width="450" />

Визуальный выбор соотношения сторон. Доступны 1:1, 4:3, 3:2, 16:9, 21:9, 3:4, 2:3, 9:16, 9:21 или произвольное соотношение, плюс целевой бюджет в мегапикселях (0.5 – 4 МП). На выходе — пустое полотно с размерами, кратными 32, идеально как `latent_image`. Если подключить картинку, нода впишет её на полотно; с `original_aspect=True` соотношение берётся из картинки, а не пресета.

**Когда использовать:** старт генерации с фиксированной пропорцией, нормализация произвольной картинки в latent-сетку.

---

#### TS Color Match
<img src="doc/screenshots/ts_color_match.png" alt="TS Color Match" width="450" />

Перенос цветовой палитры с `reference` на `target` батч. Два алгоритма:

- **MKL** (по умолчанию) — быстро, стабильно, дружелюбно к видео с временным сглаживанием.
- **Sinkhorn** — медленнее, но точнее (на основе оптимального транспорта).

В комплекте: маски совпадения (`rectangle` / `ellipse` для стабилизации только по краям), VRAM-aware чанкинг, флаг `reuse_reference` для видео.

**Когда использовать:** колор-грейдинг видео по одному ключевому кадру, сведение кадров из разных источников, вписывание CG в plate-видео.

---

#### TS Film Emulation
<img src="doc/screenshots/ts_film_emulation.png" alt="TS Film Emulation" width="450" />

Встроенные пресеты плёнки (Kodak Portra/Vision3, Fuji, Cineon-style, …) плюс возможность подгрузить свой `.cube` LUT из `models/luts/`. Гамма-коррекция, кривая контраста и регулируемая `lut_strength`.

**Когда использовать:** придание рендерам кинематографичного оттенка, не уходя из графа.

---

#### TS Remove Background (BiRefNet)
<img src="doc/screenshots/ts_bgrm_birefnet.png" alt="TS Remove Background" width="450" />

State-of-the-art удаление фона через BiRefNet. На выходе: вырезанная картинка, альфа-маска и "preview" маски. Опции: выбор модели (HR-matting / general / portrait / DIS), `process_resolution` (с override через `use_custom_resolution`), `precision` (auto/fp16/fp32), `mask_blur`, `mask_offset`, `invert_output`, `temporal_smooth` для видео (`none`/`median3`/`ema` с `ema_alpha`), фон (Alpha / цвет через COLOR-виджет). В v9.4 убран нестабильный `refine_foreground`.

**Когда использовать:** изоляция объектов, продуктовая съёмка, чистые альфа-маски для композа.

---

#### TS Lama Cleanup
<img src="doc/screenshots/ts_lama_cleanup.png" alt="TS Lama Cleanup" width="450" />

Встроенный инпейнтинг через LaMa — рисуйте маску прямо на канвасе ноды (кисть + undo/redo + reset), затем запускайте, чтобы заполнить. Хранит промежуточные правки по сессиям, не нужно ходить в Photoshop. С v9.3 архитектура — чистый PyTorch (без зависимости от upstream `lama-cleaner`), веса загружаются из `.safetensors` в `models/lama/`, а не из pickled `.ckpt`.

**Когда использовать:** убрать туристов с фото, стереть водяные знаки, починить артефакты, прототипировать чистку перед тяжёлым inpainter'ом.

---

#### TS Smart Inpaint
<img src="doc/screenshots/ts_smart_inpaint.png" alt="TS Smart Inpaint" width="450" />

Перерисовка **или** уточнение по маске в одной ноде: подайте полное изображение + нарисованную маску — нода вырежет регион (+ контекстный отступ), апскейлит кроп до бюджета в мегапикселях, VAE-энкодит, сэмплит, затем с фезером композитит и блендит результат обратно в латенте, так что нетронутые пиксели остаются бит-в-бит. Переключатель `replace` выбирает режим — **Replace** = Smart Inpaint, регенерирует область с нуля как Kontext-правку (кроп идёт в `reference_latents`, denoise зафиксирован в 1.0); опциональный `reference` подмешивается вторым reference'ом («заполни дыру ВОТ ЭТИМ»). **Refine** = ADetailer-style проход частичного denoise по значению `denoise`, без reference. Headless-порт «Xtra-Fine» инпейнт-пути из ComfyUI-Angelo (MIT) — кроп и композит происходят внутри ноды, графу нужно подать лишь источник + маску.

**Когда использовать:** замена объектов, генеративная заливка или проход высокой детализации по нарисованному выделению — без ручной цепочки кроп → сэмплер → склейка.

---

#### TS Langevin Inpaint
Сэмплер перерисовки, который на каждом уровне шума делает несколько дополнительных внутренних шагов — чтобы дорисованное согласовывалось с тем, что вокруг, а не просто заполняло дыру. Ставится вместо обычного KSampler: подайте латент с **маской шума**, на выходе — готовый `LATENT`.

Зачем это нужно: при обычном сэмплировании связь закрашенной области с окружением держится только на внимании самой модели. Динамика Ланжевена добавляет на каждом уровне короткий поправочный цикл (`think_steps` шагов), притянутый к известным пикселям через `guidance` и придемпфированный `step_size`, `beta` и `friction`. Значения по умолчанию подобраны под фотографию: поднимайте `think_steps`, если шов ещё виден, и опускайте, если заплатка «плывёт».

Работает с любым семейством моделей — ни Fill-чекпойнта, ни ControlNet не требуется.

**Когда брать:** перерисовка должна незаметно лечь в сложное окружение (кожа, ткань, листва), а обычный сэмплер оставляет заметную заплатку.

---

#### TS Universal Inpaint Sampler
То же самое, что TS Langevin Inpaint, но в виде **SAMPLER** — его подключают в родной `SamplerCustomAdvanced`, а не ставят вместо ноды сэмплера. Не требует обучения и не привязан к модели: ни Fill-чекпойнта, ни ControlNet.

Подайте в `SamplerCustomAdvanced` латент, у которого маска шума отмечает область перерисовки, и передайте ему этот сэмплер. `think_steps` задаёт, сколько поправок делается на каждом уровне шума; `resample_strength` — насколько сильно известные пиксели тянут закрашенные к себе.

**Когда брать:** у вас уже собрана своя цепочка сэмплирования (свои сигмы, свой guider), и нужно, чтобы перерисовка учитывалась внутри неё, а не снаружи.

---

#### TS Matting (ViTMatte)
<img src="doc/screenshots/ts_matting_vitmatte.png" alt="TS Matting (ViTMatte)" width="450" />

Guided alpha matting через Hugging Face ViTMatte. На вход — изображение + грубая маска (например, из SAM3 Detect), нода авто-строит trimap и уточняет маску до фотореалистичного альфа-канала. Такой же набор пост-обработки `mask_blur`/`mask_offset`/`background`, как у TS Remove Background, — drop-in замена, когда важны края, волосы и полупрозрачность. Модели кэшируются в `models/vitmatte/`.

**Когда использовать:** получить чистый cut-out из SAM-style маски без захода в Photoshop.

---

#### TS SAM Media Loader
<img src="doc/screenshots/ts_sam_media_loader.png" alt="TS SAM Media Loader" width="450" />

Загружает изображение или видео и позволяет накликать позитивные/негативные точки прямо на превью первого кадра. На выходе: `IMAGE`, `AUDIO` (для видео) и `positive_coords`/`negative_coords` — STRING JSON ровно в том формате, который ждут нативные ComfyUI ноды **SAM3 Detect** / **SAM3 Video Track**. С опциональным входом `model` (SAM3) дополнительно отдаёт рендер `initial_mask`, готовый идти в `SAM3 Video Track`.

**Когда использовать:** строите SAM3-сегментацию/трекинг и хотите кликабельный UI для seed-точек вместо ручного ввода JSON.

---

<img src="doc/screenshots/ts_crop_to_mask.png" alt="TS Crop To Mask" width="450" />

#### TS Restore From Crop
<img src="doc/screenshots/ts_restore_from_crop.png" alt="TS Restore From Crop" width="450" />

…этой ноды, которая возвращает обработанный кроп обратно в исходный кадр с feathered Gaussian/box blur'ом по швам. Классический crop-and-restore для обработки только интересующей области тяжёлой моделью.

**Когда использовать в паре:** прогнать апскейлер или face-restorer на маленьком ROI большого изображения без расхода VRAM на весь кадр.

#### TS Image Tile Splitter
<img src="doc/screenshots/ts_image_tile_splitter.png" alt="TS Image Tile Splitter" width="450" />

Режет большое изображение на перекрывающиеся тайлы для тайловой обработки. Настраивается размер тайла, перекрытие и feather. На выходе батч тайлов + метаданные `TILE_INFO`.

#### TS Image Tile Merger
<img src="doc/screenshots/ts_image_tile_merger.png" alt="TS Image Tile Merger" width="450" />

Вторая половинка пары: берёт обработанные тайлы и `TILE_INFO`, склеивает обратно в одно изображение с feathered-смешиванием в зонах перекрытия.

**Когда использовать в паре:** тайловый апскейл, шумоподавление или любой процесс, для которого 4K кадр не помещается в VRAM.

#### TS Auto Tile Size
<img src="doc/screenshots/ts_auto_tile_size.png" alt="TS Auto Tile Size" width="450" />

Выберите `tile_count` (4, 8, 16) — нода вычислит оптимальные `tile_width` × `tile_height` с учётом padding'а и `divide_by`. Отлично сочетается со splitter'ом/merger'ом выше.

---

#### TS Image Batch Cut
<img src="doc/screenshots/ts_image_batch_cut.png" alt="TS Image Batch Cut" width="450" />

#### TS Smart Batch
Собирает батч из изображений — и продолжает работать, когда одного из них нет. Входы **растут**: занял последний слот, появился следующий, до 32. Каждый слот **необязательный**, поэтому пустой или обойдённый просто пропускается. Ошибка возникает только если не подключено вообще ничего, и она об этом прямо говорит, а не подсовывает пустой кадр.

Зачем: у встроенной **Batch Images** оба входа ОБЯЗАТЕЛЬНЫЕ, поэтому стоит выключить или обойти любую сторону — и весь граф падает ещё до запуска. А сборка пары «первый кадр / последний кадр» как раз и состоит в том, чтобы то включать, то выключать одну из сторон, и перекладывать ради этого связи не должно быть нужно.

Кадры выходят в порядке слотов — `image0`, `image1`, `image2`, … — какие бы дыры вы ни оставили. Согласование как в ядре: недостающий альфа-канал дописывается единицей, изображение другого размера подгоняется под первое пришедшее. Батчи складываются: 3 кадра плюс 2 кадра дают 5.

**Когда брать:** подача в видеомодель по первому и последнему кадру, и вообще любой случай, когда одна нода должна отдавать батч из скольких угодно включённых источников.

### 🎬 Видео (8 нод)

Чтение и запись видеофайлов, интерполяция кадров, апскейл моделью, глубина, превью анимации.

#### TS Video Loader
<img src="doc/screenshots/ts_video_loader.png" alt="TS Video Loader" width="450" />

Читает видео в кадры, звук и компактный набор `video_info` — и даёт выбрать кусок **глазами**. В теле ноды плеер и таймлайн с полосой кадров: тяните ручки, чтобы задать начало и конец, приближайтесь к одной секунде часового дубля (Ctrl/Cmd + колесо) и крутите выделенное по кругу, пока оцениваете. Если мышью не попасть — впишите точный таймкод.

**Она быстрая не случайно.** Масштабирование, поворот и конверсия цвета делаются внутри графа фильтров декодера, а чтение обрывается на конце выделения: двухсекундный кусок часового 4K-дубля стоит перемотки плюс двух секунд, а не часа. Замерено на 4K: 0.43 с там, где наивный путь (декодировать в полном разрешении, потом уменьшить) занимает 5.9 с и 6.4 ГБ.

**Под полосой кадров рисуется звуковая дорожка**, если в файле есть звук — попасть в такт или в начало реплики по волне куда проще, чем по картинке, — а плеер идёт за той ручкой, которую тянут: кадр, который станет первым или последним, виден прямо в момент выбора.

`frame_rate` пересчитывает по настоящим временным меткам, поэтому источник с переменной частотой выходит равномерным. Размер задаётся не шириной и высотой, а длинной и короткой стороной, поэтому один граф годится и для горизонтальной съёмки, и для вертикальной; любую сторону можно оставить `0`, вторая выведется сама. `divisible_by` округляет вниз до того, что просят видеомодели, фильтр масштабирования по умолчанию `area` (кадры почти всегда уменьшают, и усреднение здесь лучше интерполяции), а `max_frames` — страховка памяти. Потолок под кадры считается от машины (60% ОЗУ, но не ниже 8 ГБ; переопределяется `TS_VIDEO_MAX_BYTES`), поэтому 13-секундный 4K-ролик на 64 ГБ грузится, а не получает отказ. Если кадры всё же не влезают, `when_too_large` = `use disk` кладёт их в отображённый в память файл во временной папке ComfyUI: наружу уходит обычный IMAGE, и выделение не срывается, каким бы длинным ни был ролик — ценой обращений к диску (замерено: 31.9 ГБ за 92 с против 51 с в памяти).

Материал попадает в ноду **перетаскиванием** — из проводника, из браузера Artius или из превью другой ноды, — кнопкой, вставкой из буфера или путём к файлу в любом месте машины с ComfyUI.

> **Путь куда угодно на машине — и что меняется, если сервер не только ваш.** При обычном локальном запуске (`127.0.0.1`) и нода, и превью читают **любой путь**: «Документы», рабочий стол, другой диск. Ничего не копируется в `input` — ради этого всё и затевалось, иначе эта папка растёт без конца.
> Если же ComfyUI поднят открытым в сеть (`--listen 0.0.0.0`, машина в локалке, облако), превью отдаётся по HTTP всякому, кто дотянулся до порта, — и тогда оно ограничивается вашей домашней папкой и каталогами самого ComfyUI. Добавить свои: `TS_MEDIA_EXTRA_ROOTS=D:/footage` (несколько — через разделитель путей вашей ОС), снять ограничение целиком: `TS_MEDIA_ALLOW_ANY_PATH=1`. И то и другое ставится на машине её хозяином, а не внутри workflow: workflow может приехать от кого угодно.

**Когда пригодится:** любой граф, который начинается со съёмки, а не с картинки.

#### TS Video Saver
<img src="doc/screenshots/ts_video_saver.png" alt="TS Video Saver" width="450" />

Пишет кадры в видеофайл и проигрывает результат прямо в ноде. Формат и качество названы словами — **MP4 / H.264** от черновика до «без потерь», **MP4 / H.265** — примерно вдвое меньший файл при том же качестве, с необязательными десятью битами — или **MOV / ProRes** с привычными профилями от Proxy до 4444 XQ, — а не флагами кодировщика. Звук муксится **в тот же проход и в тот же файл**: ни временного WAV, ни второго запуска ffmpeg, ни файла-дубля с суффиксом на диске.

**Запись показывает ход прямо на ноде**, как это делает сэмплинг: длинный ролик кодируется минутами, и молчащая нода всё это время выглядит зависшей.

Плеер помнит, включали ли вы звук. ProRes браузер не проигрывает, поэтому рядом пишется маленькая копия H.264 — только для просмотра (`preview: off` её отключает). Аппаратное кодирование доступно, но само не включается: оно заметно быстрее и заметно хуже при том же размере файла.

**Секвенция EXR** — четвёртый формат: по файлу на кадр, линейный свет float32 (или 16-битный half), в отдельной папке, прямо из сокета `hdr_image` и без единого прикосновения к диапазону. Этот сокет и существует потому, что обычный вход «кадры» зажимается в 0..1 задолго до сохранятеля. Настройки сжатия нет — этот кодировщик её не предлагает. Звука у секвенции не бывает; маленькое превью H.264 пишется тем же проходом, чтобы плееру в ноде было что показать.

**Когда пригодится:** когда нужен готовый ролик на диске, в формате, который примет монтажка, — или HDR-мастер кадрами, которые примет композитинг.

#### TS Video Depth
<img src="doc/screenshots/ts_video_depth.png" alt="TS Video Depth" width="450" />

Карта глубины для секвенции: **Video Depth Anything** скользящим окном кадров,
поэтому глубина не «плавает» от кадра к кадру.

Всё, что помещается в одно окно, считается одним окном ровно своей длины, а не
добивается копиями последнего кадра — такого входа модель в обучении не видела.

`window_overlap` выносят наружу само скользящее окно — трогать их стоит, только
если сознательно меняете видеопамять на связность.

загрузка за сотые доли секунды вместо целой. Против чистого fp32 глубина
отличается на 0.02% своего размаха, то есть ни на что. Старые `.pth` остаются в
списке, и прежние workflow работают как работали.

**Когда пригодится:** depth-ControlNet по клипу, параллакс и 2.5D-облёты, маски
по расстоянию во времени.

#### TS Image Depth
<img src="doc/screenshots/ts_image_depth.png" alt="TS Image Depth" width="450" />

Карта глубины для одиночного кадра или пачки не связанных между собой картинок.
Каждый кадр считает **Depth Anything V2 Large** сам по себе.

Почему отдельная нода, а не переключатель у видеоверсии: видео-модель умеет
смотреть на одну картинку только как на 32 дублированных кадра, и это сплющивает
диапазон глубины — замерено на портрете, лицо и волосы выбиваются в ровное белое,
структура пропадает. Плюс она поднимает короткую сторону до 518 px, так что
снимок 1600 px уходил в модель как 784x518 и возвращался заметно мягче.

Порядок действий — эталонный, сознательно и без добавок: подрезать стороны до
кратности 14, прогнать модель, нормировать **каждую картинку своими** min/max,
вернуть размер билинейно. Ни шумодава, ни дизеринга, ни направляемого апскейла:
всё это придумывалось под видео, а на снимке направляемый фильтр давал гало по
контурам. Против эталонной реализации карта расходится на **0.36%** — меньше
одного уровня 8-битной шкалы, при совпадающей детализации.

Единственный по-настоящему важный регулятор — `max_res`: длинная сторона, на
которой обрабатывается картинка, с округлением вниз до кратности 14. `-1` (по
умолчанию) — родное разрешение, то есть ничего не пересэмплируется вовсе.
Понижать его стоит, когда нужна скорость или не хватает видеопамяти; при
нехватке нода сама повторяет попытку вдвое меньшим размером и пишет каждый шаг
в лог.

Веса — fp16 safetensors, скачиваются при первом запуске. В списке предлагаются
только safetensors, но workflow, где записан старый `.pth`, продолжает работать —
файл просто больше не предлагают.

**Когда пригодится:** depth-ControlNet по одной картинке, 2.5D из фотографии,
перерасчёт света или маски по расстоянию, вход для 3D-реконструкции.

<a id="hdr"></a>
### 🌈 HDR / EXR (7 нод)

Нативный HDR-путь LTX 2.5, разложенный на ноды. **По умолчанию выключен и в выключенном
состоянии не стоит ничего**: галочка опущена — ни один EXR не читается, VAE в float32 не
грузится, и граф ведёт себя ровно так, как вёл до появления этих нод.

**Чем это не является:** HDR из SDR-ролика здесь не выдумывается. Сохраняется тот HDR,
который пришёл, — из опорных кадров EXR, через модель, в мастер EXR.

Готовый пример с пояснениями прямо на холсте: [`example_workflows/08_ltx25_native_hdr.json`](example_workflows/08_ltx25_native_hdr.json). Это только HDR-половина — свой двухстадийный граф LTX достраивается вокруг неё, как написано в записках.

Почему обычные ноды так не умеют: `Load Image` сплющивает всё выше 1.0 в единицу, ничего
не сказав, а `LTXVPreprocess` прогоняет кадр через H.264 и восемь бит
(`(image * 255.0).byte()` в исходнике ядра). Для SDR это нормально, для HDR смертельно,
поэтому HDR-ветка обходит их полностью.

#### TS LTX HDR Settings

Одна галочка на весь путь. Её читают все остальные ноды, поэтому режим всего графа
меняется одним переключателем, а не пятью настройками, которые должны совпасть.

`input_color_space` говорит, чем уже являются файлы EXR: `ACESCG`, `SRGB_LINEAR` или
`ACESCCT` — те же три варианта, что принимает официальный ключ `--hdr`. Настройки превью
живут здесь же, рядом с галочкой, и это осознанно: экспозиция и тон-маппинг относятся к
тому, на что смотрят, и никогда — к тому, что записывается.

`hdr_mode` выбирает, какую из двух HDR-технологий использует граф, — а они
действительно разные, а не два оттенка одной:

- **preserve HDR from EXR (ACEScct)** — нативный путь LTX 2.5. Диапазон пришёл из
  EXR, и задача его не потерять. Рабочая кривая ACEScct, код 1.0 = линейная
  **222.86**, на выходе примарии переводятся AP1 → Rec.709.
- **expand HDR from SDR (LogC3 IC-LoRA)** — та самая HDR IC-LoRA. Диапазона на
  входе не было, модель выращивает его из обычного SDR. Рабочая кривая LogC3, код
  1.0 = линейная **55.08**, и ⚠️ **примарии не меняются** — модель уже отдаёт
  нужные, а матрица ACES-пути здесь увела бы цвет. Наша обратная кривая совпадает
  с официальной `LTXVHDRDecodePostprocess` до 1e-6, замерено на 501 точке.

В режиме expand опорный кадр — обычная картинка, и ни один EXR не читается: LoRA
подключается к модели вами, тем же способом, что в официальном воркфлоу 2.3. LoRA
официально проверена на LTX 2.3, поддержка 2.5 заявлена как «в разработке».

**Когда нужна:** всегда, если используется хоть одна нода отсюда.

#### TS LTX Load HDR EXR

Читает EXR как линейный float32 — без нормализации и без зажима сверху. Показывает
диапазон и, главное, **какая доля кадра выше 1.0**. Если там ноль, света потеряли ещё
раньше, и сохранять дальше по пути уже нечего.

Три бэкенда: **OpenImageIO** (им читает официальный pipeline, стоит редко), **PyAV**
(едет с любой ComfyUI и ничего не требует настраивать — на практике он и работает) и
**OpenCV** (читает EXR, только если `OPENCV_IO_ENABLE_OPENEXR=1` была выставлена *до*
запуска ComfyUI; позже выставлять бесполезно — читалка регистрируется при импорте).

Half-float — то, в чём рендерят почти все, — тоже читается. Ради этого плоскости кадра
разбираются вручную: `gbrpf16le` PyAV в массив не превращает вообще, а любая конверсия
формата идёт через swscale, а он зажимает float в `[0, 1]`. Замерено:
четырёхканальный EXR со значением 4.0, прочитанный удобным способом, возвращается
единицей.

**Когда нужна:** опорные кадры для сцены — рендеры, а не скриншоты.

---

#### TS LTX HDR Guide

По одной ноде на опорный кадр — первый, последний, — и она же выбирает ветку, и она же
её готовит. Выключено — SDR-картинка проходит насквозь нетронутой; включено — из EXR
строятся два опорных кадра.

**Половинный кадр строится из оригинала, а не уменьшением полного.** Официальный
двухстадийный pipeline собирает image conditioning заново для каждого разрешения, и это
не одно и то же: усреднять надо линейный свет, а не логарифмические коды.

Ленивые входы — причина, по которой галочка бесплатна. С выключенным HDR ComfyUI просто
не заходит в EXR-ветку; с включённым не считается цепочка с `LTXVPreprocess`. Сломанный
путь к EXR не может сорвать обычный прогон.

Строгая проверка ловит размеры стадий, не отвечающие ни одной законной разводке —
одинаковые (без латентного апскейлера) или ровно вдвое (с апскейлером x2).

Прогон по **обычному JPG или PNG** тоже поддержан — через вход `image_guide`,
для случая «генерирую видео по картинке, а мастер нужен в линейном float32».
Стоит понимать, что это даёт: в восьмибитной картинке нет ничего выше 1.0, и
никакая кривая не выдумает то, чего не снимали. Восстановление светов из SDR-кадра
— это SDR→HDR expansion, другая модельная технология, и здесь её нет.

Но то, что получается, само по себе полезно. Гамма снимается правильно: подать
коды sRGB как линейный свет — ошибиться до **2.3 стопа** в тенях (замерено: 0.131
диапазона кода ACEScct). Мастер остаётся линейным float32 — без полос и без
впечённой гаммы. И запас в рабочем диапазоне сохраняется: белый SDR приходится на
код ACEScct **0.555**, то есть **45% диапазона, 7.8 стопа, остаётся выше** — туда
модель может уйти. Уйдёт ли — вопрос опыта, и ровно для него есть нода
TS LTX Статистика HDR.

Чтобы включить: поднимите HDR и обведите загрузчик EXR в обход — опорный кадр сам
перейдёт на `image_guide`, отдельного переключателя не нужно.

**Когда нужна:** первый и последний кадр идут в двухстадийный граф LTX.

---

#### TS LTX Final Latent Selector

Выбирает латент первой или второй стадии **до** декодирования, вместо того чтобы
декодировать оба и один выбросить. Входы ленивые, поэтому выключенный апскейлер
перестаёт стоить времени сэмплера, а не только декодера, — а один decode дальше по графу
означает одно место, где происходит HDR-преобразование.

**Когда нужна:** в графе есть переключатель двух стадий. Её стоит поставить и без HDR.

---

#### TS LTX HDR VAE

Тот же файл VAE, но с явно заданной точностью. Штатный `Load VAE` про неё не спрашивает:
model management выбирает bf16, и для картинки этого с запасом, а для мастера нет — шаг
квантования в тенях и в верхних стопах приходится ровно туда, где живёт HDR.

Всё остальное остаётся на прежнем VAE: кодирование опорных кадров обеих стадий,
латентный апскейлер, обычный SDR-decode. Подключать эту ноду можно **только** во вход
`hdr_vae` декодера — этот вход ленивый, и именно он не пускает вторую копию видео-VAE в
память, пока HDR выключен.

**Когда нужна:** HDR включён. Иначе оставьте неподключённой.

---

#### TS LTX HDR Decode

Единственное финальное декодирование, и у него два выхода, которые нельзя путать:

- `preview_sdr` — то, на что смотрят: тон-маппинг, экспозиция, кривая sRGB.
- `hdr_linear` — то, что сохраняют: сцена в линейном Rec.709, float32, без тон-маппинга,
  без гаммы, **без зажима сверху**. Ни одна настройка превью его не касается.

Пока HDR выключен, слот мастера отдаёт `ExecutionBlocker`, и подключённый сохранятель EXR
не запускается вовсе — ни файла-пустышки, ни чёрных кадров, ничего.

Сам decode выходит рабочим сигналом ACEScct в `[0, 1]` — поэтому штатный зажим ComfyUI
`(x + 1) / 2` на LTX-овском VAE здесь ничего не стоит. Диапазон возвращается на обратной
кривой, уже после декодера.

**Когда нужна:** вместо пары нод VAEDecode в конце двухстадийного графа.

---

#### TS LTX HDR Stats

Потерянный HDR выглядит совершенно нормально. Картинка та же, файл записался, ошибок нет
— просто в нём ничего нет выше 1.0, и обнаруживается это в монтажной, когда кто-то
пробует вытянуть небо обратно.

Эта нода отвечает на вопрос «диапазон на месте?» числами: перцентили, доля сэмплов выше
1.0, динамический диапазон в стопах, отрицательные значения, NaN/Inf. Она же
предупреждает, когда света упёрлись в рабочий потолок ACEScct: коду 1.0 соответствует
линейная яркость около **222.86**, это примерно 7.8 стопа над белым, и всё, что ярче,
сплющилось на входе в модель.

**Когда нужна:** первый прогон сцены и любой случай, когда EXR выглядит подозрительно
смирным.

#### TS Music Stems
<img src="doc/screenshots/ts_music_stems.png" alt="TS Music Stems" width="450" />

Разделяет музыку на стемы; движок выбирается в `model_name`.

**BS-RoFormer SW** стоит по умолчанию и даёт шесть: `vocal`, `bass`, `drums`,
`guitar`, `piano` и `others` — всё остальное. **Mel-Band RoFormer** даёт только
вокал и инструментал, и именно поэтому он для этой задачи лучше: специалист
тратит всю ёмкость на одну границу вместо того, чтобы делить её на шесть. Оба
трансформера заметно сильнее прежнего. **Demucs** (`htdemucs`, `htdemucs_ft`,
`hdemucs_mmi`) остался в списке, чтобы графы, сохранённые до этой правки,
считали ровно то же, что и считали.

**Стемы складываются обратно в микс.** Само по себе разделение масками так не
умеет — расхождение слышно в null-тесте. Поэтому один стем у модели не берётся
вовсе: он равен миксу минус всё остальное, и сумма сходится по построению.
Замерено на настоящей музыке: `vocal + instrumental` вычитается из исходника
на 161 дБ, шесть стемов — на 144 дБ, а это уже полка чисел с плавающей точкой,
а не ошибка модели.

**Выходы, которых модель не даёт, блокируются, а не заполняются тишиной.**
Попросите у Mel-Band барабаны — эта ветка графа просто не исполнится. Тишина
выглядела бы как сломанная модель и стоила бы вам вечера поисков.

`precision` выбирает fp16 или fp32 для роформеров. fp16 примерно вдвое
быстрее и вдвое экономнее по видеопамяти, а его ошибка против fp32 замерена на
уровне −61 дБFS и ниже — под шумовой полкой записи. bfloat16 не предлагается:
маска в этих моделях собирается через `view_as_complex`, который его не
принимает. `shifts` и `jobs` относятся только к Demucs.

Веса скачиваются один раз при первом запуске в `models/roformer/`. Если
чекпойнт Mel-Band уже лежит от другого пака, он берётся оттуда, а не качается
заново.

**Когда пригодится:** вытащить вокал для ремикса, собрать минусовку под караоке
или отдать чистые стемы следующей модели.

#### TS Audio Visualizer
<img src="doc/screenshots/ts_audio_visualizer.png" alt="TS Audio Visualizer" width="450" />

Превращает любой `AUDIO`-клип в стильную waveform-картинку в духе SoundCloud в заданном разрешении. Палочки в сине-фиолетовом градиенте (по умолчанию `Violet`; есть `Indigo`, `Neon`, `Spectrum`, `Fire` и др.) рисуются как antialiased-«капсулы» со скруглёнными концами и мягким неоновым свечением — поверх **абстрактного аудио-реактивного фона**, который завязан на ту же огибающую громкости: `nebula` (слоистые горы + аура волны), `glow`, `mountains`, `plasma` или `none`. Целиком на torch, без сторонних библиотек. На выходе и `IMAGE`, и `MASK` (альфа палочек + glow), чтобы накладывать визуализацию на видео или футаж. Режимы зеркальных или нижних палочек, градиент по горизонтали / вертикали / амплитуде, плюс контроль свечения, интенсивности фона, чувствительности, сглаживания и геометрии палочек.

**Когда использовать:** оверлеи для музыкальных клипов, аудиограммы для соцсетей или быстрый визуал для озвучки / трека.

### 🤖 LLM (2 ноды)

Мультимодальный prompt-enhancement и понимание изображений через локальные LLM.

#### TS Qwen 3
<img src="doc/screenshots/ts_qwen3_vl.png" alt="TS Qwen 3 VL V3" width="450" />

Мультимодальный Qwen 3 VL (image + video + text) локально. Встроенный выбор модели (Qwen 2B / 4B / 8B и uncensored-варианты), пресеты системных промптов ("Image Edit Command Translation", "Prompt Enhancement", …), 4-bit/8-bit квантование через `bitsandbytes`, поддержка FlashAttention-2, скачивание с HuggingFace на лету. С v9.5 тяжёлый пайплайн вынесен в общий `nodes/llm/_qwen_engine.py`, который переиспользует Super Prompt — исправления и оптимизации применяются к обеим нодам одновременно.

**Когда использовать:** описание изображений для промптов, перевод намерений пользователя в команды редактирования, VLM-driven пайплайны.

---

#### TS Super Prompt
<img src="doc/screenshots/ts_super_prompt.png" alt="TS Super Prompt" width="450" />

Нода-улучшайзер промптов со встроенной **голосовой кнопкой** — скажите идею, Whisper её транскрибирует (с грамматикой, заточенной под cinematography), маленький Qwen3 раскрывает в насыщенный промпт. Опциональный image input для image-conditioned промптов. Два режима: быстрый turbo и high-quality. Внутренности в v9.5 разнесены по `nodes/llm/super_prompt/` (`_helpers`, `_voice`, `_qwen` поверх общего Qwen-engine) — путь prompt enhancement идёт в ногу с TS Qwen 3 VL V3.

**Модель не скачивается молча.** Если её на машине ещё нет, нажатие кнопки улучшения сначала показывает окно: какая модель, сколько именно весит (точный размер репозитория, спрошенный у Hugging Face — без единого скачанного байта) и в какую папку она ляжет. «Не сейчас», Escape и клик мимо окна значат отказ, и не качается ничего. Согласие запоминается на сессию, чтобы не спрашивать перед каждым нажатием.

**И проверяется библиотека.** До скачивания нода узнаёт у хаба, что это за архитектура, и сверяет с тем, что умеет установленный `transformers`. Если не умеет — прогон останавливается сразу, с типом модели, установленной версией и командой, которая это чинит, вместо нескольких минут и гигабайтов ради того же вывода. Проверка спрашивает саму библиотеку, а не сравнивает номера версий: сборка из git или частичное обновление судятся по тому, что они реально могут. Модель по умолчанию — Qwen3.5, и ей нужен `transformers` не ниже **5.2.0**.

**Две референсные картинки.** Перетащите изображение прямо в ноду — из браузера Artius, с рабочего стола или превью другой ноды. Одна картинка работает как референс; перетащите вторую — и они становятся **первым и последним кадром** снимаемого плана, о чём модели говорится явно. Вторая кнопка выбора появляется, когда занята первая. На превьюшках стоят цифры **1** и **2** — какой кадр где; чтобы поменять их местами, перетащите одну картинку на другую. Уберёте первую из пары — вторая займёт её место.

**Кадры можно подать и из графа.** Опциональный вход `images` принимает обычный ComfyUI `IMAGE`. Одна картинка — просто референс; в батче **первая картинка это первый кадр**, а **последняя — последний**. Один вход, а не сокет на каждый кадр: порядок в батче и говорит, какой кадр какой, поэтому три и четыре кадра не потребуют новой проводки (читаются до четырёх). Подключённый вход **главнее** картинок, приложенных в самой ноде, и побеждает целиком: батч уже задаёт порядок, смешивать его с вложениями значило бы собрать последовательность, которой никто не просил. Каждый кадр на входе ужимается примерно до 1 МП по площади — без кропа и без апскейла, если он и так меньше.

**Кнопка Enhance тоже видит вход.** Значения по проводам не существует, пока его кто-то не посчитает, — значит кнопка считает его сама, но только ту ветку, которая в этот вход идёт. Ноды, от которых ветка зависит, вынимаются из графа в свой отдельный промпт и считаются; остального workflow в этом промпте нет, поэтому ни сэмплер, ни сохранение заодно не срабатывают. Два загрузчика, собранные в батч, масштаб, кроп — работает всё, и ничего из этого не требует сначала прогнать весь workflow. Между нажатиями намеренно ничего не запоминается: подмените файл за загрузчиком — в графе всё читается ровно так же, и запомненный результат молча улучшил бы ту картинку, которую вы только что заменили. Кэширует ComfyUI уровнем ниже — по тому, что ноды реально прочитали. Если ветка не дала картинки, нода говорит об этом, а не улучшает молча один текст.

**Надписи не переводятся.** Текст в кавычках — это то, что должно появиться в кадре: вывеска, титр, строчка песни. Он копируется как есть, на языке оригинала, а всё остальное переводится на английский. Раньше услужливый перевод превращал русскую вывеску в английскую, которую никто не просил.

**Видеопресеты и `Image Prompt Enhance`** написаны под маленькую модель (Qwen 2B/4B): короткие нумерованные шаги, явный формат вывода, пример — и самое важное стоит в начале и повторено в конце, потому что именно начало и конец длинной инструкции модель на 2 млрд параметров и удерживает. Пресет свой на каждую модель, а не один на всех: `Video Prompt Enhance LTX` — под LTX-2.5, `Video Prompt Enhance H3` и `… H3 Reference` — под MiniMax H3.

**`Video Prompt Enhance LTX` — по собственным правилам LTX 2.5, и он не трогает ваши слова.** Пресет следует системным промптам, которые LTX кладёт в свой пак для ComfyUI: промпт начинается с `Style: …`, глаголы в present-progressive, события связаны по времени, звук вплетён в действие, а не собран в конце, движение камеры появляется только если его попросили. Формулировки сдержанные — красное платье, а не ярко-алое, — источник света один, и ничего, что нельзя снять: ни запахов, ни ощущений на ощупь.

Всё, что вы поставили в кавычки — `" "`, `« »`, `' '` или `( )`, — копируется знак в знак, в своём алфавите. Русский остаётся кириллицей, будь то реплика или вывеска на двери. Это правило стоит первой строкой пресета и последней: модель на 2 млрд параметров держит начало и конец инструкции и теряет середину — то же правило, спрятанное в теле, она игнорировала, и русские реплики возвращались переведёнными на английский. Речь описывается той же формулировкой, что и в пресете H3: *носитель русского с полностью родной артикуляцией и просодией*, а не «с русским акцентом» — по-английски это просьба об иностранце.

**Надпись — не реплика.** Назовите слова в кавычках вывеской, табличкой или титром — и они впишутся в кадр как то, что видит камера, и никто их не произносит; титр появляется *поверх* картинки, а не на выдуманном щите. Сама по себе модель придумывает человека, который читает витрину вслух, и попутно переписывает слова: правилу понадобился собственный пример, чтобы оно заработало.

**`Video Prompt Enhance H3` — реплики и русская речь, которая звучит по-русски.** MiniMax H3 делает звук тем же проходом, что и картинку, и у него есть своя схема для речи: говорящему даётся стабильный идентификатор `(S1)`, кто он и как звучит — снаружи блока диалога, а внутри блока только языковой тег и сама реплика, слово в слово, без перевода:

```text
A young Russian woman (S1), a native Russian speaker with natural, neutral standard
Russian pronunciation and authentic native Russian prosody, whispers softly and
flirtatiously: <d>[Russian] Привет, красавчик!</d>
```

Формулировка здесь важнее, чем кажется. `with a Russian accent` просит английский голос с русским налётом; `a native Russian speaker … authentic native Russian prosody` просит русский голос. Пресет ещё и разводит речь и надписи — что человек произносит, идёт в блок диалога, а текст на вывеске остаётся в кавычках — и пользуется только теми языковыми тегами, которые H3 действительно знает.

**Когда использовать:** быстрый брейншторм промптов, голосовые workflow'ы, превращение сырой идеи в production-ready промпт.

#### TS Angle Select
<img src="doc/screenshots/ts_angle_select.png" alt="TS Angle Select" width="450" />

Наводите камеру на объект и получаете промпт, который просит у модели ровно
такой ракурс. В ноде — небольшое 3D-превью: объект, орбита вокруг него и камера
на этой орбите, — а под ним три регулятора: **поворот**, **высота** и
**приближение**. Двигаете регулятор — превью показывает, куда уехала камера.

Превью — это только превью. Настраивать три величины одним движением по холсту
оказалось неудобно, поэтому у каждой величины свой ползунок. И ничто в виджете
не меняет размер от значения: нода не дёргается под курсором, пока вы тянете
ползунок.

**Формулировки принадлежат модели, а не ноде.** С встроенным пресетом
**Qwen Multi-Angle** на выходе — триггерная фраза, на которой обучалась LoRA
Multiple-Angles: `<sks> back view elevated shot close-up`, и ничего сверх этого.
Она выглядит обрывком, потому что обрывок и есть: LoRA выучила именно эти слова
рядом с нодой, которая их выдаёт, и «человеческий» английский ломает
обусловливание. Токен `<sks>` обязан остаться.

**Пресеты — обычный JSON**, по файлу на модель, в `nodes/text/angle_presets`.
Пресет говорит, какой шаблон заполнять и какая фраза отвечает каждому положению
камеры, поэтому поддержка новой модели — это новый файл, а не правка кода.
Пресет без одной из фраз не подключается и пишет строку в лог: половина словаря
тихо дала бы промпт с дырой на месте ракурса.

**Восемь поворотов, четыре высоты, три крупности.** Это те корзины, на которых
модель обучалась; промежуточных положений нет, потому что фразы для них попросту
не существует.

Three.js едет вместе с паком и подгружается **только когда эта нода появилась** —
он сознательно лежит вне веб-папки: ComfyUI импортирует оттуда каждый скрипт при
загрузке страницы, и платить за 3D-библиотеку тем, кто ноду не ставил, незачем.

**Когда пригодится:** пересъёмка того же объекта с другого ракурса в
Qwen-Image-Edit с LoRA Multiple-Angles или сборка кругового облёта по восьми
поворотам.

#### TS Prompt Builder
<img src="doc/screenshots/ts_prompt_builder.png" alt="TS Prompt Builder" width="450" />

Собирает промпт из **паков вайлдкарт**. Пак — это просто папка в
`nodes/prompts/` с файлами `.txt` и **семантической картой**, и вся суть в карте: без неё
случайная строка из двадцати списков даёт зимнюю улицу в купальнике, крупный план с позой
в полный рост и две несовместимые сцены разом.

Карта говорит, чем каждый вайлдкарт *является* — какая у него роль, где его место во
фразе, что он исключает и с чем сочетается, — и сборка идёт по ней, а не наугад. Восемь
шагов, взятых из раздела `algorithm` самих паков: профиль или ваши галочки, затем правило
о людях в кадре, взаимоисключения, несовместимые пары, необязательные спутники, проход по
аффинити, по строке из каждого дожившего вайлдкарта и, наконец, фраза в порядке ролей.

**Смешивать можно любые паки в любых сочетаниях.** Включите несколько — роли
переплетутся в одну фразу: сперва всё, что про внешность, потом одежда, потом действие,
потом место и камера, а не вывод одного пака, приклеенный к выводу другого. Вайлдкарты
именуются вместе с паком, поэтому два `face.txt` не сталкиваются, а там, где два пака
дают лицо, свет или позу, остаётся ровно один — жеребьёвкой с весом `mix.priority`.
Поэтому смесь из пяти паков звучит смесью, а не самым громким из них.

**Сцена не разъезжается.** Место живёт в тексте строк, а не в связях файлов, поэтому
одной семантикой его не удержать: замерено, что у 22% сборок в одной фразе сходились
бассейн, ливень и кухня. Теперь место выбирается первым, а каждая следующая строка
читается с оглядкой на него — спорящие о том, где мы и когда, отбрасываются. Тот же
замер после: 3%, и там уже метафоры, а не ошибки.

Положите папку руками и нажмите **Reload** — перезапуск ComfyUI не нужен. Нода покажет
вайлдкарты по ролям, притушит те, что при прогоне схлопнутся в один, даст закрепить
нужный булавкой и покажет живой предпросмотр тем же кодом, которым пойдёт прогон. Второй
выход рассказывает, что именно отбросила семантика и почему.

`seed = 0` — новый промпт каждый прогон; всё, что больше нуля, воспроизводимо.

**Когда пригодится:** пачки с управляемой вариативностью — каждый вайлдкарт категория,
каждая строка оттенок, а семантическая карта держит сочетание осмысленным.

<img src="doc/screenshots/ts_style_prompt_selector.png" alt="TS Style Prompt Selector" width="450" />

Визуальный выбор стиля: библиотека из **157 стилей** с превью, разложенных по 15 категориям — от наскальной живописи и византийской мозаики через авангард двадцатого века и фильм-нуар до пиксель-арта и вейпорвейва. Выбираете один — получаете `STRING`.

### 🎨 Ideogram (1 нода)

Инструменты дизайна для open-weight модели **Ideogram 4**.

#### TS Ideogram Designer
<img src="doc/screenshots/ts_ideogram_designer.png" alt="TS Ideogram Designer" width="450" />

Визуальный дизайнер JSON-промптов для Ideogram 4. Открывает полноэкранный редактор: перетаскивайте и меняйте размер блоков **текста** и **объектов** на холсте с правильным соотношением сторон (можно поверх референс-изображения) и проектируйте через **двухуровневые пресеты** — 10 шаблонов-лейаутов (*что* делаем) и 10 стилей (палитра + шрифты + вид) — в интерфейсе **RU/EN**. На выходе нода отдаёт валидный **структурированный JSON-капшен** Ideogram 4 как `STRING` плюс **`width` и `height`** (INT), рассчитанные из соотношения сторон и ползунка **0.5–2 МП** и всегда кратные 32 — заводятся прямо в ноду пустого латента / создания холста. Прямоугольники редактора превращаются в нормализованные bounding-box `[y_min, x_min, y_max, x_max]` (целые 0–1000, начало в левом-верхнем углу), а весь капшен собирается **точно по схеме Ideogram 4** — с выверенным порядком ключей в каждой секции (включая порядок `medium`/`art_style` для фото и не-фото). **Превью в ноде — точная WYSIWYG-копия редактора**: настоящие шрифты, начертания, цвета, обводки и сплошные плашки, с авто-подгонкой и переносом текста, — так что после *Сохранить* вы видите ровно то, что просите нарисовать Ideogram, а итоговый JSON-промпт показан с **цветовой подсветкой синтаксиса**. Каждый текстовый блок стилизуется единым списком **«Стиль текста»** (шрифт задаётся описанием, а не именем — у Ideogram нет селектора гарнитуры), начертанием **Тонкий / Обычный / Жирный** и регистром; **размер текста берётся из того, насколько крупно вы нарисовали блок**, без абстрактного выбора размера. Для читаемости добавляются **обводка** и/или **сплошная плашка** — каждая со своим цветом, и обе рисуются вживую на холсте и в превью. Цвет задаётся отдельными палитрами для **всего изображения, фона и освещения** плюс цветами отдельных элементов — всё это вплетается в капшен и показывается вживую на артборде. Отдельные лейауты и стили — или **целый дизайн** (весь артборд) — можно **сохранять, экспортировать и импортировать как JSON** (импорт копируется в папку ноды `user_presets/`). Инспектор разбит на понятные шаги — *что вы создаёте* → *как это должно выглядеть* → *что в сцене* — и **у каждого элемента есть дружелюбная всплывающая подсказка** (полностью локализованная RU/EN). Текст правится по двойному клику прямо на блоке, копирование — **Alt+перетаскивание** или **Ctrl+C / Ctrl+V**, а размер текста одинаков в режиме правки и в превью. Первоклассная поддержка **русского / кириллицы** (UPPERCASE + bold по умолчанию) и режим *visual-only*, который эмитит чистую плашку, чтобы добавить текст вручную для печати. Резиновое превью в ноде, работающее и в LiteGraph (Nodes 1.0), и в Vue (Nodes 2.0).

**Когда использовать:** дизайн обложек для YouTube, постеров и каверов, где нужен точный контроль расположения текста и элементов — и выбор стиля, которым рисует Ideogram.

### 📁 Файлы и модели (2 ноды)

Инструменты для управления модельными файлами, скачиваниями, EDL и инспекции весов.

#### TS Files Downloader
<img src="doc/screenshots/ts_downloader.png" alt="TS Files Downloader" width="450" />

Multi-file загрузчик, который принимает список строк формата `URL <пробел> target_path` и скачивает их последовательно. Автоматически подменяет HuggingFace-зеркала с проверкой доступности по всему списку зеркал, поддерживает `models/<subdir>` алиасы, докачивает прерванные файлы, защищает auto-unzip от zip-slip, показывает прогресс (включая верификацию SHA256). Удобно отдавать workflow с готовым списком моделей.

**Взять модели из workflow.** Кнопка на ноде заполняет этот список сама: обходит открытый граф — **включая содержимое сабграфов**, где обычно и лежат загрузчики шаблонов, — и собирает все нужные модели. Читает метаданные `{name, url, directory}`, которые ComfyUI проставляет каждому загрузчику, сверяет их с Markdown-заметкой workflow'а и, если ссылки нет нигде, берёт хотя бы имя файла из самого загрузчика. Сначала показывается разбор: **Дополнить** дописывает только недостающее и не трогает строки, набранные вручную, **Заменить список** собирает заново.

Уже скачанные модели тоже попадают в список, и это намеренно: список едет вместе с workflow, и тому, кому вы его отдадите, эти строки нужны.

**Какие загрузчики она понимает — спрашивается у вашего ComfyUI, а не записано здесь.** Список в каждом загрузчике заполнен из какой-то папки `models/`, то есть сами варианты и говорят, откуда они взялись: нода читает это с работающего сервера и сопоставляет каждый виджет каждой установленной ноды со своей папкой. Поэтому модель в `Load Latent Upscale Model` или в ноде из пакета, поставленного вчера, находится так же, как чекпойнт. Записанная таблица так не может: на машине автора 49 установленных типов нод имеют виджет с моделью, которого в такой таблице нет, и две из них — родные ноды ComfyUI. Если у одной ноды два виджета из разных папок, они не путаются: текстовый энкодер и чекпойнт на одном загрузчике поедут каждый к себе.

Папка предлагается та, в которой у вас **уже лежат** модели этой категории. ComfyUI читает по две директории на категорию — `clip` и `text_encoders`, `unet` и `diffusion_models` — и обе настоящие; если ваши энкодеры сложены в `clip`, туда и будет предложено качать, а не в пустую соседнюю. Строку, которую вы написали в списке сами, это не переписывает.

**Остановка прогона обрывает всё.** Кнопка остановки ComfyUI прекращает не только текущий файл, но и все оставшиеся в списке. Недокачанный файл остаётся как `.part` — следующий запуск продолжит с того же места, а не начнёт сначала. Ход показывается одной полосой на весь список: от первой модели до последней.

**Остальной workflow ждёт.** Нода приносит модели, без которых графу нечего загружать, поэтому она держит прогон до последнего файла — а не отпускает его вперёд, пока байты ещё летят.

**Когда использовать:** распространение workflow'а, которому нужны N конкретных моделей — открыли, нажали кнопку, нода заполнена.

### 🛠️ Утилиты (6 нод)

Маленькие помощники, чтобы граф меньше захламлялся.

#### TS Group Bypasser
<img src="doc/screenshots/ts_group_bypasser.png" alt="TS Group Bypasser" width="450" />

Пульт по группам открытого workflow. В теле ноды — только названия групп и чекбоксы, ничего лишнего: снятие галочки переводит **все ноды внутри группы в байпас**. Двойной клик по строке показывает группу на канвасе. Нода сама подстраивает высоту под число групп — две группы дают ноду в две строки, без пустоты внизу.

Состояние не хранится в ноде, а читается из самого графа — поэтому нода, замьюченная руками, или нода, попавшая сразу в две группы, честно показываются как «включена частично», а не выдаются за что-то определённое.

**Настройки — в панели свойств ноды** (правый клик → Properties Panel): фильтр по названию (подстрока, а `/…/` — регулярное выражение), фильтр по цвету (через запятую, понимает и названия цветов LiteGraph, и hex, и `none` для групп без цвета), порядок списка (по расположению, названию или цвету) и правило «максимум одна» / «всегда ровно одна» включённая группа — удобно гонять A/B-ветки, когда включение одной должно выключать остальные. **Массовые действия** (включить/выключить/инвертировать показанные) — в меню ноды по правому клику.

Выключенное состояние сохраняется вместе с workflow само собой: оно живёт в режимах нод, а не в этой ноде.

**Когда использовать:** тяжёлый workflow с несколькими ветками, из которых за прогон нужна одна.

**На самом холсте у каждой группы есть значок** — маленький квадрат в правом верхнем углу группы (та самая механика, которую приучил любить rgthree-comfy). Одно нажатие отправляет всю группу в байпас, второе возвращает; у пустых групп значка нет — там нечего выключать. Работает и с классическими нодами, и в Nodes 2.0, и ноды на графе для него не нужно вовсе — выключается в **Settings → TS Timesaver → Canvas → «Bypass button on group headers»**.

#### Навести порядок — одна команда, без ноды

Правый клик по холсту (или по любой ноде) → **Навести порядок** → **Разложить аккуратно**. Что выделено — а если ничего не выделено, то весь граф — встаёт на место: каждая нода ужимается до размера под собственное содержимое, и всё раскладывается по колонкам вдоль проводов, слева направо, по сетке. Обе команды есть и в палитре ComfyUI, так что на них можно повесить горячие клавиши.

Колонка ноды — это её расстояние от начала потока: загрузчик всегда левее семплера, который его читает, а нода с одним входом встаёт на одну линию с тем, что её кормит. Порядок внутри колонки подбирается так, чтобы провода поменьше пересекались, и отсчитывается от того порядка, который уже был, — команда приводит в порядок вашу расстановку, а не заменяет её чужой. Схема остаётся там же, где стояла: левый верхний угол не двигается, и искать свой граф после команды не придётся.

**Группы раскладываются изнутри наружу.** Ноды группы расставляются внутри неё, рамка подгоняется по ним, а сама группа участвует во внешней раскладке одним блоком — оформленный workflow остаётся оформленным. **Закреплённые ноды не двигаются никогда**: закрепление — это и есть способ сказать «эта пусть стоит», и команда его уважает.

**Провода, которые режут ноды, можно развести.** Второй пункт, **«Разложить и развести провода»**, раскладывает схему, а затем каждой связи, чья прямая проходит сквозь чужую ноду, ставит точки: провод уходит в коридор между колонками, идёт по свободной полосе и возвращается — одна полоса на весь обход, а всё лишнее выбрасывается обратно. Связи, где точки уже есть, остаются хозяйскими; провода против потока не трогаются. Запустите второй раз — ничего не изменится.

Каждый провод разводится, зная об уже разведённых, и полоса выбирается по цене: **лечь ПОВЕРХ чужого провода почти запрещено** — две линии, читающиеся как одна, и делают схему нечитаемой, по ней даже не понять, сколько там проводов. Пересечь заметно дешевле, длинный крюк — дешевле всего. Это осознанный размен: пересечение видно и понятно, наложение — нет. Провода из одного гнезда исключением не считаются. Повод развести — не только порезанная нода, но и провод, легший на другой; а потом вся схема разводится ещё раз, где каждый провод снимается и прокладывается заново, уже зная, куда встали остальные.

Замерено на настоящем workflow из 32 нод: одна раскладка оставляла 68 мест, где провод режет ноду, и 94 пересечения; разводка доводит это до **0 порезов, 0 наложений и 88 пересечений**. Та же схема, разложенная автором вручную: 40 порезов, 84 пересечения. Оставшиеся пересечения идут от порядка нод в колонках, а не от проводов — совместная раскладка, где порядок выбирается с оглядкой на будущие провода, ещё не сделана.

**Или уложить плитками.** Третий пункт, **«Уложить плитками»**, — это другой запрос: не «покажи поток», а «убери пустоту». Каждая нода в колонке получает одинаковую ширину — тогда это читается как плитки, а не как лесенка, — а сама колонка вмещает **несколько подряд идущих слоёв графа**, а не один: колонка на слой превращает схему в ленту, которая не влезает ни в один монитор. Высота колонок подбирается так, чтобы вся картина была близка к **16:9** и чтобы ни одна колонка не оказалась заметно пустее соседних. Однотипные ноды стоят рядом, а внутри колонки порядок — по тому, как скоро результат ноды понадобится: та, с которой поток начинается, оказывается верхней левой, а последняя — нижней правой. (Одних барицентров для этого мало: загрузчик, чей выход нужен только в самом конце, о соседней колонке мнения не имеет и всплывал наверх.) **Провода в этом режиме не трогаются вовсе**: ни выравнивания, ни разводки.

Замерено на настоящем workflow из 32 нод: 17 колонок и 5540×1308 превращаются в **5 колонок и 1760×1128** — площадь, занятая нодами, растёт с 17% до 76%, а формат с 4,2:1 до 1,6:1, то есть схема помещается на экран.

**Точки на связях тоже выпрямляются.** Круглые точки перегиба, которые ComfyUI разрешает бросать прямо на провод, распределяются по прямой между гнездом-источником и гнездом-приёмником: провод, шедший ломаной через случайно брошенную точку, становится прямым. Точка, которую делят несколько связей, встаёт в среднее между ними. Провод, чья прямая упёрлась бы в чужую ноду, остаётся в обходе: обход, поставленный не зря, не распрямляется. Ничего не создаётся и не удаляется — граф возвращается тот же, что был. Второй пункт подменю, **«Выровнять только точки на связях»**, делает это, не трогая ноды: на случай, когда схема уже стоит как надо.

Работает в обоих режимах нод. Это не само собой: на одном и том же графе Nodes 2.0 даёт ноде другой размер, чем Nodes 1.0 (`SaveImage` — 58 пикселей против 70), а некоторые ноды вообще отказывается ужимать, хотя `node.size` утверждает обратное. Поэтому команда спрашивает у холста, что он на самом деле нарисовал, и только потом решает, где чему стоять.

#### TS LoRA Loader
<img src="doc/screenshots/ts_lora_loader.png" alt="TS LoRA Loader" width="450" />

Стопка модельных LoRA в одной ноде. Плюс открывает поиск по тем LoRA, что реально есть в этой сборке; выбранная становится строкой со своим полем силы, а плюс остаётся на месте — для следующей. Строки переставляются перетаскиванием за ручку: порядок важен, LoRA накладываются одна за другой.

**У каждой строки есть выключатель.** Выключенная LoRA остаётся в списке вместе со своей силой и своим местом — прогон просто идёт без неё, а один клик возвращает её обратно. Ровно столько и должно стоить сравнение «с ней / без неё» — ничего. Клик по названию делает то же самое, кому так быстрее.

**Сила может быть отрицательной** (до −10): так гасят LoRA, зашитую в чекпоинт, или разворачивают её эффект. Протаскивание влево-вправо по полю силы крутит значение.

**Только что положенная в `models/loras` LoRA появляется по `R`** — той же клавише, которой обновляются родные загрузчики. Поиск здесь нарисован своими руками, а не стандартным выпадающим списком, и до сих пор обновление проходило мимо него: новый файл не показывался до перезагрузки страницы.

Сама нода ничего не грузит — она разворачивается в цепочку **родных `LoraLoaderModelOnly`**. Отсюда два следствия, ради которых всё и сделано: результат один в один совпадает с цепочкой, собранной руками, а кэш ComfyUI считает каждое звено отдельно — правка силы последней LoRA не заставляет пересчитывать предыдущие. LoRA, которой нет на этой машине, стоит своей строки, а не всего прогона, — это важно для workflow, пришедших от другого человека.

Только модель, без CLIP: у современных семейств текстовый энкодер живёт отдельно, да и половина LoRA в обиходе — чисто модельные.

**Когда пригодится:** LoRA больше одной или заранее понятно, что порядок придётся подбирать.

## 🔰 Подсказки для новичков

### Только начинаете?

1. **Ищите по категориям** в правом клике: каждая нода живёт под `TS/<Категория>`.
2. **Доверяйте дефолтам**: у каждого входа есть разумное значение по умолчанию. Меняйте по одному параметру, чтобы понять, что он делает.
3. **Используйте [TS Resolution Selector](#image)** как источник latent-изображения — он всегда возвращает sampler-friendly размер.
4. **Бросьте [TS Animation Preview](#video) в конец** любого видео-графа, чтобы делать QA без перезапуска.
5. **Нужен быстрый голосовой промпт?** [TS Super Prompt](#llm) — кликнули по микрофону, описали идею, получили готовый промпт.

### VRAM не хватает, что использовать?

| Задача | Решение |
|---|---|
| Апскейл 4K-картинки | TS Image Tile Splitter → апскейлер → TS Image Tile Merger |
| Обработать только лицо/объект | TS Crop To Mask → апскейл/restore → TS Restore From Crop |
| FP8 модель | TS Model Converter Advanced |

### Где модели лежат?

| Нода | Папка по умолчанию |
|---|---|
| TS Lama Cleanup | `models/lama/` |
| TS Whisper | `models/whisper/` |
| TS Silero TTS | `models/silerotts/` |
| TS Silero Stress | `models/silero-stress/` |
| TS Qwen 3 VL | `models/LLM/` |
| TS Super Prompt | `models/LLM/` |
| TS Music Stems | `models/roformer/`; кэш demucs для старого движка |

Можно переопределить через `extra_model_paths.yaml` — Timesaver уважает path-resolution ComfyUI.

## 🛟 Если что-то сломалось

<details>
<summary><b>Раньше пак печатал при старте большую таблицу — куда она делась?</b></summary>

При чистой загрузке пак говорит одну строку и больше ничего:

```
[TS Timesaver] All 73 nodes loaded successfully.
```

Консоль ComfyUI общая для всех установленных паков, и два экрана таблиц на
каждом запуске хоронили в себе настоящие ошибки — в том числе наши. Всё, что
пошло не так, по-прежнему печатается, и только оно.

Полный отчёт (таблица модулей, таблица внешних импортов, итоги) возвращается
одной переменной:

```bash
TS_VERBOSE_STARTUP=1
```

Задайте её до запуска ComfyUI (в Windows: `set TS_VERBOSE_STARTUP=1` в том же
окне консоли или строкой в вашем `.bat`). Нужна, когда ноды не хватает и надо
увидеть, какой именно модуль не загрузился и почему.

</details>

<details>
<summary><b>«ffmpeg не найден» или ноды звука и видео не декодируют</b></summary>

Ставить ffmpeg вручную не требуется: `imageio-ffmpeg` — обязательная зависимость,
и она привозит статический бинарник под каждую платформу, где работает пак.
Загрузчик аудио, TS Whisper, голосовой ввод Super Prompt и TS Animation Preview
сначала спрашивают именно этот бинарник и только потом смотрят в PATH.

Значит, само сообщение говорит о том, что зависимости нет или её бинарник
вычистили. Лечится тем Python, из которого запускается ComfyUI:

```bash
python -m pip install --upgrade imageio-ffmpeg
```
</details>

<details>
<summary><b>«A required media input has no file selected» после перезагрузки</b></summary>

Это ошибка самого ComfyUI, и пак её чинит — единственное место, где он вообще
трогает ядро.

Когда вы вставляете картинку в ноду через Ctrl+V или бросаете её мышью, ComfyUI
кладёт файл в `input/pasted/`, а в виджете остаётся значение `pasted/имя.png`. До
перезагрузки всё работает. После перезагрузки список доступных файлов приходит с
сервера, а штатный `Load Image` перечисляет только то, что лежит прямо в корне
`input` — вложенных папок он не видит. Проверка интерфейса не находит значение в
списке и объявляет файл отсутствующим, хотя тот всё это время на диске.

Timesaver расширяет список у штатных `Load Image` и `Load Image (as Mask)`: они
начинают видеть картинки во всех подпапках `input`. Ноды не подменяются, файлы
никуда не переносятся, уже сохранённые workflow начинают открываться сами.
Папки, начинающиеся с точки (служебные кэши паков), в список не попадают.

Выключить: переменная окружения `TS_DISABLE_PASTED_MEDIA_FIX=1` перед запуском
ComfyUI.
</details>

<details>
<summary><b>"Module not found" при старте</b></summary>

Смотрите startup-лог — Timesaver печатает load report. Отсутствующие опциональные зависимости появляются под **Optional missing imports** с указанием, какому файлу они нужны. Установите:

```bash
python -m pip install <missing_module>
```

Используйте тот же Python, что запускает ComfyUI. На Windows portable: `python_embeded\python.exe -m pip install <module>`.
</details>

<details>
<summary><b>Нода не появилась в меню</b></summary>

В startup-логе ищите **Module load issues**. Самая частая причина — отсутствие опциональной зависимости (например `py360convert` нужен для cube/equirect нод). Установите её и перезапустите.
</details>

<details>
<summary><b>Workflow ломается после обновления</b></summary>

Timesaver специально замораживает id нод и входы между версиями. Если что-то сломалось после `git pull`:
1. Проверьте `doc/migration.md` на breaking changes.
2. Убедитесь, что `pip install -r requirements.txt` запускался.
3. Полностью перезапустите ComfyUI — не просто обновите вкладку браузера.
</details>

<details>
<summary><b>OOM (out of memory)</b></summary>

- Уменьшите `process_resolution` (BiRefNet) или `compute_max_side` (Color Match).
- Для апскейла используйте `TS Image Tile Splitter` + тайловую обработку.
- Для LLM понизьте точность до int8 или int4 (`TS Qwen 3 VL V3` → `precision=int8`).
- `unload_after_generation=True` освобождает VRAM модели после каждого запуска.
</details>

### Тихая консоль на Windows

ComfyUI на Windows засыпает консоль вот этим — пачками по три-шесть штук в секунду, каждый раз, когда закрывается websocket: после задачи, при каждой перезагрузке страницы:

```
[ERROR] Exception in callback _ProactorBasePipeTransport._call_connection_lost(None)
ConnectionResetError: [WinError 10054] An existing connection was forcibly closed by the remote host
```

Замерено на живой сборке: 402 строки из 1865 — 22% всего, что сказала консоль. Это баг CPython, а не ComfyUI: `asyncio/proactor_events.py` зовёт `self._sock.shutdown(...)` в `finally`, ничем не прикрыв случай, когда клиент уже отвалился. [python/cpython#83191](https://github.com/python/cpython/issues/83191) открыт с 2020 года, и обновление Python не помогает — в ветке `main` код так и стоит без защиты.

**И это не только шум.** Исключение вылетает *до* `self._sock.close()`, поэтому сокет остаётся открытым до сборщика мусора.

Пак оборачивает этот один метод и доводит до конца уборку, которую прервало исключение, — для шести кодов закрытия сокета и ни для чего больше. Незнакомый код пробрасывается нарочно: через тот же метод проходит `connection_lost` вашего протокола, и глушить его значило бы прятать настоящие поломки. Замерено на восьми перезагрузках страницы и двух задачах: **9 трассировок до, 0 после**. Выключается через `TS_DISABLE_PROACTOR_GUARD=1`.

Чего пак **не** делает — не переключает цикл событий на `WindowsSelectorEventLoopPolicy`, хотя этот совет попадается в большинстве ответов в интернете: такой цикл на Windows не умеет подпроцессы и упирается в 512 сокетов. Тишина не стоит настоящих поломок.
